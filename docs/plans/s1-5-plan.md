## 0. 함정 원장 등재 1건 (이 커밋에 포함 — PROGRESS.md ⑫)

**커밋 메시지 수치는 증거가 아니다** — ccc3736 제목 "F 그룹 최초 도입 — … 65케이스"의 65는 **F43+K19+B3 케이스 합**인데 제목 문맥은 F 그룹이라, 제목 스코프(F 그룹)와 수치 스코프(신규 전체)가 섞여 병합 전 대사 1라운드가 들었다. 이후 커밋 제목의 수치는 제목이 말하는 스코프와 일치시키고, 스코프가 섞이면 수치를 본문으로 내려 스코프별로 쪼개 적는다. 검증의 근거는 커밋 메시지가 아니라 실행 로그다.

**판정 조건 ⑧ 대사 결과(마커 실측 확정)**: 왕복 e2e 20케이스(모듈 마커 group_f) + 파서 단위 12함수 중 1개의 parametrize 12값 확장 = 23케이스 → **F43** / 레지스트리 아키텍처 6 + 통합 제약 13 → **K19** / CSV 3종 e2e → **B3** / 합 **65**. 커밋 본문의 J 표기 3건·K 표기 4건(왕복 파일)은 F 케이스에 겹친 **복수 마커라 수량 기여 0**(K19는 별도 파일분만). 따라서 PR #11 대사 보고(F43+K19+B3=65)가 옳았고, 이 원장 초판의 "(F+K+B+J 합)" 문구가 틀린 쪽이었다 — 본 판(계획서·PROGRESS ⑫ 동시)에서 정정했고 상충 수치 잔존 0이다.

같은 규율의 이번 세션 적용 2건(기억·기록 수치의 실측 정정):
- PROGRESS의 "SKU CSV 22칸"은 낡은 수치다 — PR-2에서 MSDS링크 칸이 documents로 승격되며 빠져 **현재 21칸**(`catalog/router.py::SKU_CSV_HEADER` 실측). 부기로만 남기면 같은 파일 안에서 수치가 상충하므로 **이 커밋에서 PROGRESS 본문 2곳(조건 8·다음 세션 안건)을 21칸으로 정정**한다(S1-1 관통 기록의 22칸은 당시 실측이라 유지). PR #11 병합·S1-3 종결 상태도 같은 이유(기록과 실측의 일치)로 함께 반영한다.
- "MIG-0001 한국유리(주)"는 리포에 실재하지 않는다(전 파일·전 이력 grep 0건). 리포의 MIG-0001은 백필 테스트 픽스처 "한국 콜마"(`test_migrations.py:189`)다. 한국유리(주)는 영준이 실DB에서 승격 마이그레이션(e45b79db6198)이 만든 실데이터 행으로 추정 — 세션 시작 시 실DB `SELECT partner_code, name_ko FROM partners WHERE partner_code LIKE 'MIG-%'` 실측으로 고정하고 시작한다.

### 작업 2 — 실데이터 반입 (범위·순서·검증 — 요구 c)

반입 순서(참조 의존 순): ① 거래처(대장의 거래처 + 제조사·공급사 문자열 승격분 — 왕복 신규 생성) + **MIG- 전량 검수·개명(작업 3)을 이 단계에서 완료** — 이후 단계의 제조사코드·기본공급사코드가 정식 코드를 참조하게 한다 → ② 브랜드·제품 → ③ SKU(제조사코드 연결)·자재(기본공급사코드 연결) → ④ 성분 마스터 → ⑤ 전성분·BOM·라벨(성분·제품·자재 의존) → ⑥ 문서(MSDS 등 실물 파일) → ⑦ 재고 수량 대장 검산.

반입 수단(실측): 왕복 어댑터 보유 = 거래처·자재·SKU(작업 1 산출물) — CSV 왕복로 반입. 어댑터 부재 = 브랜드·제품·성분·전성분·BOM·라벨·문서 — **(판정 ④ 확정) 수단 기본=화면.** 세션 시작 실측에서 반입 예정 50건 초과 엔터티는 어댑터 신설 사전 승인(조건: 레지스트리 패턴·등록 API 검증 재사용·왕복 실증 동일 적용·초과 실측치 평문 보고). 단 **BOM은 자동 승인 제외**(원가 마스킹 계보 인접 — 필요 시 실측치 들고 별도 판정). **브랜드·제품은 이월 불가** — SINGLE SKU는 제품 없이 DB CHECK가 막으므로(§4.1 [M1] 보강 ①) SKU 반입의 선행 조건이다. 이월 가능한 것은 전성분·BOM·라벨·문서 등 하류뿐. 건수는 대장 실물을 봐야 알므로 웹 세션에서 대장 실측과 함께 확정한다.

재고 수량 대장: 원장은 P4다(§8.1 OPENING·LEG- 로트는 그때 소비). WBS 문면대로 **스테이징 검산까지** — 초안: 대장 파일을 문서보관소에 보존 등록하고, 합계·건수 검산 기록을 검산 리포트에 남긴다(원장 반입 시도 금지). 그릇 판정은 안건 4.

검증 방법(임포트 코어 왕복 실증 활용 — 요구 c 명시분):
1. 대상별 반입 표준 절차: 표준 양식 다운로드 → 대장 값 이식 → 업로드 스테이징 → 오류 행 리포트(행번호+사유) 0건까지 수정 라운드 → diff 검토 → 확정 1클릭 → **확정 직후 내보내기→재업로드 diff 0 확인**(§20 J "동일 임포트 재실행 변화 0"의 실데이터 적용 — 왕복 전단사(ADR-0027)의 실증) → **확인 후 검증용 스테이징 즉시 파기**(diff 0이어도 스테이징은 PENDING으로 생성된다 — `imports/service.py` 실측. 파기하지 않으면 다음 재검증 업로드가 `DUPLICATE_PENDING` 422에 걸리고 대기물이 쌓인다. 파기 엔드포인트는 기실재 — PR-3 관통 기록의 "대기 스테이징 파기 204→404").
2. 건수 대사: 대장 행수 = 시스템 활성 행수 + 제외 행수(사유 목록화 — DoD ②).
3. 유형 정합 검산 쿼리: 기본공급사 비SUPPLIER 0건 · 제조사 비OEM 0건(안건 3의 방어와 연동).
4. 원가 마스킹 실기동 재확인: 실데이터 반입으로 실원가가 처음 DB에 들어온다 — VIEWER 시야 BOM 원가 필드 부재·로그 원가 0건·BOM CSV 원가 흔적 0을 실데이터 상태에서 1회 재관통(§20 G).
5. 종료 실측: scheduled_jobs 0행 · events 행수(부채 #11 단조 증가 관찰) · **PENDING 스테이징 잔존 0건** · MIG- 파트너 **전량 처분 판정 완료**(개명·병합 재판정 대기·유지 각 N건 — 사유 첨부. 미판정 잔존 0건이 기준이며, '유지'·재판정 대기 채택 행은 사유와 함께 잔존을 허용한다).
6. 표본 화면 대조: 대상별 표본 N건을 화면에서 대장과 직접 대조(비개발자 검수 경로 — 안건 2 처리안 A가 이 수단의 전제. B 채택 시 표본 대조는 CSV로 대체).

산출물(WBS 명시): 검산 리포트 + 병행 운영 체크리스트. **병행 운영 SoR(판정 ④ 확정)**: S1.5 기간 기존 엑셀 유지. 마스터 SoR 전환은 종결 검산 통과 후 **영준이 확정 선언으로만** 한다. 재고·거래 전표는 P4/S2 이후까지 엑셀.

**유형 정합 검산 쿼리(판정 ③ — SQL 전문. 실행 시점 2회 고정: 거래처 단계(①) 완료 시·세션 종료 검산. 각 실행 결과 0건을 평문 보고):**

```sql
-- (1) 기본공급사가 활성 SUPPLIER 유형이 아닌 자재 — 0건이어야 한다
SELECT m.material_code, p.partner_code, p.name_ko
FROM materials m
JOIN partners p ON p.id = m.default_supplier_partner_id
WHERE m.deleted_at IS NULL
  AND (p.deleted_at IS NOT NULL
       OR NOT EXISTS (SELECT 1 FROM partner_type_links l
                      WHERE l.partner_id = p.id AND l.type_code = 'SUPPLIER'
                        AND l.deleted_at IS NULL));

-- (2) 제조사가 활성 OEM 유형이 아닌 SKU — 0건이어야 한다
SELECT s.sku_code, p.partner_code, p.name_ko
FROM skus s
JOIN partners p ON p.id = s.manufacturer_partner_id
WHERE s.deleted_at IS NULL
  AND (p.deleted_at IS NOT NULL
       OR NOT EXISTS (SELECT 1 FROM partner_type_links l
                      WHERE l.partner_id = p.id AND l.type_code = 'OEM'
                        AND l.deleted_at IS NULL));
```

**S1.5 유형 해제 수칙(판정 ③)**: 반입 기간 중 거래처 유형 해제는 원칙 금지. 불가피하면 해제 전 위 참조 쿼리를 그 거래처 한정으로 실행하고 결과를 평문 보고한 뒤에만 진행한다.

**백업 절차(판정 ⑨ 신설 — 계획서 초판에 없어 추가):**
1. S1.5 실데이터 작업 재개(스택 기동) 직후 최초 1회: `pg_dump -Fc` 전체 백업 → 스크래치 DB(`kbos_s15_restore_check`)에 복원 실증(주요 테이블 행수 대조) → 스크래치 DB 파기. 실증 결과 평문 보고.
2. 이후 각 엔터티 **확정 직전** 단계별 백업 1회.
3. 파일명 규약: `s15_<NN>_<대상>_<YYYYMMDD-HHMM>.dump`(KST) — NN은 2자리 순번(00=작업 재개 기준선), 대상은 확정 직전 엔터티 코드(partners·brands-products·skus·materials·ingredients·formulas·labels·documents). 저장 위치는 리포 밖 `C:\Users\PC\orca\kbeauty-backups\s1-5\`(git 미추적).

### 작업 3 — 제조사·공급사 승격 실검수 (요구 b — MIG-0001 검수 양식 동일 적용)

검수 대상: 영준이 실DB의 MIG- 자동 생성 파트너 전량(승격 마이그레이션 e45b79db6198 백필분) + S1.5 반입에서 새로 승격되는 거래처 전량.

검수 양식 — **7항 확정판**(판정 ⑤: 원본 양식 전문 인계 부재로 아래 7항이 확정본이다). 항목당 —
1. MIG 코드(또는 신규 거래처코드)
2. 정규화 거래처명(트림·연속 공백 1칸 — 백필과 같은 식)

### 작업 5 — 거래처 유형 해제 대칭 갭 × 대량 승격 간섭 평가 (요구 e — **판정 ③ 처리안 B 채택 확정**)

확정(판정 ③): 운영 수칙+검산으로 우회하고 **구현은 S3-1 이월 확정**. 수칙·SQL 전문·실행 시점 2회는 작업 2에 명문화했다. 아래 평가·처리안 대비는 상정 당시 원문 보존.

갭 원문(PROGRESS 관찰 항목): 왕복 임포트가 유형 해제 경로를 처음 열었는데, SUPPLIER 해제 시 그 거래처를 기본공급사로 참조 중인 자재를 보지 않는다. 자재 확정 쪽은 verify_references로 닫았고, 반대 방향은 §7.7 게이트 사상과 얽혀 등재만(재판정 트리거: S3-1 또는 거래처 수정 화면 신설).

S1.5 간섭 평가: 반입은 신규 생성(빈 ID) 위주라 유형 해제는 기존 행 재수정 라운드에서만 발생한다. 위험 창은 둘 — ① 거래처 재수정에서 SUPPLIER/OEM을 해제하면 이미 확정된 자재·SKU의 참조가 비유형 거래처를 가리키는 상태가 조용히 생긴다(확정 시점 재검증은 그 후를 못 본다). ② SKU 어댑터가 제조사코드를 도입하면 같은 갭이 OEM 축으로 복제된다. 즉 **간섭은 실재하되, 창이 좁고 검산으로 잡을 수 있다.**

처리안 A — 이번 구현(해제 확정 시 참조 존재하면 409): 갭은 닫히나, 등재 문면의 재판정 트리거(S3-1/수정 화면)가 미도달이고 "차단 지점은 등록이 아니라 게이트" 사상(§7.7)과의 정합 판정 없이 임의 구현하지 않기로 한 항목이다.

처리안 B — **운영 수칙+검산(추천)**: S1.5 한정 수칙 — 반입 순서 고정(거래처 확정 후 자재·SKU), 반입 기간 중 기존 거래처의 유형 축소 변경 금지, 반입 완료 검산에 유형 정합 쿼리(작업 2 검증 3) 포함으로 창을 닫는다. 구현 0, 등재·트리거 원문 유지. 근거: S1.5는 데이터 세션이고, 상시 방어의 설계 판정은 트리거 세션(S3-1) 몫이다.

### 작업 6 — 골든케이스 대조 + 부채 대사 (요구 f)

골든케이스 대조(실측): WBS의 GC↔세션 매핑표에 S1.5 행이 없다 — 배정 GC 0건. SKU 왕복은 GC 신설 대상이 아니라 F 그룹이 이미 고정한 왕복 거동 계약의 대상 확장(재실증)이다. 반면 S1.5 DoD의 검산 거동(이월 합계=대장 합계·불일치 사유 목록화)은 GC에 대응 케이스가 없다 — S1-2 선례(v1.1: 구현 세션에 대응 케이스 0건이라 GC 기준 검수 불성립 → 케이스 추가)와 같은 상황이므로 **GC v1.2 후보 1건(가칭 GC-A5 "기초 이월 검산 — 이월 합계=대장 합계, 불일치 건 사유 목록화, 검산 없이 확정 금지")** 추가 여부를 안건 6으로 상정한다. **판정 ⑥ — 신설 승인**: 기대값은 **반입 전 원천 파일 엔터티별 행수 실측으로 선고정**하고 반입 후 소급 조정을 금지한다. 검산 4항 = 행수 대사 · 왕복 diff 0 · 정합 쿼리 0건 · MIG 전량 처분 완료. GC v1.2 문서 갱신은 PR-3. PR 검수는 GC 문서의 검수 프롬프트를 그대로 사용.
