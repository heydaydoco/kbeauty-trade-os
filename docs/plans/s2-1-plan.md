## 2. 신규 테이블 전량 목록 (요구 a — **전건 사전 승인 대상**)

컬럼 초안까지가 승인 요청 범위다. §5.1이 컬럼 명세를 얇게 두므로(문면: 적용단위·유형·선행요건·유효기간·갱신주기·리드타임·비용·근거링크·확인일) 추측 구현 금지 원칙상 그릇을 판정으로 고정하고 시작한다.

**2-1. `markets`** — 근거: §5.1(요건의 시장 축), §3 전체 테이블 맵 [M2], §2 ADR-03, ADR-0023(markets 전까지 코드 문자열 — 이번에 그 "전까지"가 끝난다).
- 컬럼 초안: `code` String(2) NOT NULL·형식 CHECK `^[A-Z]{2}$`·**전역 UNIQUE(판정 조건 3 반영 — 초안의 unique_active를 정정: 코드 참조 FK의 대상이라 부분 유니크 불가, §0-1 ②)** — 기존 3테이블 실데이터(US·EU·CA 등)와 동일 형식. EU처럼 ISO 국가가 아닌 시장 코드도 이 형식이 이미 수용한다. / `name_ko` NOT NULL / `name_en`·`note` nullable.
- 믹스인 전부(Pk·Timestamp·SoftDelete·Version·Actor) — 편집 대상 마스터다(roles·document_types 같은 순수 시드 테이블이 아니다).
- 비포함 결정 2건: §5.5의 Tier(T1/T2/T3)는 "템플릿 준비 우선순위"라는 문서 개념이지 시장 속성이 아니라 컬럼으로 담지 않는다. 중국 CBEC는 §5.5 문면이 "CBEC **별도 템플릿**"이라 시장 축(CN)이 아니라 템플릿 축에서 갈린다 — 별도 시장 행을 만들지 않는다.
- 시장 헤더 자체는 ADR-03 근거 필수 대상이 아니다(요건·세율·기한 데이터가 대상 — 근거는 requirement_templates가 진다).

**2-2. `requirement_templates`** — 근거: §5.1(3층 모델의 1층), §2 ADR-03(근거 필수), ADR-11(요건=데이터, 상태는 코드 고정).
- 컬럼 초안: `market_id` FK NOT NULL / `name` NOT NULL·unique_active(market_id, name) / `applies_to` 5값 CHECK(PRODUCT[처방]/SKU/FACILITY/COMPANY/INGREDIENT — WBS DoD의 5종 그대로) / `requirement_type` 코드 문자열(NOT NULL·형식 CHECK — 별도 유형 테이블 승격은 필터·집계 소비가 생길 때 재판정, ADR-11 승격 규율) / `validity_months`·`renewal_cycle_months`·`renewal_lead_days` nullable·positive(요건마다 없을 수 있다 — MoCRA 시설등록 격년 같은 주기형과 1회성 공존) / `estimated_cost_amount` BigInteger nullable + `estimated_cost_currency` CHAR(3) nullable + **쌍 CHECK**(둘 다 있거나 둘 다 없거나 — credit_limit 선례 `credit_limit_amount`/`credit_limit_currency` 꼴·ADR-0003 ④ "BIGINT 정수 최소단위+CHAR(3) 통화" 그대로. 접미사 `_amount`라 금액 감지기 `is_money_column_name`에 **자동 편입**된다 — 검증 실측: `_minor` 같은 비규약 접미사는 감지기가 못 본다) / `source_url`·`last_verified_on` **nullable** / `status` 3값 CHECK(DRAFT/CONFIRMED/RETIRED — 라벨 선례 ADR-0025: 값 고정까지, 전이 명문은 §5.2 인증뿐) / `note`.
- **확정 게이트(핵심 계약)**: 근거 2필드가 nullable인 이유는 초안 상태가 실재해야 하기 때문이다 — §5.5가 "근거 링크 없는 항목 **확정 차단**"을 명시한다(근거 없는 초안의 존재 전제. sku_hs_codes·ingredient_rules의 NOT NULL과 다른 이유: 그 둘은 확정 개념 없는 즉시 등록 데이터). 강제는 이중이다: ① DB CHECK `status <> 'CONFIRMED' OR (source_url IS NOT NULL AND last_verified_on IS NOT NULL)` — 확정 상태의 행은 어떤 경로로도 근거를 비울 수 없다. ② 서비스 확정 액션 — 사람 1클릭 + idempotency key(§17.4·§12.2 보강 ⑤ 선례), 근거 없으면 422 거부.
- 확정 후 수정: 템플릿은 마스터 데이터라 확정 불변 대상이 아니다(ADR-03 "규제 변경은 관리 화면에서 흡수" — 확정 전표 불변(ADR-05)은 전표 계약). CONFIRMED 행의 수정은 허용하되 위 CHECK가 근거 소실을 막는다. "그때 요건"의 동결은 S2-2 인스턴스 스냅샷 몫.

**2-3. `template_checklist`** — 근거: §5.1(certification_tasks의 원천 — "체크리스트, 서류 링크"), §5.6(공통 수출 서류 CFS·GMP·CoA는 "체크리스트가 참조하는 공용 문서").
- 컬럼 초안: `template_id` FK NOT NULL / `seq` positive NOT NULL·unique_active(template_id, seq) / `item_name` NOT NULL / `document_type_id` FK **nullable**(§5.6 서류 참조 항목만 연결 — 서류 없는 행정 절차 항목이 실재한다) / `is_required` boolean NOT NULL / `note`.
- S2-2가 인스턴스 생성 시 certification_tasks로 **참조 복사**한다(ADR-05 참조 생성) — 이번 세션은 정의까지.

**2-4. `template_prerequisites`** (신설 여부 자체가 판정 — 안건 1. **판정 확정 2026-08-07: 교차 테이블 신설 — §0-1 ①, 조건 1**) — 근거: §5.1 문면 "선행요건".
- 쟁점: 문면이 단복수를 못박지 않는다. (a) 단수 self-FK 컬럼 vs (b) 다중 교차 테이블.

## 4. 마스킹·민감 컬럼 사전 점검 (요구 c)

- **신규 금액 컬럼 1건**: `requirement_templates.estimated_cost_amount`(+`estimated_cost_currency` 쌍). **비마스킹 판정 요청(안건 4)** — 근거: ADR-0018·0024의 보호 대상은 원가·마진이고, 인증 예상 비용은 요건 준비 판단이 소비하는 운영 필요 데이터다(여신한도 선례 ADR-0026과 같은 지위). **재판정 트리거안: 비용 원장 도입 세션(S3-4 — §10.1 expense_types에 '인증비' 열거 실재) 또는 역할 세분화 시.** 판정 결과는 마스킹 원장에 등재한다(수칙 — 구현은 판정 후에만).
- **금액·민감 컬럼 유니크 키 금지 준수**: 신규 5테이블의 어떤 유니크 키에도 금액·민감 컬럼이 들어가지 않는다(유니크 키는 code·(market,name)·(template,seq)·FK 쌍뿐). 이 규율은 K 아키텍처 테스트(`test_no_unique_key_contains_a_cost_column` — Base.metadata **전수 자동 스캔**)에 신규 테이블이 자동 편입된다. **컬럼명이 규약 접미사를 따라야 이 스캔이 실효한다** — 계획 검증에서 `_minor` 같은 비규약 접미사는 금액 감지기(`is_money_column_name` — `_amount`·`_cost` 등 접미사 매칭)에 안 걸리는 것을 실측했고, 그래서 이름을 선례 꼴 `estimated_cost_amount`로 확정했다. 편입 사실은 감지기 자기검사에 1건 추가해 고정한다.
- 금액 규약: BIGINT 정수 최소단위+CHAR(3) 통화 쌍 CHECK(ADR-0003 ④ — credit_limit 선례 문면 그대로), Float 금지는 K 자동 스캔 기편입.
- 그 외 민감 컬럼 없음: source_url·last_verified_on·체크리스트 항목명은 비민감. 로그 마스킹 신규 대상 0건(원가·비번·토큰 계열 부재).
