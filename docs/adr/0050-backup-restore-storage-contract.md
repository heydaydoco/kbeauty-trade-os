# ADR-0050: 백업은 암호화 세트+복원 리허설까지 — 스냅샷 일관 매니페스트·fail-closed·앱은 읽기 전용·물리 정리는 기본 OFF·worker 잡 자동 등록

- **상태**: 채택 (S2-4 계획 **자율 확정** — 오너 자율 지시[2026-09-29]에 따라 웹 세션 판정 없이 권장안 확정, 계획 §5 ⑩~⑬. 사후 번복 가능)
- **날짜**: 2026-09-29
- **관련**: DESIGN.md §2(접근 통제·audit)·§15(스케줄 레지스트리·자동화 4금)·§17.1(트랜잭션 안 외부 IO 금지)·§18.4(스토리지 용량 모니터링)·§21(백업=복원 리허설까지)·§22 / ADR-0029(문서 저장소)·0043~0046(알림·배치) / PROGRESS 관찰 "[S1-3] 실물 잔존·용량 모니터링"·S2-3 판정 요청 17 / s2-4-plan.md §2 안건 ⑦~⑩

**맥락** — Phase 2는 "실사용 개시"이고(§19), 그 직전에 데이터가 사라질 때 되돌릴 수단이 없다면 지금까지의 모든 기능이 무의미하다. §21은 "백업은 DB+파일 세트 복원 리허설까지가 백업"이라 못박았지만 v1.0의 어느 세션에도 배정돼 있지 않았다(S2-4 산출물로 추가). 판단할 것은 다섯이다: 백업의 형태·보안, "백업이 있다"를 어떻게 증명하는가, 앱이 백업에 어디까지 접근하는가, 백업이 조용히 안 도는 것을 어떻게 잡는가, 소프트 삭제 문서의 실물을 언제 지우는가.

**결정** — ① **세트 = DB 덤프(pg_dump -Fc)+files/ 묶음+manifest.json**, 두 산출물은 **AES-256-CBC+PBKDF2(600000)로 암호화**(패스프레이즈 `KBOS_BACKUP_PASSPHRASE` 16자 이상 — **없으면 실행 거부[fail-closed, 평문 백업 금지]**). 세트는 임시 폴더에서 만들어 성공했을 때만 최종 이름으로 rename하고(반쪽 세트 금지), 파일 600·폴더 700, 이름 규칙(`kbos-YYYYMMDDTHHMMSSZ`)에 맞는 세트만 최근 14개 보관·삭제한다. **manifest의 테이블별 행수는 pg_dump와 같은 스냅샷(pg_export_snapshot)에서 센다** — 백업 중 쓰기가 있어도 덤프와 매니페스트가 일치한다. 실행 위치는 postgres:16.14 이미지(compose `backup` 서비스 — 앱 이미지에 클라이언트를 넣지 않는다), 덤프는 기존 소유 계정, 리허설은 기존 슈퍼유저(스크래치 DB 생성) — **새 비밀 도입 없음**(패스프레이즈만 신규). dev는 profile `backup`(기본 미기동), prod는 기본 포함. ② **복원 리허설**(주 1회 일요일 04:00 KST, 일일 백업 03:00 KST): 최신 세트를 **스크래치 DB에 실제로 복원**해 ⓐ 산출물·평문 해시 ⓑ 테이블별 행수(여분 테이블도 실패) ⓒ 마이그레이션 head ⓓ FILE 문서 전건 실물·sha256(물리 정리된 문서 제외) ⓔ FILE 문서 수를 검증하고, 결과 JSON을 기록하며 **실패해도 기록하고 비0 종료**, 스크래치 DB는 항상 삭제한다. ③ **앱은 백업 볼륨을 읽기 전용으로만 본다**: 관리자 전용 `GET /api/v1/system/backups`(세트 목록·최근 리허설·신선도 문제 — **호출마다 audit**)가 매니페스트 요약만 돌려주고 **산출물 본체를 내려주는 API는 만들지 않는다**(전 데이터 유출면). ④ **신선도 감시 잡 `backup-freshness`**(daily@08:00 KST): 최신 백업 26시간 초과·리허설 8일 초과(백업이 8일 넘게 쌓이는데 리허설이 없으면 NO_REHEARSAL)·마지막 리허설 실패(읽을 수 없는 결과 파일도 실패)·사용할 수 있는 세트 없음 → ADMIN 알림(일자[KST]+종류 dedup). `KBOS_BACKUP_DIR`가 없는 환경(dev 기본)에서는 건너뛴다(OK). ⑤ **저장소 감시 잡 `storage-monitor`**(daily@05:00 KST): 여유율(임계는 `alert_rules.config` 데이터 — 기본 경고 20%·위험 10%, 형이 흐리거나 경고≤위험이면 기본값)·**고아 파일**(DB 행 없음, 수정 1시간 이내는 제외 — 업로드는 실물 먼저 쓰고 행을 나중에 만든다)·**유실 파일**(실물 없는 FILE 행, 정리된 문서 제외)을 ADMIN에 알리되 **고아·유실은 보고만 한다(자동 삭제·복구 금지)**. ⑥ **실물 물리 정리**(S2-3 요청 17): 소프트 삭제된 FILE 문서를 **유예기간(기본 30일) 경과+보존기한 없음/경과(당일은 아직 잠금)**일 때만 실물 삭제 후 `documents.purged_at` 기록(마이그레이션 1컬럼+CHECK: 소프트 삭제된 FILE에만) — **되돌릴 수 없어 기본 OFF**(`KBOS_FILE_PURGE_ENABLED`), CLI `purge-files`는 **기본 dry-run(`--apply`만 실행)**, 잡은 OFF면 후보 수만 보고. 파일 IO는 트랜잭션 밖, 기록·audit는 건별 트랜잭션에서 잠금 후 **조건을 재확인**(TOCTOU)하고, 삭제 뒤 기록 전에 죽으면 다음 실행이 "이미 없음"으로 기록을 마무리한다. 소프트 삭제 문서는 원래 다운로드 404라 별도 410은 만들지 않는다. ⑦ **worker는 기동 시 레지스트리의 새 잡을 자동 등록한다**(멱등 — 이미 있는 행·관리자가 끈 상태는 건드리지 않는다): 수동 register-jobs를 잊어 신규 잡이 조용히 안 도는 사고를 막는다. ⑧ **장애 SOP·수기 표준 양식·백업 운영 절차**를 runbook에 둔다(§21: 수기 기록→소급 입력[증빙일=실제 발생일·입력일=복구일]+검산 1회). 소급 입력 대응표는 **현재 존재하는 필드만**(문서 발급일·인증 신청/승인/시작/만료일·통신 기록 오간 날) 가리키며 전표 계열은 도래 시 갱신한다(발명 금지) — 문서 계약 테스트가 대응 필드의 실재를 고정한다.

**근거** — 백업이 평문이면 백업 볼륨 유출이 곧 전 데이터 유출이고 fail-closed가 아니면 "패스프레이즈를 빠뜨린 날부터 평문"이 된다. 스냅샷을 공유하지 않으면 행수 대사가 백업 중 쓰기 때문에 거짓 실패하거나(더 나쁘게) 거짓 통과한다. 복원해 보지 않은 백업은 있다고 믿는 것일 뿐이라 리허설이 백업의 정의다 — 통과하는 리허설이 변조·유실을 잡아내는지를 테스트가 변조 세트로 증명한다. 앱이 산출물을 다루는 순간 앱 침해가 곧 전 데이터 유출이 되므로 매니페스트 요약과 audit 조회까지만 허용한다. 신선도 감시가 없으면 "백업이 조용히 안 도는" 상태가 사고 뒤에야 드러난다. 물리 정리는 되돌릴 수 없는 유일한 동작이라 기본 OFF·dry-run·유예·보존기한·재확인의 다중 방어를 둔다(실물이 사라지면 백업 외에 복구 수단이 없다). 잡 자동 등록은 "등록만 하면 도는 코드 고정 폐쇄 열거"(스케줄러 독스트링)와 모순되지 않는다 — 새 동작이 생기는 것이 아니라 이미 코드에 있는 잡의 행이 생길 뿐이다.

**기각한 대안** — 평문 백업+디스크 암호화에 의존(볼륨 복제 시 노출), 스냅샷 없이 백업 후 행수 집계(경합), 리허설 없는 "백업 성공" 로그(복원 불가를 모름), 앱에서 산출물 다운로드 API(유출면), 앱 이미지에 pg 클라이언트 포함(이미지 비대·공격면), 백업 전용 새 DB 계정·비밀(비밀 증식), 고아 자동 삭제(업로드 중단·이관 중 정상 파일 삭제 위험), 물리 정리 기본 ON·유예 없음(복원 가능성 상실), 수동 register-jobs 유지(신규 잡 미등록 사고).

**되돌리기 비용** — 낮음~중간. 마이그레이션 1건(컬럼 1+CHECK 1 — downgrade 완결, 정리 기록은 소실). 스크립트·compose·잡은 파일 단위로 교체 가능하고, 이미 만들어진 세트는 manifest `format_version`으로 구분된다. 패스프레이즈를 바꾸면 그 이전 세트는 옛 패스프레이즈가 있어야 풀린다(문서에 명시).

**부기(2026-09-29 PR-3 적대 검증 반영 — 결정 불변, 구현 정정·경계 명문화)** — ① **물리 정리 순서**: 잠금 → 조건 재확인 → `purged_at`·audit 기록(커밋) → **그 뒤에** 실물 삭제. (초안은 삭제가 잠금보다 앞서 재확인이 무의미했다 — 되돌릴 수 없는 동작에서 방어가 아니었다.) 기록 뒤 삭제 전 크래시·삭제 실패는 다음 실행의 잔여물 정리가 마무리한다. ② **앱의 백업 폴더 읽기**: 백업 컨테이너는 root로 돌고 앱은 비root uid라 폴더·매니페스트를 **755/644**로 두고 **산출물(.enc)만 600**으로 한다(앱 침해로도 산출물은 읽히지 않는다). 앱이 폴더를 못 읽으면 `BACKUP_UNREADABLE`(별도 종류)로 알리고 "백업 없음"으로 오보하지 않는다. ③ **복원은 새 DB로, 소유·권한까지**: 실제 복원 스크립트 `restore.sh`(새 DB 이름만·빈 폴더에만·소유 kbos_owner·ACL 그대로 — append-only REVOKE 유지)와 리허설 ⓕ(테이블 소유·앱 역할 읽기·audit_log UPDATE 불가)를 둔다. 초안 runbook의 `--no-privileges`+`20-grants.sql` 재실행 절차는 기존 객체에 권한을 주지 못해 잘못이었다. ④ **스케줄러는 catch-up**: "정확히 03:00 분"이 아니라 "오늘(KST) 03:00 이후이고 오늘 세트가 없으면" 실행한다(디스크 기록이 기준 — 내려갔다 올라와도 만회, 재기동해도 하루 두 번 안 돎, 실패 시도는 30분 재시도 간격). ⑤ **비정상 종료 잔여물**: 60분 넘은 `.tmp-kbos-*`(평문 덤프 가능)를 다음 실행이 지우고 SIGTERM은 EXIT trap이 지운다. ⑥ 리허설 ⓓ는 실패가 삼켜지지 않도록 결과를 먼저 받고 **검증 건수 = 대상 건수**를 단언한다. ⑦ 매니페스트의 미래 시각·불가능한 날짜 이름은 무시·건너뛴다(신선도 감시가 영구 "신선"·크래시가 되지 않게). ⑧ 소프트 삭제 문서는 원래 다운로드 404라 410을 만들지 않는다. ⑨ **알려진 한계**: 암호화는 CBC(무결성 인증 없음) — 무결성은 평문 매니페스트의 해시로 확인하며 볼륨 쓰기 권한자가 산출물과 매니페스트를 함께 바꾸는 경우는 막지 못한다(패스프레이즈 없이는 유효한 평문을 만들 수 없다). 고아·유실 알림은 해결될 때까지 매일 반복된다(가시성 우선 — 소음이 문제가 되면 집합 변경 시에만 알리도록 재판정). 리허설 결과 파일은 최근 30개만 보관한다.
