# ADR-0031: 커버리지 임계는 실측 96%에서 여유 2%p를 뺀 94%로 제안한다 (채택 — 게이트 도입)

- **상태**: **채택(2026-08-07 — S2-1 계획 판정 안건 6 승인, 조건 10).** ci.yml backend 잡에 `--cov-fail-under=94` 도입(S2-1 PR-1 별도 커밋). 보안 모듈 개별 임계는 **기각**(소형 파일 임계 요동 — 판정 문면), 대안 채택: 도입 커밋 완료 보고에 identity/passwords.py 미커버 문 정체 실측 포함, 보안 경로 미커버 확인 시 동일 PR에서 케이스 추가로 종결.
- 이전 상태: 제안 (초안 — 게이트 도입 금지 유지. 판정 ⑦(s1-5-plan.md §0-1)이 S1.5 범위를 "`--cov` 실측+임계 제안 ADR 초안까지"로 한정. 도입은 별도 웹 세션 판정으로만 — 이 문서가 그 판정의 안건이었고 S2-1 계획 판정이 그 자리였다)
- **날짜**: 2026-08-07
- **관련**: PROGRESS.md 부채 #8 / docs/plans/s1-5-plan.md §0-1 판정 ⑦·§0-3 / docs/plans/s2-1-plan.md §0-1 ⑥ / .github/workflows/ci.yml (`--cov-fail-under=94`)

**맥락** — 부채 #8: 커버리지를 측정만 하고(`--cov`) 임계 게이트가 없어 하락해도 CI가 잡지 못한다. 판정 ⑦이 실측 기반 초안까지를 S1.5 종결분으로 지정했다.

**결정(제안)** — backend CI의 pytest에 `--cov-fail-under=94`를 제안한다. 근거 실측(2026-08-07, 로컬 전체 1회 실행): 전체 **96%**(5328문 중 202문 미실행), 743케이스 전건 통과, 12분 49초. 95% 미만 모듈 15개, 최저 `identity/passwords.py` 76%(17문 중 4문 미실행 — 소형 파일이라 1문의 가중이 큼), 큰 파일 중 최저 `imports/registry.py`·`partners/service.py` 91%.

**근거** — 게이트의 목적은 하락 추세 차단이지 현상 동결이 아니다. 실측치 96에 바로 놓으면 정상 리팩터링(문 수 변동)마다 게이트가 깨져 임계 하향 커밋이 반복되므로, 실측에서 2%p 여유를 뺀 94가 "지금은 통과하고, 유의미한 하락(전체의 약 100문 이상 신규 미커버)만 잡는" 값이다.

**기각한 대안** — ① S1.5 내 즉시 도입(판정 ⑦ 위반), ② 모듈별 개별 임계(편차 76~100%에서 단일 하한은 최저치에 끌려가고, 개별 관리는 파일 수에 비례하는 유지 비용), ③ diff-cover식 신규 코드 한정(도구·CI 개편이 초안 범위 밖 — 도입 판정 시 재론 가능).

**되돌리기 비용** — 도입 전이라 0. 채택 시 ci.yml 한 줄(`--cov-fail-under=94`) 추가이고 철회도 그 한 줄 제거다. 임계 조정은 이 ADR의 실측 절차(전체 실행 1회 → 실측−2%p) 재적용으로 한다.
