# ADR-0043: 아웃박스 디스패처 계약 — 클레임=처리=표식 단일 트랜잭션·백오프·상한

- **상태**: 채택 (S2-3 계획 웹 세션 판정 2026-08-12 — 안건 ④·판정 요청 11·12 기승인, PR-1 실장)
- **날짜**: 2026-08-12
- **관련**: DESIGN.md §17.1·§17.6·§2 ADR-07·§16·§20 J / ADR-0044(실행기)·0045(수신자·dedup) / PROGRESS 부채 #11

**맥락** — S0-2부터 events는 적는 주체만 있고 보내는 주체가 없었다(의도된 상태 — 부채 #11). 소비 주체를 세울 때의 판단은 셋이다: 클레임 경계, 실패 처리, 보존.

**결정** — ① **건당 1클레임이 한 트랜잭션**이다: `SELECT … WHERE published_at IS NULL AND attempts < 5 FOR UPDATE SKIP LOCKED` → 규칙 평가 → 알림 생성 코어 → `published_at` 표식이 같은 트랜잭션 안이고, 후보 id 수집만 잠금 밖 읽기다. ② 실패는 그 건의 트랜잭션만 롤백하고 **실패 기록은 별도 트랜잭션**으로 남긴다(attempts+1·last_error·`next_retry_at`, 지수 백오프 60·300·900·3600초). ③ **시도 상한 5회**에 닿으면 대기열에서 빠지고 관리자 알림이 1회 나간다(§17.6 "실패 알림"). 대기열 이탈은 `published_at`이 아니라 대기열 질의의 `attempts < 상한`으로 표현한다. ④ 매칭 규칙이 없는 이벤트도 published 처리한다. ⑤ **events는 삭제하지 않는다** — 재판정 트리거는 10만 행(§2 아카이브 원칙 계보). ⑥ 평가 대상은 alert_rules뿐이고 webhook_subscriptions 평가는 S6-3이다.

**근거** — 행 잠금의 수명은 트랜잭션이라, 배치로 잠그고 건별로 커밋하면 첫 커밋에서 나머지 잠금이 풀려 동시 디스패처와 이중 처리가 열린다. 실패 기록을 같은 트랜잭션에 적으면 롤백과 함께 사라져 같은 실패를 영원히 반복한다. 대기열 이탈을 published로 적으면 "보내지 않은 것을 보냈다"가 되어 events가 발행 원장으로서 거짓이 된다.

**기각한 대안** — 배치 클레임 후 건별 커밋(이중 처리 창), 실패 기록 동일 트랜잭션(무한 반복), 무제한 재시도(포이즌 이벤트가 조용히 영구 잔존), 상한 도달분 published 처리(원장 거짓), 발송 후 N일 삭제(감사 계보 상실), webhook_subscriptions 선평가(매칭돼도 갈 커넥터가 없다).

**되돌리기 비용** — 낮다. 디스패처를 멈추면 events는 S0-2 상태(단조 증가)로 돌아가고, 이미 만들어진 alerts는 남는다. `next_retry_at` 컬럼과 인덱스 재정의는 마이그레이션 downgrade가 되돌린다.
