# ADR-0052: 전표 사슬 구조 — 8테이블·3계층 모듈 DAG·참조 카디널리티·소비량은 파생·수주전환은 SO 확정·복제/개정은 copied_from_id 하나

- **상태**: 자율 확정(2026-09-30) — 사후 번복 가능 (S3-1 계획 통합 검토서 §4.2 — A 묶음 A1·A4·A10·A12, B 묶음 B3·B5, 통합 X-08·X-18·X-19·X-20·X-23)
- **날짜**: 2026-09-30
- **관련**: DESIGN.md §3 표 맵·§7.1~7.3·§8.3·§17.2 / ADR-05(전표 사슬=참조 생성) / ADR-0003 ④(금액 행 단위 통화)·0041 / docs/plans/s3-1/design-A.md A1·A4·A10, design-B.md B3·B5, design-integrated.md §1.1·§1.2·§2.8

**맥락** — DoD "참조 생성만으로 QT→PI→SO 관통(재입력 화면 없음)"은 테이블 구성·참조 방향·잔량 산정·수주전환 시점이 한 번에 정해져야 성립한다. A·B 두 묶음이 QT 수주전환 시점(SO 확정 vs 후속 전표 첫 생성)과 복제·개정 표현(`revises_qt_id` vs `copied_from_id`), 모듈 계층(전이 오케스트레이션의 위치)을 서로 다르게 잡아, 통합 검토가 하나로 정했다.

**결정** — ① **헤더+라인 8테이블**(`quotations`·`proforma_invoices`·`sales_orders`·`purchase_orders`와 각 `*_lines`). PI 라인은 §3 표 맵에 `(+lines)`가 없으나 표기 누락으로 확정한다. 라인은 자기 `currency`를 갖고 **헤더와 복합 FK `(hdr_id, currency)`로 묶어** 혼합 통화를 DB가 막는다. FK 열 이름은 `qt_id·pi_id·so_id·po_id`(식별자 63자 한도), 라인은 Version 믹스인 없이 헤더 version으로 직렬화하며 ORM `relationship`은 두지 않는다. ② **모듈 계층은 단일 DAG(임포트 방향 아키텍처 테스트로 고정)**: **L0 `trade_docs`**(상수·믹스인·기계 표·`record_birth/record_transition`·`FIELD_POLICY`·`CHILD_LINKS` 레지스트리와 `has_live_children`[테이블명 기반 쿼리, 모델 무임포트]·`lock_document`·`open_quantity`·상태이력 모델) / **L1 전표별 모듈**(모델·스키마·CRUD·라인 편집만) / **L2 `trade_chain`**(모든 전이 오케스트레이션 — issue·confirm·cancel·hold/resume·transitions 라우터, `converge_parent`·`lock_chain`·참조 생성·개정·만료 스윕·`document_flow`)과 `credit`·`payments`·`order_intake`·`order_board`. 그래서 SO 취소는 `sales_orders.service`가 아니라 `trade_chain.lifecycle.cancel_sales_order`다. ③ **참조 카디널리티**: QT→PI 1:N / PI→SO 활성 1:1(취소 후 재생성 허용) / QT→SO 직접 1:N / **PI의 `qt_id`는 NOT NULL**(직접 PI 발행 경로 없음)·SO의 `qt_id`·`pi_id`는 NULL 허용(직접 인테이크 SO) / SO 라인은 `qt_line_id`·`pi_line_id` 중 하나만(`num_nonnulls<=1`). ④ **소비량·잔량은 열로 저장하지 않고 하위 라인 SUM으로 파생**한다. 소비자 레지스트리 `LINE_CONSUMERS`의 키는 `QT_LINE·PI_LINE·SO_LINE·PO_LINE`이고 S3-1 등록은 3건(QT_LINE←PI_LINE.qt_line_id, QT_LINE←SO_LINE.qt_line_id, PI_LINE←SO_LINE.pi_line_id)이며 "활성"은 `deleted_at IS NULL`이고 CANCELLED·EXPIRED가 아닌 전표의 라인(초안·접수 포함)이라 만료·취소 PI의 수량은 QT로 환원된다. 선적·입고 소비는 **헤더 `FOR SHARE`(`CONSUMABLE_STATUSES` 검증)→라인 `FOR UPDATE` id 오름차순**(`lock_lines_for_consumption`)으로 직렬화하고, 이는 S3-1 로컬 결정이라 **S4-1 ADR이 `lock_lines_for_consumption`·`open_quantity` 시그니처와 라인 안정 id를 유지하는 한 대체할 수 있다**(DESIGN §8.3 부기). ⑤ **QT 수주전환(CONVERTED)은 "그 QT에서 파생된(직접 또는 PI 경유) 살아 있는 확정 SO(`confirmed_at IS NOT NULL`)가 1개 이상"인 상태**다. `converge_parent`의 목표는 확정 SO ≥1이면 CONVERTED, 아니면 ISSUED(유효기간 경과+살아 있는 후속 0이면 EXPIRED)이고 SO 확정·SO/PI 취소·만료 시점에 호출한다. 후속(PI·SO)이 살아 있는 QT·PI는 만료 스윕 대상에서 제외하며 후속 생성 가드(`is_lapsed`)는 그대로 둔다. ⑥ **복제와 개정은 `copied_from_id` 하나로 통일**한다(`revises_qt_id`는 만들지 않는다). 복제 원본은 CANCELLED·EXPIRED일 때만 허용(`COPY.SOURCE_NOT_ELIGIBLE`, 동일 유형·동일 거래처)하되, `POST /quotations/{id}/revisions`는 **원본이 ISSUED일 때만 허용되는 유일한 복제 진입점**이고 개정 초안의 발행 트랜잭션이 원본을 사람 엣지(ISSUED→CANCELLED, 사유 자동 문구)로 취소한다. 개정본은 `CHILD_LINKS`에서 제외(계보 표시이며 사슬 후속이 아니다)하고, 4종 공통 부분 유니크 `(copied_from_id) WHERE deleted_at IS NULL AND copied_from_id IS NOT NULL AND status NOT IN ('CANCELLED','EXPIRED')`로 "살아 있는 복제본 1개"를 DB가 보증한다. ⑦ **참조 생성 API**(QT→PI·QT→SO·PI→SO)는 요청 스키마에 원천에 이미 있는 값(SKU·단가·통화·환율·거래처·시장·스냅샷)을 다시 받는 필드가 **존재하지 않고**(`extra=forbid`, 낙관 잠금 본문 필드는 `version`), `Idempotency-Key`가 필수이며 한 트랜잭션에서 원천 헤더 `FOR UPDATE`→원천 라인 `FOR UPDATE` id순→요청 수량≤잔량 검증→**선행 전표 값을 복사(마스터 재조회 금지, `line_amount`는 새 수량×복사 단가로 재계산)**→채번(마지막)한다. 원천 자격은 참조 허용 상태 **그리고** `valid_until >= today_kst()`이며(상태만 믿지 않음), 입금이 있는 PI(PARTIALLY_PAID·PAID)는 유효기간을 면제한다. **PI·PO에 초안 상태가 없으므로 편집 요구는 비저장 미리보기**(`POST …/proforma-invoices/preview`·`POST /purchase-orders/preview` — 채번·감사·이벤트·멱등 소비 없음)로 충족한다. ⑧ **라인 편집 API는 라인 단위 엔드포인트**(`/{doc}/{id}/lines/{line_id}`)이고 공개 함수는 `add_line·update_line·remove_line` 3개(모두 `assert_editable`→헤더 `FOR UPDATE`→version 대조→헤더 version 증가→`recompute_total`)이며 응답에 갱신된 헤더 `version`·`total_amount`를 싣는다. ⑨ **할당·백오더 분기 포트** `AllocationPort`(`on_confirmed`·`on_cancelled`)는 같은 트랜잭션의 동기 호출이고 S3-1 기본 구현은 `NOT_IMPLEMENTED`를 반환해 **SO 확정 응답 `allocation` 필드로 그대로 노출**(할당이 된 것처럼 보이지 않게)하며, 포트 예외는 확정 전체를 롤백한다.

**근거** — 잔량을 유지 컬럼으로 두면 소비 코드 없는 죽은 컬럼이고 §8.3이 P4 ADR로 남긴 결정을 선점하며, 카운터 불일치의 결함 원천이다(SUM 파생은 드리프트가 구조적으로 불가). 수주전환을 SO 확정으로 잡은 것은 PI가 오퍼 회신이고 SO 접수는 게이트 전이라 "수주 성립"이 아니기 때문이며(§7.2 문면의 "수주전환"은 SO 단계), B가 원했던 후속 생성 시점 전환과 달리 엣지 수·자동/사람 구분·총수(QT 6·14)는 그대로 둘 수 있다. 개정을 별도 자기참조(`revises_qt_id`)로 두면 개정 초안이 원본의 살아 있는 후속으로 잡혀 원본 취소가 자기 자신 때문에 막히는 교착이 생기므로 복제 계보 하나로 합쳤다. 계층 재배치는 L0/L1이 L1/L2 모델을 요구하는 순환(취소 시 `converge_parent`가 부모 QT 모델을 갱신)을 없앤다. 참조 생성이 원천 값을 다시 받지 않는 구조가 "재입력 화면 없음"의 스키마 수준 보증이다.

**기각한 대안** — 잔량·소비량 유지 컬럼(불일치·죽은 컬럼), 수주전환을 후속 전표 첫 생성 시점으로(PI를 수주로 오독), `revises_qt_id` 별도 열(개정 교착·복제와 이중 정의), 원본 자동 취소를 위한 "합성 전이"·새 사유 코드(기존 사람 엣지 ISSUED→CANCELLED로 충족), 라인 통화 열 없음(행 단독 금액이 자립하지 않아 ADR-0003 ④ 위반), 라인 단독 PATCH/DELETE 없이 `replace_lines` 전체 교체(참조 FK 보존용 안정 id·IDOR 헬퍼와 불합치), PI·SO에 미리보기 대신 초안 상태 추가, L1 안에서 전이 오케스트레이션(순환 임포트).

**되돌리기 비용** — 중간~높음. 참조 요청 계약과 수주전환 시점은 프런트·테스트가 즉시 의존한다(수주전환 시점을 SO 접수로 앞당기는 것은 서비스 1곳이나 QT 상태 의미가 바뀐다). PI→SO를 1:N으로 푸는 것은 부분 유니크 1개 제거+입금 귀속 재정의(중간). 라인 통화 복합 FK 철거나 PI 라인 신설/제거는 S3-2 소비 시작 후 높아지므로 첫 PR 전에 확정한다. 잔량 표현 교체는 시그니처가 유지되면 소비자 무영향(낮음).

**영향 세션** — S3-1 PR-5~8·12(구현) / S3-2(shipment 라인이 `LINE_CONSUMERS['SO_LINE']`·`CHILD_LINKS`에 등록 — 누락은 K 테스트가 실패로 알림·SO 후반 엣지) / S3-3(QT·PI 서류가 스냅샷을 소비) / S4-1(PO 후반·잔량 표현 ADR) / S4-2(`AllocationPort` 실구현) / S3-4(백오더=open−allocated 파생).
