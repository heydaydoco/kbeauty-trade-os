# ADR-0053: 동결·불변·정정·취소 — 열 분류(FIELD_POLICY)가 정본·트리거/해시 미채택·취소는 상태 전이·정정은 취소+신규·전표 삭제 경로 0

- **상태**: 자율 확정(2026-09-30) — 사후 번복 가능 (S3-1 계획 통합 검토서 §4.2 — A 묶음 A3, B 묶음 B2·B3·B9, 통합 X-03·X-04·X-07·X-09·X-22)
- **날짜**: 2026-09-30
- **관련**: DESIGN.md §2 ADR-05·§17.4·§17.5·§20 A·H / ADR-0028·0033·0038·0040(트리거 반복 기각) / docs/plans/s3-1/design-A.md A3, design-B.md B2·B3·B9, design-integrated.md §1.1·§1.3

**맥락** — WBS DoD "확정 후 단가·환율 불변"이 검증 가능하려면 "무엇이 언제 불변인가"가 열 단위로 있어야 하고, ADR-05의 "역순 취소만·역기록=원본 불변+반대 부호 신규 기록"을 원장·수량을 쓰지 않는 4종 전표에 어떻게 적용할지 정해야 한다. 전표 헤더는 상태 전이 UPDATE가 앱 계정의 정상 쓰기라 GC-A4("확정 전표 UPDATE/DELETE 불가—DB 권한")를 그대로 적용할 수 없다.

**결정** — ① **동결 시점**: QT=발행(ISSUED 진입) / PI=생성(=발행) / **SO=확정** / PO=생성(=발행). 표식은 QT·PI·PO=`frozen_at`, **SO=`confirmed_at` 하나**(SO에 `frozen_at`은 만들지 않는다)이며 단일 출처 상수 `FREEZE_COLUMN = {QT:'frozen_at', PI:'frozen_at', SO:'confirmed_at', PO:'frozen_at'}`를 `frozen_complete` CHECK·동결 판정·`FIELD_POLICY`가 공유한다. 편집 가능 상태는 QT:DRAFT·SO:RECEIVED 두 곳뿐(PI·PO는 편집 구간 없음), ON_HOLD는 동결 취급. ② **열 분류 레지스트리 `FIELD_POLICY`가 유일 정본**이다(4 헤더+4 라인의 모든 컬럼을 CONTENT·ORIGIN·FREE·SYSTEM 중 정확히 하나로 등재, 미등재·유령=CI 실패). CONTENT=편집 가능 상태에서만 수정·동결 후 불변, ORIGIN=생성 시 1회 결정·이후 어느 상태에서도 불변(참조 FK·`copied_from_id`·**SO의 `buyer_partner_id`** — 여신 잠금이 "거래처→SO" 순서를 지키려면 SO의 거래처를 잠금 전에 읽을 수 있어야 한다), **FREE는 정확히 4개(`internal_note`·`assignee_id`·`oc_reference`·`oc_received_on`)**, SYSTEM=서비스 통로 외 대입 불가(id·`doc_number`·status·version·`confirmed_at`·SO 증적 3열·감사 컬럼·`deleted_at`). 동결 열 집합(`FROZEN_*`)과 동결 제외 집합은 FIELD_POLICY에서 **파생**하며 수기로 따로 정의하지 않는다. 라인 열은 전부 CONTENT, 요청납기도 CONTENT이고 라인에는 내부 메모 열을 두지 않는다. SO는 승인 결속 토큰 `content_rev` 열을 만들지 않고 **digest 하나**(`gate_input_digest`)를 쓴다(ADR-0060). ③ **강제 계층은 DB CHECK(상태값·`confirmed_at` 정합·QT `valid_until`·PO OC·`frozen_complete`·자기참조 금지)+서비스(모든 수정은 `update_document`/`add_line·update_line·remove_line`/`update_meta` 통로만, CONTENT·ORIGIN이 현재값과 다르면 409 `DOCUMENT.FROZEN`, detail=필드명만)+아키텍처 테스트(FIELD_POLICY 완전성·핀 고정·`assert_editable` 미경유 쓰기 0)**이고 **DB 트리거와 동결 해시/다이제스트는 채택하지 않는다**(리포 `CREATE TRIGGER` 0건, 인계 일괄 UPDATE 예외 로직·plpgsql 부담, 후속 세션이 CONTENT 컬럼을 추가하면 기존 동결 행의 해시가 전부 불일치하는 스키마 진화 위험). ④ **GC-A4 해석**: GC-A4("UPDATE/DELETE 불가—DB 권한")는 S4-1 매핑의 출고 전표·원장 문면이며, S3-1은 그중 ADR-05 취소 세칙(원본 불변·취소가 원본 참조 기록)만 유추 적용한다 — S3-1 부채로 오독하지 않는다. ⑤ **취소는 상태 전이이고 역전표를 만들지 않는다**: 4종은 원장·수량·회계를 직접 쓰지 않으므로 "반대 부호 신규 기록"은 (a) 원본 CONTENT 불변 (b) 원본을 참조하는 신규 불변 이력 행(사유·행위자·일시, ADR-0051)으로 충족하고, 여신 노출·미결 잔량·백오더는 LIVE 전표에서 파생되므로 취소만으로 자동 복원된다. 취소 사유·행위자·일시의 유일 원천은 상태이력이며 헤더에 `cancelled_*` 복제 열을 두지 않는다. ⑥ **LIVE = `deleted_at IS NULL AND status NOT IN ('CANCELLED','EXPIRED')`**(`machine.DEAD_STATUSES`에서 생성 — COMPLETED·CLOSED·FULLY_RECEIVED·ON_HOLD도 살아 있다). 취소 요청(to=CANCELLED, 대상 비종결)은 **엣지 검사보다 먼저** 살아 있는 후속을 검사해 409 `CANCEL.SUCCESSOR_ALIVE`(detail=후속 문서번호 목록, 금액 없음)이고, 후속 등록부는 `CHILD_LINKS`(QT←PI·QT←SO·PI←SO 3건 등록; 이 표를 가리키는 모든 FK는 `CHILD_LINKS` 또는 `NON_CHILD_FK_ALLOWLIST`에 있어야 한다는 테스트가 S3-2의 등록 누락을 잡는다)다. ⑦ **SO 취소 트랜잭션 순서**(`trade_chain.lifecycle.cancel_sales_order`): 조상→SO 잠금→상태 검사→후속 검사→**`approvals.void_for_target(reason_code='TARGET_CANCELLED')`**(REQUESTED와 미소비 APPROVED를 VOIDED로, 이미 CONSUMED인 승인은 건드리지 않음)→`AllocationPort.on_cancelled`→`record_transition(CANCELLED, 사유)`→부모 연쇄 수렴, 어느 단계든 실패하면 전체 롤백. ⑧ **수량·납기·단가 변경 경로=취소+신규(단일 경로)**이며 취소와 복제는 **두 개의 독립 동작**(각각 멱등·원자, 결합 액션 없음)이다. 정정 전표(승인 동반 개정본)는 만들지 않는다. 취소 SO의 **바이어 PO번호는 재사용 가능**하도록 중복 바이어 PO·PI→SO·복제본 부분 유니크의 술어에 `status <> 'CANCELLED'`를 넣는다(DESIGN §17.4 술어 보강 — 정정=취소+신규 경로 보장). ⑨ **전표 삭제 경로는 없다**(DELETE 메서드·soft delete 쓰기 경로 0 — 폐기의 유일한 방법은 사유 필수의 CANCELLED이며 행과 번호는 남는다). 우회 경로 10건(상태 PATCH·벌크·인테이크/임포트 확정·CLI·ADMIN 역할·soft delete 은닉·라인 직접 쓰기·이벤트 재시도 이중 실행·평가 불능을 통과로 취급·자동 발주 확정)은 차단표와 아키텍처 테스트로 고정한다. ⑩ `frozen_at`은 동결 전이 트랜잭션에서 한 번 채우고 지우지 않으며(취소는 status로 표현), SO의 `confirmed_at`은 재설정·해제가 없다.

**근거** — 기본 동결(열 단위 분류가 정본이고 미분류=CI 실패)은 "조용한 미동결"을 구조적으로 막는다. FREE를 4개로 좁힌 것은 인계 일괄 UPDATE가 동결 전표에서도 `assignee_id`를 바꿔야 하고 OC 기록·내부 메모는 오기 정정이 필요하지만 그 밖은 거래 조건이기 때문이다. 트리거는 ADR-0028·0040이 반복 기각한 수단이고(권한 제거로 충분한데 수단이 늘어난다), 상태 의존 동결은 행 교차라 CHECK로 표현할 수 없다. 취소를 전이로 보는 해석은 ADR-05 문면의 "전표·원장 공통"의 적용 범위를 판정한 것이며, 살아 있음 판정에 `deleted_at`을 포함하고 삭제 경로를 없애야 결번·번호 재사용·고아 이력 논쟁이 봉쇄된다(ADR-0054). §17.4의 "부분 인덱스"가 삭제 후 재유입 허용이 목적인 것과 달리, 취소된 SO의 바이어 PO번호는 정정이 같은 번호를 다시 받아야 하므로 취소를 술어에서 제외한다.

**기각한 대안** — 동결 해시/다이제스트·야간 전건 재해시(스키마 진화 시 전량 불일치, 관찰 등재), DB 트리거(선례 기각), 정정 전표(승인 동반 개정본 — 신규 테이블·상태·승인 유형·잔량 재계산), 취소 시 역전표·반대 부호 행 생성(원장이 아닌 전표에 의미 없음), 헤더에 `cancelled_*` 복사 열(원천 이중화), 소프트 삭제로 폐기(결번·번호 재사용), `frozen_at`과 `confirmed_at` 이중 보유(SO에 같은 뜻의 열 2개), 라인 내부 메모 열(FREE 4개 고정 위반), 취소·복제를 하나의 `cancel-and-clone` 액션으로(취소 성공·복제 실패의 부분 상태).

**되돌리기 비용** — 낮음(FREE 확장·분류 1줄+핀 테스트+ADR)~높음(취소+신규→정정 전표 전환: 신규 테이블·상태·승인 재정의. 그래서 실사용 마찰이 확인될 때까지 관찰 트리거로 등재). 트리거·다이제스트 추가는 마이그레이션 1건(낮음). 분류 레지스트리·`confirmed_at`은 신규 테이블 시점이라 지금이 최저가다.

**영향 세션** — S3-1 PR-5~8·12 / S3-2(선적은 SO 확정 후만 복사, `CHILD_LINKS` 등록) / S4-1(GC-A4 본 대상 — 출고 전표·원장 권한 회수) / C(승인 후 불변이 같은 동결 집합을 사용) / 후속 세션은 신규 CONTENT 컬럼 추가 시 분류를 강제당한다.

**부기(2026-10-04 — S3-2 계획)** — (자율 확정 — 사후 번복 가능. 위 원문 결정은 고치지 않는다.) **선적 복사·동결**: 선적은 확정된 SO(CONFIRMED·IN_SHIPMENT) 또는 소비 가능 PO(ISSUED·SUPPLIER_CONFIRMED)에서만 참조 생성하며 통화·고정 환율·결제조건 4열·Incoterms 3열·거래 상대·SKU 품명을 **ORIGIN 사본**으로 받는다(생성 본문에 필드 없음). **`doc_date`는 복사가 아니라 생성 시 `today_kst()` 1회 설정·이후 불변(ORIGIN)**이다(R-15). 동결 시점 = 출고지시(PLANNED→RELEASE_ORDERED 동결 액션, `frozen_at`), 편집 가능 상태 = PLANNED뿐이며 그 뒤 CONTENT 수정은 `TRADE_DOCS.DOCUMENT.FROZEN`(선적 전용 코드 신설 없음).
