# ADR-0026: 거래처 다중 유형은 교차 테이블로 담는다

- **상태**: 채택 (웹 세션 판정 2026-08-05 — S1-3 계획 조건부 승인)
- **날짜**: 2026-08-05
- **관련**: DESIGN.md §4.6·§7.7·§10.4 / WBS.md S1-3 / ADR-0003·ADR-0018·ADR-0024

**맥락** — §4.6은 partners를 "다중 유형(공급사/OEM/바이어/RP/IOR/경내책임자/포워더/관세사/3PL/인증대행)"으로 정의한다 — 한 거래처가 공급사이면서 포워더일 수 있다. 이를 어떤 구조로 담을지, 그리고 여신한도의 마스킹 지위가 결정 대상이었다.

**결정** — 유형은 교차 테이블 `partner_type_links`(거래처 FK × 유형 코드 VARCHAR+CHECK 열거 10종, 부분 유니크 `WHERE deleted_at IS NULL`)로 담는다. 여신한도는 금액 규약(정수 최소단위+통화 쌍 CHECK — ADR-0003) 그대로이며 **마스킹 비대상**이다.

**근거** — 유형별 필터(§7.7 DG 미취급 파트너 제외, §10.4 소싱 후보)가 SQL 조인으로 서야 하고, 유형 열거는 §4.6에 고정 명문이라 CHECK가 스펙과 1:1이다(materials.material_type 선례). 여신한도 비마스킹의 근거는 ADR-0018·0024의 보호 대상이 원가·마진이라는 것 — 여신한도는 수주 게이트(§7.10)가 소비하는 운영 필요 데이터다. 재판정 트리거: 여신 게이트 도입 세션(S3-1) 또는 역할 세분화 시.

**기각한 대안** — 불리언 컬럼 10개(유형 추가마다 스키마 변경·열거와 이중 관리), 배열 컬럼(FK·CHECK 규율과 불합치, ADR-0003 정신 위반), 유형 마스터 테이블(§4.6 열거가 고정 문면이라 설정화 실익 없음 — ADR-11의 "데이터로" 대상은 열린 유형 코드다).

**되돌리기 비용** — 유형 구조 변경은 교차 테이블 마이그레이션+유형 필터 질의 전부. 여신 마스킹 도입은 응답 스키마 분기(ADR-0024 방식) 추가로 가능해 낮다.
