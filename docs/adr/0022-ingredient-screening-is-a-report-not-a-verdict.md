# ADR-0022: 성분 스크리닝은 판정이 아니라 대조 리포트다 (3분류·fail-closed·미저장·워딩 금지)

- **상태**: 채택 (웹 세션 판정 2026-07-30 — 조건 D)
- **날짜**: 2026-07-30
- **관련**: DESIGN.md §4.3·§1(비범위)·§5.3·§15(L3 금지 영역) / WBS.md S1-2 / GC-C3~C7

**맥락** — §4.3은 스크리닝의 출력 3분류(금지/제한초과/미등재)만 정하고 판정 규칙의 경계(함량 미입력, 빈 전성분, 규칙 공존, 저장 여부)는 정하지 않았다. §1은 "요건의 자동 판정"을 비범위로 못박고, §15는 법적 판정을 L3 금지 영역으로 둔다.

**결정** — 스크리닝은 **사용자가 근거를 확인해 등록한 규칙(ingredient_rules)과 전성분의 기계적 대조 표시**다: ① 미등재 = 성분×국가 규칙 행의 부재("안전"이 아니라 "근거 없음·확인 필요") ② RESTRICTED인데 함량 미입력 = 제한초과 버킷에 사유 표기(fail-closed) ③ 전성분 0건 = 빈 리포트가 아니라 명시적 오류(`INGREDIENTS.FORMULA.EMPTY`) ④ 게이트 0·계산값 미저장(§5.3 매트릭스와 같은 원칙) ⑤ 출력 어디에도 "적합/통과/합격" 판정 워딩 금지 — 한도 이내는 사실 서술만. 같은 성분×국가에 규칙은 한 행이다(유일키 (ingredient_id, country_code) — 금지·제한 공존 불허).

**근거** — 법적 판정이 아니라 등록 데이터의 대조이므로 §1·§15의 자동 판정 금지에 저촉되지 않되, 그 지위가 무너지는 경로(차단 게이트化·결과 영속화·판정 워딩)를 코드가 아니라 테스트가 막는다: 미저장은 아키텍처 테스트(test_screening_is_stateless), 워딩 금지는 부정 단언, 고정 문구 "참고용·근거 확인"(§4.3)은 존재 단언. 모르는 것을 통과로 세는 순간(함량 미입력·빈 전성분) 등록 누락이 "문제 없음"으로 읽힌다 — fail-closed가 맞다.

**기각한 대안** — ① 함량 미입력 = 별도 4번째 분류: §4.3·DoD가 3분류를 못박았다. ② 빈 전성분 = 검출 0건 리포트: "검사할 것이 없었다"와 "문제 없었다"가 같은 모양이 된다. ③ 금지·제한 공존 허용: 같은 성분이 금지이면서 제한초과로도 집계되는 모순 리포트가 가능해진다 — 용도별 상이 한도 요구가 실데이터로 오면 재판정(PROGRESS 관찰 항목).

**되돌리기 비용** — 낮다. 저장이 없어 스키마 영향이 없고, 분류 경계는 서비스 한 곳이다. 유일키 완화(공존 허용)만 마이그레이션+리포트 규칙 재정의가 같이 움직인다.
