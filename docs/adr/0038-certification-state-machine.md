# ADR-0038: 인증 상태머신 — 11값·27전이·만료 비종결·갱신 직행 왕복·차단 3층

- **상태**: 채택 (S2-2 계획 웹 세션 판정 2026-08-11 — 안건 ③·조건 A·B·E)
- **날짜**: 2026-08-11
- **관련**: DESIGN.md §5.2·[M2] 보강(S2-2 PR-1) ② / ADR-11(상태는 코드 고정) / GC-C9·C10 / backend/app/modules/certifications/machine.py(정의 정본)

**맥락** — §5.2 문면(미착수→…→승인→만료임박(자동)→갱신중→… / 반려·만료·중단(사유 필수))은 갱신 이후 경로와 만료의 지위를 말줄임으로 남겼다. 계획 적대 검증이 "만료=종결+자동" 조합의 불가역 고착(오입력 정정 불가), 갱신 재진입의 축 혼동(갱신 신청 반려가 유효 인증을 종결), 리드 부재 인증의 갱신 진입로 차단을 확정 결함으로 검출했다.

**결정** — ① 만료=비종결 달력 파생 상태(사유는 자동 기록 — 조건 B로 DB CHECK 3종 포함), 종결=반려·중단 2태뿐(재도전=신규 인스턴스). ② 갱신=직행 왕복(만료임박·승인·만료→갱신중, 갱신중→승인 — 재진입 배제, 절차 세부는 태스크·comm_logs). ③ 자동 전이=달력 파생 3태 상호 6방향뿐(부여+해소 복귀 대칭 — #16 비대칭 결손 금지 계보), 승인 진입은 사람 기록 2경로뿐(4금 ①). ④ 허용 27(사람 21+자동 6)·미허용 83 — 총수를 아키텍처 테스트가 고정(조건 E). ⑤ 3태 진입·만료일 정정 직후 같은 트랜잭션 즉시 수렴(조건 A — 거짓 상태 창 제거). ⑥ 차단 3층: DB(값·사유·기간 CHECK — 전이 규칙 자체는 행 내 검증의 한계로 불가·명문화)/서비스(전이 표 단일 상수·상태 대입 단일 통로·스키마 status 부재+extra 거부)/아키텍처 테스트(전수·스캔).

**근거** — 상태 축은 "기존 인증의 유효성"을 표현해야 매트릭스(§5.3)의 원천이 되고, 달력 파생 상태는 정정 가능해야 사실과 일치한다.

**기각한 대안** — 만료=종결(불가역 고착), 갱신중→신청제출 재진입(축 혼동), 리드 기본값 발명(추측 구현 — 필요하면 템플릿에 입력이 정공법), 전이별 개별 엔드포인트(27개 API 비대).

**되돌리기 비용** — 높다. 전이 표는 S2-3 매트릭스·기일 엔진·S2-4 대행 협업이 소비하는 계약이다 — 변경은 총수 테스트·GC·DESIGN 명문·이 ADR의 세트 갱신이다.
