# ADR-0054: 전표 채번 — 접두어 QT/PI/SO/PO·행 최초 저장 시 발급·연도는 발급 시각의 KST·doc_number는 전역 UNIQUE

- **상태**: 자율 확정(2026-09-30) — 사후 번복 가능 (S3-1 계획 통합 검토서 §4.2 — A 묶음 A10, B 묶음 B4, 통합 X-01)
- **날짜**: 2026-09-30
- **관련**: DESIGN.md §2 ADR-02·§3(채번 SO-2026-0001)·§17.3·§17.4 / ADR-0032(전역 UNIQUE 선례) / docs/plans/s3-1/design-A.md A10, design-B.md B4, design-integrated.md §1.1 X-01

**맥락** — `SO-2026-0001` 형식(§3)을 4종 전표에 적용해야 하고, 발급 시점·연도 기준·전표 쪽 UNIQUE가 DESIGN에 없다. 현재 채번 서비스(`numbering/service.py`)의 연도는 UTC 기준이고 앱 안 호출부가 0곳이라 지금이 무비용 창구다. §17.4는 멱등 UNIQUE를 부분 인덱스로 규정하는데 자사 발급 번호는 재발급이 금지(§17.3)돼 목적이 정반대다.

**결정** — ① 접두어는 `QT·PI·SO·PO` 4종이고 정본은 `trade_docs.constants`(`DocKind` 4값 ↔ `DOC_PREFIXES` ↔ `doc_number` 형식 CHECK가 3자 일치)이며, 채번 호출은 래퍼 `issue_doc_number` 하나로 하고 `next_document_number` 직접 호출은 kernel 밖 0(AST 스캔)이다. `doc_number_seq.prefix`는 CHECK가 없어 후속 접두어(SH·CI·PL 등)는 마이그레이션 없이 확장된다. ② **발급 시점은 행 최초 저장 시(4종 공통), 같은 트랜잭션, 서비스의 마지막 단계(모든 검증·라인 구성·게이트 후 INSERT 직전)**다: QT=DRAFT 생성 시 / PI·PO=생성(발행) 시 / SO=접수(RECEIVED) 행 생성 시(인테이크 확정 트랜잭션). 롤백 시 카운터도 함께 되돌아가고, 스테이징(인테이크) 행에는 번호를 발급하지 않는다. ③ **연도는 발급 시각의 KST 연도**다(`numbering/service.py`의 `year = to_kst(at or utcnow()).year` 1줄 변경, naive `at`은 `ValueError`로 fail-closed). 소급 입력 시 번호 연도가 증빙일 연도와 다를 수 있으며 이는 정상이다(증빙일은 `doc_date`, 번호는 발급 순서). ④ **`doc_number`는 전역 UNIQUE(부분 인덱스 아님)+형식 CHECK**(`uq_<t>_doc_number`·`ck_<t>_doc_number_format`, 접두어 고정 정규식, `VARCHAR(20)`)이다. §17.4 열거의 "문서번호"는 **외부 유입 멱등의 (partner_id, 바이어 PO번호) 축**을 가리키는 것으로 해석한다(DESIGN §17.3 부기). ⑤ 폐기는 CANCELLED 전이(사유 필수)이며 전표 삭제 경로가 없으므로 발급된 번호는 항상 실재 행으로 남아 **결번 0**이고 취소 번호는 재사용되지 않는다(ADR-0053).

**근거** — §17.3(MAX+1 금지·행 잠금·발급 번호 UNIQUE 이중 안전·취소 번호 재사용 금지)과 §2(시각=UTC 저장·KST 표시)에서 도출된다. 한 규칙으로 4종을 통일하고 `doc_number`를 NOT NULL로 두면 삭제 금지와 함께 결번 0이 구조로 보장된다. 부분 인덱스는 삭제 후 재유입을 허용하려는 장치인데 삭제 경로가 0이고 재발급이 금지이므로, 전역 UNIQUE가 오히려 결번 재사용 구멍(부분 인덱스에서 삭제 후 같은 번호 재유입)을 막는다. 카운터가 단조 증가라 전역 UNIQUE가 정상 흐름을 막을 일이 없다. 문서일자 연도로 채번하면 과거 일자 입력이 지난 해 카운터를 재개방해 발급 순서와 번호가 어긋나고 별도 잠금 규칙이 필요하다. 카운터 행 잠금은 트랜잭션 끝까지 유지되므로 발급을 INSERT 직전으로 미룬다.

**기각한 대안** — 문서일자(`doc_date`) 연도 기준 채번(비단조·기발급 순서 붕괴), 동결(발행) 시 채번(접수 SO가 번호 없이 보드에 뜨고 취소/삭제 이중 경로 발생), 부분 UNIQUE `unique_active(doc_number)`(삭제 경로가 0이라 무의미하고 결번 재사용 구멍), `at`을 doc_date 연도로 넘기는 우회, 접두어 문자열을 서비스 코드에 직접 기재.

**되돌리기 비용** — 낮음(첫 실번호 발급 전 한정). 연도 1줄·CHECK는 저렴하나 **실번호가 발급된 이후에는 KST↔UTC/문서일자 기준 변경이 기발급 번호 체계와 단절돼 사실상 비가역**이다. 발급 시점을 "발행 시"로 바꾸려면 `doc_number` nullable화·CHECK·UNIQUE 재정의가 필요해 중간.

**영향 세션** — S3-1 PR-2(연도 1줄+`test_numbering` 연도 경계 신규)·PR-5~8·13(발급 호출) / S3-2·S3-3(접두어는 `DocKind`/`DOC_PREFIXES` 멤버 추가만) / D(인테이크 확정 트랜잭션에서 SO 번호를 마지막에 발급).
