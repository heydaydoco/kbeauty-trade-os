# ADR-0049: T1 시드는 앱 경로 초안 투입 — 카탈로그 계약·확인일은 사람의 몫·위저드는 계산값·전달 서류 zip은 유실 시 거부

- **상태**: 채택 (S2-4 계획 **자율 확정** — 오너 자율 지시[2026-09-29]에 따라 웹 세션 판정 없이 권장안 확정, 계획 §5 ⑦~⑨. 사후 번복 가능)
- **날짜**: 2026-09-29
- **관련**: DESIGN.md §5.4·§5.5·§17.1·§18.1·§21·§22 / ADR-0033(확정 게이트)·0047(계산값 미저장)·0048(대행 협업) / PROGRESS 조건 12(S2-1 — 템플릿 시드는 마이그레이션 시드 불가) / s2-4-plan.md §2 안건 ④⑤⑥·§5

**맥락** — Phase 2의 남은 공백은 "실제 진출 시장의 요건을 처음부터 손으로 넣어야 한다"와 "전달 서류를 한 묶음으로 만들 수단이 없다"이다. 판단할 것은 셋이다: T1 시드를 어떤 경로로 넣을 것인가(markets·requirement_templates가 ActorMixin[users FK]을 달아 마이그레이션 시드로는 TRUNCATE CASCADE 보존이 무력화된다 — 함정 ⑩), 시드 데이터의 신뢰를 어디까지 시스템이 보증할 것인가(이 세션은 외부 규제 사이트를 검증할 수 없다), 전달 서류 묶음에서 파일이 빠졌을 때 어떻게 할 것인가.

**결정** — ① **앱 경로 투입**: 저장소의 버전 붙은 카탈로그(`backend/app/seeds/t1_requirements.json`)를 사람이 **시장 단위로 선택**해 투입한다(CLI `seed-t1 --market … --actor-email …`·API `GET /seeds/t1`[현황]·`POST /seeds/t1/apply`[멱등 키·인증+관리자]). 시장이 없으면 등록하고, 템플릿은 **항상 초안(DRAFT)·확인일 없음**으로 만들며, 같은 (시장, 이름)이 있으면 **건너뛴다**(사람이 고친·확정한 템플릿을 덮지 않는다). 선행요건은 이번에 만든 템플릿에만 건다. 요청 1건=트랜잭션 1건(시장 여럿도 전부 성공/전부 롤백), 삭제된 시장이 코드를 점유하면 되살리지 않고 안내한다. ② **카탈로그 계약**(로드 시점+CI 테스트): 전 항목 https 근거링크(명시 호스트 허용목록 — 새 호스트는 목록을 함께 고쳐 리뷰에서 사람이 본다)·키·이름 유일·선행 키 실재·비순환·적용단위 열거·`last_verified_on` 필드 부재. **확인일은 사람이 링크를 열어 확인한 뒤 입력하고 기존 3층 확정 게이트로 확정한다** — 시스템은 규제를 단정하지 않는다(§21). 내용은 DESIGN §5.5 T1 문면만 담고 없는 세부는 발명하지 않고 note에 "확인 필요"로 남긴다. ③ **신규 시장 위저드**(`GET /market-wizard/{code}` — 읽기 전용·저장 없음): 5단계(시장·템플릿·HS·협정·성분 규칙)의 상태를 데이터에서 계산한다. 협정(FTA 마스터)·세율 마스터는 Phase 4 몫이라 협정은 "모듈 도래 전"으로 표시하고 **완료 계산에서 제외**한다. ④ **전달 서류 zip**(`GET /certifications/{id}/package`): 인증 소유 문서+태스크가 서류로 연결한 문서(다른 소유 포함 — GMP류 소유 공백 흡수), 통신 기록 첨부는 제외. manifest.csv(BOM)·README·links.txt·`documents/NN_종류_원본명`. 메타 조회는 트랜잭션 안, **파일 IO는 트랜잭션 밖**, `SpooledTemporaryFile` 8MiB, 상한 파일 100건·합계 200MiB(422). **실물 유실·해시 불일치는 조용히 빼지 않고 409+목록으로 거부한다.** 전 역할 열람, 생성 이력은 남기지 않는다(관찰 등재).

**근거** — ① 마이그레이션 시드는 함정 ⑩으로 불가하고, 앱 경로는 감사 컬럼(투입자)이 정상이며 사람이 진출 시장만 고르므로 "시드 투입은 진출 시장분만"(§5.5)과 맞는다. 덮어쓰지 않는 멱등이 사람의 편집을 지킨다. ② 확인일을 시스템이 채우면 검증하지 않은 링크가 "확인됨"으로 보이는 거짓이 되어 확정 게이트가 형식이 된다 — 그래서 카탈로그에 확인일 필드 자체를 두지 않는다. ③ 미도래 단계를 미완으로 세면 위저드가 영영 끝나지 않는다. 위저드는 체크리스트+딥링크라 저장할 상태가 없다(계산값 계보 — ADR-0047). ④ 빠진 채 나간 전달본은 받는 쪽(기관·대행사)이 서류 누락으로 반려하거나 더 나쁘게 누락을 모른 채 진행하는 사고라, 시끄럽게 실패하는 편이 안전하다. 파일 IO를 트랜잭션 밖에 두는 것은 §17.1(idle_in_tx 60s)이다.

**기각한 대안** — 마이그레이션 시드(함정 ⑩), 카탈로그에 확인일 기재(거짓 확인), 전 시장 일괄 자동 투입(진출하지 않는 시장 오염), 같은 이름 덮어쓰기·갱신(사람의 편집 소실), 위저드 진행 상태 저장(이중 진실), 유실 파일을 빼고 생성+경고(빠진 채 발송 위험), 트랜잭션 안에서 zip 생성(idle_in_tx), 통신 기록 첨부 포함(전달 서류가 아님).

**되돌리기 비용** — 낮음. 스키마 변경 0(마이그레이션 없음). 카탈로그는 데이터 파일 하나이고 투입된 행은 일반 초안 템플릿이라 기존 삭제·편집 경로로 정리한다. 위저드·zip은 읽기 전용이다.
