# ADR-0030: 왕복 임포트는 ID 키 diff와 원자적 확정으로 동작한다

- **상태**: 채택 (S1-3 계획 승인 문면의 구현 확정 — 2026-08-06)
- **날짜**: 2026-08-06
- **관련**: DESIGN.md §12.2·§15·§17.2·§17.4 / §2 ADR-09 / ADR-0027 / WBS S1-3 / PROGRESS 부채 #17

**맥락** — §12.2 왕복 편집(목록 다운로드→오프라인 수정→업로드→diff 스테이징→확정)에는 행 식별 키, 내보내기·양식의 관계, 충돌 처리, 확정 단위의 구현 확정이 필요했다. diff 4분류(빈 ID=신규/ID 있는 행=변경분만/파일에 없는 행=무시/ID 훼손=오류)는 웹 세션 승인 문면이다.

**결정** — ① 왕복 CSV 1열은 **ID**이고, 표준 양식과 목록 내보내기는 임포트 레지스트리의 한 헤더 상수를 공유한다(자재 기본공급사는 거래처 **코드** 열 — 표시명은 유일키가 아니라 왕복 결정성이 없다). ② 스테이징은 행마다 대상 version을 기록하고, 확정은 전 행 대조 후 하나라도 어긋나면 **전체 409**(부분 반영 없음). ③ 같은 파일(sha256)은 검토 대기(PENDING) 중 한 번만 — 부분 유니크를 PENDING·미삭제로 좁혀 확정 후 재업로드는 diff 0으로 수렴시킨다. ④ 확정은 사람 1클릭 + idempotency key뿐(§15 L2) — 마스터는 ADR-09 자동 확정 예외 범위 밖.

**근거** — ID 키는 코드(자연키) 수정 자체를 diff로 표현할 수 있고, 원자적 확정은 "사람이 검토한 것만 반영된다"를 지킨다. 값 파싱·검증은 등록 API의 함수(문구 포함)를 재사용해 두 경로가 갈라질 자리를 없앴다.

**기각한 대안** — 자연키(코드) 기반 diff(코드 수정 표현 불가·리네임=삭제+신규 오검출), 행 단위 부분 확정(검토-반영 불일치), mapping_templates 자유 매핑(승인 범위 밖 — 표준 양식 고정이 §12.2 "표준 양식=스키마 문서"와 부합, 필요 시 후속 재판정).

**되돌리기 비용** — diff 의미를 바꾸면 파서·레지스트리·F 그룹 테스트가 같이 움직인다. 저장되는 것은 스테이징뿐이라 마스터 데이터는 무변이고, 스테이징은 soft delete로 파기 가능하다.
