# ADR-0055: 결제조건·Incoterms·환율 규약 — 구조화 열거·선수금은 bp 정수와 함수·환율은 헤더 스냅샷만(fx_rates 마스터 미신설)·비교 불가는 None이며 통과가 아니다

- **상태**: 자율 확정(2026-09-30) — 사후 번복 가능 (S3-1 계획 통합 검토서 §4.2 — A 묶음 A5·A6·A7)
- **날짜**: 2026-09-30
- **관련**: DESIGN.md §2 ADR-02·§3 표 맵(`fx_rates`)·§7.1·§7.3·§7.5·§7.10·§12 ADR-06 / ADR-0048("환율 축이 없어 환산은 추측이다") / docs/plans/s3-1/design-A.md A5·A6·A7

**맥락** — S3-2 대금만기 계산과 선적 서류가 소비할 결제유형·기산점·일수·Incoterms를 지금 열거로 완결하지 않으면 S3-2가 CHECK를 재정의해야 한다. DoD "확정 후 환율 불변"의 대상(저장 위치·방향·정밀도)도 정해야 하는데, `fx_rates`는 §3 표 맵에 있으나 WBS 배정·코드가 0건이다.

**결정** — ① **결제조건은 구조화 4열**(QT·PI·SO·PO 동일 형태, 자유 텍스트 열·거래처 기본값 열 없음): `payment_type ∈ {TT_ADVANCE, TT_DEFERRED, LC}`('기타' 없음 — 신규 유형은 CHECK 마이그레이션+ADR로만), `advance_pct_bp`(basis point 정수, 1%=100), `balance_anchor ∈ {ORDER_DATE, INVOICE_DATE, ETD_DATE, BL_DATE, ARRIVAL_DATE, RECEIPT_DATE}`(RECEIPT_DATE는 PO 전용 — 판매 체인에서 선택하면 422), `balance_days`(−90..365, **음수는 ETD_DATE에서만**). 형태 CHECK `payment_terms_shape`가 행 단위로 조합을 묶는다(4열 전부 NULL[동결 전 초안] / TT_ADVANCE는 1..10000bp이고 100%면 앵커·일수 NULL, 미만이면 NOT NULL / TT_DEFERRED는 선수금 NULL·앵커·일수 NOT NULL / LC는 셋 다 NULL). API는 **퍼센트 문자열**(소수 2자리까지, 초과 422·반올림 없음)로 받고 서버가 bp로 변환하며 응답에 `advance_pct`(문자열)와 `advance_pct_bp`를 병기해 프런트 산술을 0으로 둔다. ② **선수금은 저장하지 않고 함수** `split_advance(total, advance_pct_bp) -> (advance, balance)`: 선수금 `=(total*bp+5000)//10000`(파이썬 정수·HALF_UP), **잔금=총액−선수금**(합 일치 보장), SQL에서 곱하지 않는다. ③ **L/C**: DB CHECK는 항상 LC를 허용하고, 서비스가 `payment_type`에 'LC'를 **새로 입력**(생성·편집)할 때만 `is_feature_enabled('lc')`(**행 없음·꺼짐·조회 실패=꺼짐, fail-closed**)를 검사해 422 `PAYMENT.LC_DISABLED`를 낸다. 참조 복사로 상속되는 LC와 동결·조회·진행은 검사하지 않는다. 현재 코드에 플래그 행을 만드는 경로가 없으므로 **S3-1 프로덕션에서 L/C 선택은 닫혀 있고**, 토글 경로는 S3-3(`lc_terms`)으로 인계한다. ④ **Incoterms는 4헤더 3열**: `incoterm_code`(EXW·FCA·FAS·FOB·CFR·CIF·CPT·CIP·DAP·DPU·DDP·DAT 12코드)·`incoterm_year ∈ {2010, 2020}`·`incoterm_place`(VARCHAR(100), 공백 불가)이며 **셋 다 NULL이거나 셋 다 NOT NULL**(`incoterm_all_or_none`), 교차 CHECK로 DAT는 2010만·DPU는 2020만 허용하고 동결 시 `incoterm_code` NOT NULL이다. 완전성 검증 본체는 S3-3. ⑤ **환율은 헤더 스냅샷만**: 전표 통화는 헤더 단일(라인은 복합 FK로 일치), `fx_rate NUMERIC(18,8)`(**"전표 통화 1단위 = x KRW" 한 방향만 저장**)·`fx_rate_date DATE`이고, 수동 입력(비KRW 동결 시 필수, `Decimal` 문자열 입출력·float 금지), KRW는 서버가 `fx_rate=1`·`fx_rate_date=doc_date`를 채우며(CHECK와 일치) `fx_rate_date<=doc_date`·상한 1,000,000이다. 신선도(stale) 서버 규칙은 두지 않고(참조 생성이 원천 환율을 복사하므로 수 주 지난 값이 정상) 화면이 `fx_rate_age_days`를 파생 표시한다. **`fx_rates` 마스터는 S3-1에서 신설하지 않는다**(WBS v1.5에 "소유 세션 미배정 — 재판정 트리거: 환율 자동 수집 도입[§15 L3] 또는 S6-2 착수 또는 환율 입력 오류 사고" 등재). ⑥ **환산·비교는 함수이며 저장하지 않는다**: `to_krw(amount_minor, currency, fx_rate)`(`Money.from_decimal` HALF_UP 단일)와 `comparable_amount(amount, doc_currency, fx_rate, target_currency) -> int | None` — 같은 통화면 원액, 목표가 KRW이고 환율이 있으면 `to_krw`, **그 외는 `None`=비교 불가**이며 **`None`은 통과가 아니다**(여신 게이트·결재 임계는 승인 게이트로 보내거나 평가 불능으로 확정을 거부하고 사유 코드를 남긴다). 임의 역환산·제3통화 환산은 하지 않는다. 여신·승인 판정 결과에는 `(doc_id, currency, total, fx_rate, fx_rate_date, 비교 결과/None 사유)`를 값으로 남긴다.

**근거** — §7.1이 결제조건을 "구조화(기산점+일수) — 자유 텍스트 금지"로, §7.5가 T/T=약정 기산점 / L/C=네고·인수 분기와 "환율 고정"을 요구한다(설계 A5·A7). 프런트는 `\w\s*[/*]\s*100\b` 산술 가드가 있어 퍼센트를 문자열로 주고받아야 한다. `fx_rates` 마스터의 소비자는 (i) 확정 후 불변(스냅샷으로 충족) (ii) 승인 임계·여신·보드의 KRW 환산뿐이고, 환율 수집·이력·출처 정책은 §15 L3·ADR-06 2단계·S6-2 소관이라 지금 세우면 그 정책을 조기 확정하며 충돌할 수 있다. 마스터 등록을 TRADE에 열어도 임의 환율로 여신·결재 임계를 우회하는 우려를 닫지 못하므로(ADMIN 전용은 주 1회 이상 갱신 운영 부담), 환율 입력·변경을 audit로 남기고 증빙에 사용 환율·기준일을 값으로 싣는 fail-visible 계약으로 다루고 마스터 도입은 재판정 트리거로 이월했다(ADR-0048 "환산은 추측이다"와 같은 판단). L/C를 fail-closed로 둔 것은 DB가 플래그에 종속되지 않게 하면서 진행 중 거래가 갇히지 않게 하는 가장 좁은 규칙이다.

**기각한 대안** — `payment_type`에 OTHER(계산 의미 없는 죽은 값·자유 텍스트 우회 입구), 선수금 %를 소수·실수로 저장·전송(프런트 산술 가드), 선수금 금액 열 저장(파생값 이중 저장·청구서와 게이트 요구액 어긋남), 잔금을 별도 반올림(합 불일치), 동결 시 L/C 재검사·복사 시 차단(진행 중 거래 갇힘), `incoterm_year`를 2020 상수열로(§7.5가 연도를 데이터로 요구), `fx_rates` 마스터 신설(소비자 없음·S6-2 정책 선점), 환율 신선도 서버 규칙(참조 복사 값이 정상적으로 오래됨), 통화 불일치 무조건 UNEVALUABLE(수출 대부분이 USD라 게이트 무용 — 대신 `comparable_amount`가 KRW 목표만 환산), `None`을 0으로 대체.

**되돌리기 비용** — 중간. 열거 추가는 CHECK 재정의 1건(선례 있음)이지만 삭제·의미 변경은 S3-2 소비 후 비싸 지금 6앵커를 확정한다. 마스터 신설·`fx_rate_source` 열은 additive라 전표 컬럼은 불변이다. **환율의 방향·정밀도를 바꾸는 것은 전 전표 값 변환+소비 코드 수정으로 비싸다.**

**영향 세션** — S3-2(대금만기=앵커+일수 계산·환율 고정=SO 스냅샷 복사·선적이 Incoterms 3열 복사) / S3-3(`lc_terms`·L/C 플래그 토글 경로·Incoterms 완전성 검증) / S3-4(부담자 기본값) / S6-2(환노출·`fx_rates` 재판정) / E(여신·PI 게이트가 `split_advance`·`comparable_amount` 사용) / C(결재 임계는 같은 통화만 비교).

**부기(2026-10-04 — S3-2 계획)** — (자율 확정 — 사후 번복 가능. 위 원문 결정은 고치지 않는다.) **"휴일 보정"의 해석과 선적 사본**: ① 위 영향 세션의 대금만기 계산은 `trade_docs/schedule.py` 순수 함수(결제유형 분기·`balance_anchor` 6종 — 앵커 미확정·INVOICE_DATE = UNKNOWN, 수입 ORDER_DATE = PO `frozen_at` KST 날짜)로 이행한다. ② S3-1 계획 부록의 "휴일 보정은 S3-2"는 **경고만**(자동 순연 0 — DESIGN §7.5 문면 '경고')으로 해석한다 — 휴일과 겹친 만기 값은 불변이다. ③ 환율 고정·Incoterms 3열은 선적 헤더가 원천 스냅샷을 복사한다(`fx_rates` 미신설 유지 — P-22). ④ L/C 산식은 순수 함수만, 운영 경로 UNKNOWN(`lc_terms`·플래그 공급은 S3-3). 근거: ADR-0080·0081·0082.

**부기(2026-10-05 — S3-3 계획)** — (자율 확정 — 사후 번복 가능. 위 원문 결정은 고치지 않는다.) **S3-3 이행(적대 R-34)**: 영향 세션란의 'S3-3(`lc_terms`·L/C 플래그 토글·Incoterms 완전성)'을 이행한다 — ① `lc_terms`·제시 기록·하자 체크 마크(ADR-0094, PR-4a) ② L/C 플래그 토글 `PUT /feature-flags/{code}`(ADMIN·폐쇄 레지스트리 `{"lc"}`·시드 0 — OFF = 새 입력만 닫음, P-10 종결) ③ **Incoterms 완전성 = 서류 저장 전 검증 V-항목**(`incoterms.py`에 `incoterms_completeness` 가산 — 3열 형식 검증 위에 장소 공백 BLOCK·해상 전용 코드 + 비해상 모드 NOTICE, ADR-0093·0095, PR-5a). 결제조건 4열·Incoterms 3열·환율 스냅샷 규약은 그대로이며, 대금만기 INVOICE_DATE 앵커 원천은 채권 `invoice_on`(ADR-0088).
