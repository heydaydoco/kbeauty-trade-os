# ADR-0039: 만료임박 "배치" = 날짜 스윕 함수 + CLI 수동 실행 (scheduled_jobs 비접촉)

- **상태**: 채택 (S2-2 계획 웹 세션 판정 2026-08-11 — 안건 ⑦, WBS "배치" 해석 고정)
- **날짜**: 2026-08-11
- **관련**: DESIGN.md §5.2(자동 부여)·§15(스케줄 레지스트리)·§17.2·§17.6 / WBS S2-2 DoD / PROGRESS 부채 #12(실행기 전 행 삽입 금지 — 위반 반려) / GC-C10

**맥락** — WBS S2-2 DoD "만료임박 날짜 조건 자동 부여 **배치**"와 부채 #12(scheduled_jobs 행 삽입 금지 — 실행기=S2-3)가 교차한다. DESIGN §5.2는 "자동 부여"만 명시하고 수단 "배치"는 WBS 표현이다(DESIGN 우선).

**결정** — 배치의 충족 형태=일괄 처리 함수(sweep_date_transitions)의 실재+C 그룹 직접 호출 검증. 실행 수단은 CLI `certification-sweep`(기준일 인자, 기본=KST 오늘) 수동 호출뿐이고, scheduled_jobs 등록·스케줄은 S2-3 실행기가 추가한다(등록만 — 함수 재작성 없음. §15 "모든 배치를 scheduled_jobs로" 충족 시점도 그때). 함수 계약: 건별 독립 트랜잭션(§17.6 — 한 건 실패가 스윕을 안 막음)·행 잠금 후 상태 재확인(§17.2 — 사람 전이와 직렬화)·멱등(재실행 변화 0)·전이 서비스 경유(상태 대입 단일 통로)·무기한 비대상.

**근거** — 함수와 스케줄을 분리하면 검증은 지금, 등록은 실행기 세션에서 — 부채 #12를 안 밟고 DoD를 충족한다.

**기각한 대안** — scheduled_jobs 선등록(부채 #12 위반=반려), 조회 시점 계산만(저장 상태와 달력의 불일치가 남는다 — 조건 A의 즉시 수렴과 상충), 스윕 전체 단일 트랜잭션(한 건 실패가 전체를 되돌린다 — §17.6 위반).

**되돌리기 비용** — 낮다. S2-3이 레지스트리 등록 한 줄을 더하는 구조이고, 함수 계약은 그대로다.
