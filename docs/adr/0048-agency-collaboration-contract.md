# ADR-0048: 대행 협업 계약 — 처리방식·공 주체는 편집 필드·comm_logs 폴리모픽·정체 N일은 데이터+몫 dedup·스코어카드는 계산값·비용은 현행 계약 표시

- **상태**: 채택 (S2-4 계획 **자율 확정** — 오너 자율 지시[2026-09-29]에 따라 웹 세션 판정 없이 권장안 확정, 계획 §5 ①~⑥·⑫. 사후 번복 가능)
- **날짜**: 2026-09-29
- **관련**: DESIGN.md §5.4·§5.2·§2 ADR-07·ADR-11·§17·§18.4·§21·§22 / ADR-0028(폴리모픽 소유 열거)·0037(인스턴스 그릇 — "인스턴스 비용 컬럼 0")·0041(문서 소유 확장 규율)·0045(알림 라우팅)·0046(기일 엔진 — 알림 코어 직접 호출)·0047(계산값 미저장) / s2-4-plan.md §0-2 ④·§2 안건 ①②③⑪·§5

**맥락** — 인증 인스턴스·상태머신·기일 알림(S2-1~3)이 서서 "무엇이 언제 만료되나"는 시스템이 안다. 남은 공백은 **일이 사람 사이에 멈추는 것**이다 — 대행사에 맡긴 건이 누구 손에서 며칠째 멈췄는지, 무엇을 주고받았는지, 다음에 무엇을 해야 하는지가 시스템 밖(메일·메신저)에 있다(§5.4). 판단할 것은 여섯이다: 처리방식·공 주체를 상태로 볼 것인가 필드로 볼 것인가, 통신 기록의 주제를 어떻게 담을 것인가, "정체"를 무엇으로 정의할 것인가, 독촉을 몇 번 어떤 키로 낼 것인가, 스코어카드를 저장할 것인가, 스코어카드의 "비용"을 무엇으로 채울 것인가(S2-2 판정 "인스턴스 비용 컬럼 0"과 §5.4 "비용"이 부딪힌다).

**결정** — ① **처리방식(DIRECT|AGENCY)·현재 액션 주체(INTERNAL|AGENCY|AUTHORITY)·공이 넘어간 날·대행사 지정은 인증의 편집 필드다**(상태가 아니다) — PATCH(version)로 바꾸고 §5.2 전이 표 27전이는 건드리지 않는다. CHECK: **AGENCY ⇔ 대행사 지정(양방향)·공이 대행사이면 대행 처리**. 서비스가 적용 후 조합을 먼저 판정해 필드별 422로 안내하고, 주체가 바뀌면 공이 넘어간 날을 오늘(KST)로 기록하며 명시한 날짜(소급)가 이긴다. ② **`comm_logs`는 폴리모픽**(주제 유형 CHECK — 소비분 CERTIFICATION 1종, FK 없이 서비스가 실재 검증)이고 첨부는 documents 소유 열거 `COMM_LOG`(CHECK 수기 재정의)다. 대행 계약(`agency_contracts`)은 상태 컬럼이 없다 — 유효 여부는 오늘 기준 계산값이다. ③ **정체 = 공이 어딘가에 있는 진행 중 5태(서류준비·신청제출·심사중·보완요청·갱신중)에서 "공 이동·상태 변경·통신 기록·다음 액션 완료가 모두 N일 없음"** — N은 공 주체별 데이터(`alert_rules.config.days`, 기본 사내 7·대행사 7·기관 30). ④ **독촉은 N일마다 1건**: dedup 키 `stagnation:certifications:{id}:{주체}@{마지막 활동일}#{k}`(k=정체일÷N) — 지난 몫을 소급하지 않고, 활동이 생기면 새 에피소드. 다음 액션은 기한 당일 DUE·도과 후 OVERDUE 각 1건. 알림 생성 코어를 직접 부른다(아웃박스 비경유 — ADR-0046 계보), 발송은 없다. ⑤ **스코어카드는 저장하지 않는다**(집계 테이블·컬럼 0 — 아키텍처 테스트가 소스 스캔으로 고정, 질의 수는 대행사 수와 무관). ⑥ **스코어카드 "비용" = 그 대행사의 현행 계약 수수료를 계약에 적힌 그대로 표시**(합산·환산 없음) — 인증 실비 컬럼은 도입하지 않는다.

**근거** — ① 상태로 보면 §5.2의 27전이 표·3층 차단·상태 대입 단일 통로가 전부 흔들리고, 사실은 상태가 아니라 "지금 공이 누구에게 있나"라는 주석에 가깝다(대행 여부·기관 대기 여부는 사실이 아니라 사람의 판단이라 상태 변경으로 자동 추정하면 추측이 된다). 양방향 CHECK는 스코어카드 귀속이 모호한 행("대행인데 누구인지 모름")을 DB가 막는다. ② 통신 기록은 인증뿐 아니라 포워더·관세사에도 같은 패턴이 적용되므로(§5.4·§7.9) 주제를 폴리모픽으로 두되, **검증할 수 없는 값을 미리 넣지 않는다**는 ADR-0028·0041 규율에 따라 소비분 1종만 CHECK에 둔다. ③ 정체를 "공 이동일 이후 N일"로만 정의하면 독촉 메일을 보낸 사람의 기록이 시계를 되돌리지 못해 같은 건에 알림이 계속 쏟아진다 — 통신 기록·상태 변경을 활동으로 세야 "아무도 손대지 않은 건"만 남는다. 미착수를 뺀 이유는 §4.8 자동 적용이 대량의 미착수를 만들 수 있어 정체 알림이 소음이 되기 때문이고(그 신호는 매트릭스 🔴가 맡는다), 승인계는 기일 엔진이 맡는다. N을 데이터로 둔 것은 ADR-11(기일 문턱 선례)이고 기관 30일은 기관 회신의 실제 속도 때문이다. ④ 한 번만 알리면 30일 정체한 건이 첫 알림 뒤 침묵하고, 매일 알리면 소음이라 N일 주기가 중간이다 — 몫 k를 키에 넣으면 스캔 지각에도 그 시점 몫 1건만 생겨 멱등이 유지된다(과거 몫 소급은 정보가 아니라 소음 — 기일 스캔의 도과 소급 금지와 같은 판단). ⑤ 저장하면 정정·자정 뒤에 거짓이 되고(매트릭스와 같은 사유), 원료(상태 이력·인증·계약)가 이미 불변·정본이라 저장할 이유가 없다. ⑥ S2-2가 "실비=S3-4 원장·인스턴스 비용 컬럼 0·중복 보관 금지"로 못박았고, 실비 컬럼을 지금 도입하면 원장 도래 후 이중 진실이 된다. 계약 수수료는 이번 세션이 새로 만드는 데이터라 충돌이 없고, 합산·환산을 하지 않는 이유는 계약마다 기준(건당·정액)이 달라 합이 의미가 없고 환율 축이 없어 환산은 추측이기 때문이다.

**기각한 대안** — 처리방식·공 주체를 상태머신에 편입(전이 표·차단 3층 전면 개편·자동 추정은 추측), 통신 기록을 인증 전용 테이블로(포워더·관세사 재사용 시 폴리모픽 재설계), 주제 열거를 미리 넓힘(검증 불가 값), 정체를 공 이동일만으로 정의(독촉 행위가 시계를 못 되돌림), 미착수 포함(자동 적용 소음)·승인계 포함(기일 엔진과 중복), 일 1회 반복 독촉(소음)·에피소드당 1회(장기 정체 침묵), 스코어카드를 배치로 저장(정정 반영 지연·거짓 잔존), 인증 실비 컬럼 신설(S2-2 판정 번복·원장과 이중 진실), 계약 수수료 합산·환산(의미 없는 합·추측 환율), 스코어카드에 대행사 교체 이력 반영(이력 테이블이 별도로 필요 — 관찰 등재).

**되돌리기 비용** — 낮음~중간. 컬럼 4·테이블 2·CHECK 재정의는 마이그레이션 1건(downgrade 완결 — 대행 협업 데이터는 소실)이고, 정체 정의·N 기본값·독촉 키 형식은 한 파일의 상수·함수다(키 형식을 바꾸면 1회 중복 알림을 감수). 스코어카드 정의(소요일·보완율·귀속)는 계산 코드 한 곳이라 바꿔도 데이터 이관이 없다. 실비 컬럼은 나중에 추가하는 방향이 비용이 낮다(컬럼 추가 마이그레이션 1건 — S3-4 원장 설계와 함께 판정).

**부기(2026-09-29 PR-1 적대 검증 반영 — 결정 불변, 경계 명문화)** — ① 통신 기록 첨부는 문서 보관소 권한(무역+인증)을 따라 본문 편집(인증)보다 넓다 — 인증 인스턴스 소유 문서와 같은 권한 계보라 소유 유형별 분기를 새로 만들지 않는다(테스트로 고정). ② 첨부가 남은 통신 기록의 삭제는 409로 막는다(DOCUMENTS.LINKED_TO_TASK의 '선해제 후 삭제' 계보 — 보존기한 잠금을 우회하는 연쇄 삭제는 하지 않는다). ③ 정체 몫 k는 규칙으로 N을 바꾸면 새로 시작(1회 추가 알림 감수)하고, 과거 날짜 통신 기록은 발생일로 시계를 판단하므로 정체를 소급 해소하지 않으며, 마지막 활동 기록을 삭제하면 dedup 키가 바뀌어 1회 재알림될 수 있다. ④ 스코어카드에서 소프트 삭제된 거래처의 실적은 제외된다(거래처 삭제 경로가 없어 현재 도달 불가). ⑤ 계획서 §2 문면과 DESIGN·코드가 다른 곳(마지막 활동일 원천에 '다음 액션 완료일' 추가·CHECK `agency_owner_requires_agency` 추가·담당자 편집 UI 비포함·dedup 키 복수형)은 **DESIGN이 정본**이다.
