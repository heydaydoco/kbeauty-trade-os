# ADR-0056: 스냅샷·마스터 보강 — 전표는 값 복사 스냅샷·partners 2열/bank_accounts/skus.moq 신설·단가는 반올림 없이 거부·서브 미니멈 단가는 한계로 명시

- **상태**: 자율 확정(2026-09-30) — 사후 번복 가능 (S3-1 계획 통합 검토서 §4.2 — A 묶음 A8·A9·A11, 통합 X-02·X-44)
- **날짜**: 2026-09-30
- **관련**: DESIGN.md §3 "거래 시점 값 스냅샷 복사"·§4.1·§4.6·§7.3·§18.1 / ADR-0008(로그 마스킹)·0017(그때 단가)·0018·05 / docs/plans/s3-1/design-A.md A8·A9·A11, design-integrated.md §2.1(b)·§2.2

**맥락** — "거래 시점 값 스냅샷 복사"의 범위·시점·원천을 확정해야 하고, QT·PI 서류가 필요로 하는 값(거래처 영문명·주소, 자사 은행 계좌, SKU MOQ)의 원천이 마스터에 없다. 단가 입력·자릿수·무상 규칙과 SKU 상태(SET·단종)도 DESIGN이 침묵한다.

**결정** — ① **스냅샷 규약**: 전표(헤더·라인)는 값 복사 열이고 원천 마스터 FK는 식별·추적용으로만 남기며 조회·렌더링은 스냅샷 열만 읽는다. 마스터에서 직접 만드는 경로(QT 라인 추가·직접 SO/PO 라인·PI 은행)는 **생성(추가) 시점에 1회 복사**하고, 초안 편집 창에서는 사용자의 명시 편집·거래처 변경으로만 값이 바뀌며(자동 갱신 없음), **참조 생성(PI·SO)은 선행 전표 값을 그대로 복사하고 마스터를 다시 읽지 않는다**. 라인 스냅샷은 `snapshot_line_from_master`·`snapshot_line_from_source` 두 함수만 만든다(`sku_code·sku_name_ko·sku_name_en·sku_kind·buyer_item_code·unit_price_amount·list_price_amount·currency·price_basis`). `buyer_item_code`는 활성 매핑이 정확히 1건이면 그 값, 0건이면 NULL, 2건 이상이면 사용자가 지정(미지정=NULL — 추측 선택 금지). SET SKU는 세트 그대로 1라인이고 구성품 전개는 하지 않는다(S4-2). ② **마스터 보강 3건(마이그레이션 M01·M03~M04)**: `partners.name_en VARCHAR(200) NULL`·`address_en VARCHAR(500) NULL`(country 열은 만들지 않음), **`bank_accounts`**(label·통화·수취인·은행·계좌번호·SWIFT 전부 NOT NULL, **쓰기 ADMIN 전용·조회 ADMIN·TRADE**, 초기 행은 화면/API로만·시드 금지, `account_no`는 어떤 유니크 키에도 넣지 않고 중복은 서비스가 (정규화 계좌번호, SWIFT)로 409), **`skus.moq INT NULL CHECK (moq IS NULL OR moq > 0)`**(단위 EA, NULL=MOQ 미정의, 바이어별·구간별 MOQ는 없음). 세 변경 모두 DESIGN §4.1·§4.6 보강+CSV 왕복 어댑터(열 끝 추가·열 부재 허용)+왕복 diff 테스트가 한 세트이며, S3-1이 수정하는 `PartnerCreateRequest`·`SkuCreateRequest`는 **PR-3에서 `extra=forbid`로 전환**한다(통합 X-44: 기존 스키마가 forbid가 아니었다). ③ **PI 은행**: PI 생성 시 `bank_account_id` 필수이며 계좌 통화=PI 통화일 때만 허용하고 은행 6열을 값 복사한다(마스터를 이후 수정·비활성해도 발행 PI 불변). QT·PI 동결은 `buyer_name`·`buyer_address` 비공백을, PI는 추가로 은행 6열 전부를, SO 확정은 `buyer_name`을 요구한다. **자사 레터헤드는 S3-1 스냅샷 대상이 아니다**(S3-3 이월). ④ **로그 마스킹**: `redaction.SENSITIVE_SUFFIXES`에 `_account_no`·`_account_number`를 추가하고(`bank_account_no`가 자동 마스킹되지 않는 것을 실측) audit·이벤트·알림에는 계좌번호를 싣지 않는다. 은행정보는 원가·마진이 아니므로 역할 마스킹 비대상이다. ⑤ **단가 규칙**: 기본 단가=`price_at(price_type="SALES", currency, on=doc_date)`(부재는 `CATALOG.PRICE.NOT_EFFECTIVE` 422를 그대로 전파, 0·NULL 대체 금지), 같은 값을 **`list_price_amount`에 스냅샷**(단가 편차 게이트가 확정 시점에 mutable한 `sku_prices`를 다시 읽지 않고 "당시 기준가"를 재현), 다수 라인용 벌크 `catalog.pricing.prices_at`을 신설한다. 수동 입력은 허용하되 사유를 요구하지 않고 `price_basis='MANUAL'`(인테이크 추출 단가는 `BUYER_PO`), **통화 최소단위 자릿수 초과는 반올림 없이 422**(공용 `core/money.py::parse_minor_amount`), 마스터 판가가 0이면 자동 수용하지 않고 422다. **0원은 명시 무상(`is_free`+`price_reason` 필수, 마스터 자동 무상 없음)**이고 QT·PI·SO 라인만 허용, PO는 단가>0, PI는 서비스가 `total_amount>0`을 요구한다. 라인금액은 `quantity::numeric*unit_price_amount`(오버플로 500 방지)로 CHECK하고 헤더 합계는 `recompute_total()`에서만 대입한다. ⑥ **SKU 라인 규칙**: 단종·삭제 SKU는 QT·PO 신규 라인에서 즉시 차단(단일 통로 `require_sellable_sku`), PI 생성은 해당 SKU를 열거해 사용자가 제외하게 하며, SO 접수는 저장을 허용하되 표시하고 **SO 확정에서 재검사해 차단**한다. 수량은 EA 정수만이고, 같은 전표에서 `(sku_id, is_free)` 유일이다(유상 1줄+무상 1줄까지, 분할 납기 미지원). ⑦ **서브 미니멈 단가(USD 0.125 등)는 지원하지 않는 한계**이며 재판정 트리거는 실데이터에서 소수 단가가 발생할 때다.

**근거** — ADR-0017은 "이력과 스냅샷은 값 복사"라고 하며 `sku_prices`가 MUTABLE이라 과거 `price_at`이 재현되지 않으므로 전표 라인이 진실이어야 한다. QT·PI 서류 필수값이 마스터에 없어 전표마다 손으로 입력하면 ADR-05 "재입력 화면 금지" 정신을 어긴다(마스터 확장은 nullable additive라 저렴하다). 자릿수 초과 반올림 금지는 `partners.parse_credit_limit`의 거부 선례와 같은 규칙이며, `pricing._to_money`의 조용한 반올림은 전표에 쓰지 않는다. `list_price_amount`는 나중에 추가하면 백필이 불가능해 지금 둔다. 단종 SKU 규칙은 DESIGN 침묵 구간의 "가장 좁은 안전한 결정"이다(바이어가 실제로 보낸 PO를 시스템이 접수 단계에서 거부하지는 않되 확정은 마스터 상태를 되돌리는 가시적 조치 뒤에만).

**기각한 대안** — "마스터 대비 변경됨" 배지·수동 새로고침 액션(복잡도 대비 근거 없음, 관찰 등재), 자사 레터헤드·country 열의 지금 도입, 수동 단가 사유 필수(협상 문서라 정상 업무를 막음), 자릿수 초과 반올림, 마스터 판가 0을 자동 무상으로 수용, `bank_account_no`를 유니크 키에 포함(`test_secret_boundaries` 실패), 바이어별·구간별 MOQ 테이블(문면 근거 없음), SET 구성품 전개·구성 스냅샷(S4-2 착수 시 재판정), 동일 SKU 다중 유상 라인·분할 납기(부분선적으로 대체), `pricing._to_money`를 전표에 재사용.

**되돌리기 비용** — 중간. partners 2열·`skus.moq`는 nullable additive라 삭제가 저렴하나 CSV 어댑터·화면 되돌림이 따르고, `bank_accounts` 대체는 마이그레이션+PI FK 이관이 필요하며, 전표 스냅샷 열은 소비 시작 후 삭제가 비싸다. 반올림 허용 전환은 서비스 1곳(낮음)이나 서브 미니멈 단가 지원은 전 금액 의미 변경이라 매우 비싸다 — 그래서 한계로 명시한다.

**영향 세션** — S3-1 PR-3(마스터 보강)·PR-5~8 / S3-3(서류 렌더링이 스냅샷·레터헤드 자산을 소비) / S4-2(SET 구성 변경 드리프트 재판정) / D(인테이크가 `parse_minor_amount`·`prices_at`·`skus.moq`를 소비) / E(0원 선수금 처리).
