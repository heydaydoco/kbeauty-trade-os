# ADR-0044: 배치 실행기 계약 — 폐쇄 열거 매핑·schedule 2형·미스파이어 1회·크래시 정리

- **상태**: 채택 (S2-3 계획 웹 세션 판정 2026-08-12 — 안건 ⑤·판정 요청 13·14·15·조건 F, PR-1 실장)
- **날짜**: 2026-08-12
- **관련**: DESIGN.md §15·§17.6·§2 운영 품질 / ADR-0039(스윕 — "등록만" 예약분의 종착)·0043(디스패처) / PROGRESS 부채 #12

**맥락** — scheduled_jobs는 S0-2부터 빈 테이블이었고(행 삽입 금지 — 부채 #12), ADR-0039가 "S2-3 실행기가 등록만 추가한다"를 예약해 두었다. 실행기를 세울 때의 판단은 넷이다: 코드-함수 매핑 방식, schedule 문법, 미스파이어 의미론, 비정상 종료 처리.

**결정** — ① **코드→함수 매핑은 코드 고정 폐쇄 열거**(`JOB_REGISTRY`)다. 등록되지 않은 code는 실행 거부 + 실패 기록이며, 아키텍처 테스트가 마이그레이션 시드 0건·쓰기 경로 한정을 고정한다. ② **schedule은 폐쇄 2형**이다 — `daily@HH:MM`(KST 기준 매일 1회) · `interval@N`(N분 주기, N≥1). cron 표현식과 파서 의존성을 들이지 않는다. ③ **미스파이어는 1회로 수렴**한다 — 다운 중 밀린 회차를 몰아 실행하지 않는다. ④ **기동 시 잔존 RUNNING을 FAILED로 정리하고 관리자에게 알린다.** ⑤ 중복 실행 방지는 **잡별 트랜잭션 advisory lock**(`pg_try_advisory_xact_lock`)이다 — 클레임 트랜잭션과 수명이 같다. ⑥ 등록 경로는 **CLI `register-jobs`(멱등)뿐**이고 마이그레이션 시드는 항구 금지다(함정 ⑩). ⑦ 화면은 **목록 열람 + is_enabled 토글까지**(관리자) — 스케줄 문자열 편집 통로를 두지 않는다. ⑧ 잡 본체는 실행기가 트랜잭션으로 감싸지 않는다 — 각 잡이 자기 건별 독립 트랜잭션을 연다(§17.6).

**근거** — 행을 넣는 것만으로 새 동작이 생기면 scheduled_jobs에 한 줄 적는 행위가 곧 코드 배포이고, 자동화 4금(§15 L3)을 데이터로 우회하는 통로가 열린다. 문법이 좁으면 "그 표현이 정확히 언제 도는가"를 사람이 검산할 수 있다. 정상 종료 경로만 기록하면 worker가 죽었을 때 RUNNING이 영원히 남아, 관리 화면은 돌지 않는 잡을 실행 중으로 표시하고 §15의 실패 알림은 크래시 경로에서 미발화한다.

**기각한 대안** — code로 임의 함수를 찾아 부르는 동적 디스패치(4금 데이터 우회), cron+croniter(§1 규모에 과설계·검산 불가), 밀린 회차 전량 실행(하루 다운 뒤 24회 폭주), RUNNING 방치(허위 표시+실패 알림 미발화), 마이그레이션 시드(함정 ⑩ — users FK가 TRUNCATE CASCADE로 PRESERVED_TABLES를 무력화), 화면에서 스케줄 편집(오타가 곧 조용한 미실행).

**되돌리기 비용** — 낮다. worker 컨테이너를 내리면 등록 행은 남고 실행만 멈춘다(CLI 수동 호출 경로는 그대로). 잡 등록 행은 soft delete로 되돌린다.

**부기(2026-08-12 — PR-1 자기 적대 검증 반영, 4건)**: ① 초판은 **프로세스 단위 세션 advisory lock**을 잡았는데, 앱 계정에 `idle_in_transaction_session_timeout='60s'`가 걸려 있어(infra/postgres/init/00-roles.sql) 잠금만 잡고 노는 세션이 60초 뒤 PG에 끊기고 **잠금도 함께 조용히 풀렸다** — 기동 60초 후부터 중복 기동 방지가 없는 상태였다. 잡별 트랜잭션 잠금으로 바꾸고, 실제 동시 실행 테스트로 "등록 잡 2종이 각각 정확히 한 번"을 고정했다. 잠금 실패 시 프로세스를 종료시키던 처리도 없앴다(`restart: unless-stopped`와 만나면 무한 재기동이 된다). ② 매핑 없는 코드·문법 밖 schedule 행이 **fail-open**이었다 — is_due를 건너뛰고 매 틱 실행되며 상태는 OK로 찍혔다. 지금은 `_defect_of`가 실행 전에 판정해 거부·FAILED 기록하고, 이미 그 사유로 FAILED인 행은 다시 집지 않는다. ③ 실패 알림 dedup 키가 **분 단위**라 1분 주기 잡이 지속 실패하면 하루 1,440건이 쌓였다 — KST **일 단위**로 바꿨다. ④ `last_error`에 원본 DB 예외 문자열이 그대로 들어가 관리 API로 되돌아갔다(함정 ④ 계보) — `scrub_text`를 통과시킨다. 토글 API의 낙관 잠금도 제거했다(시스템이 매 실행마다 같은 행을 갱신해 관리자의 끄기가 항상 409였다).
