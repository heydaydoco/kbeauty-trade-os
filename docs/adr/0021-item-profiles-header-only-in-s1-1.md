# ADR-0021: item_profiles는 S1-1에서 헤더와 적용 FK까지만 만든다

- **상태**: 채택
- **날짜**: 2026-07-29
- **관련**: DESIGN.md §4.8·§5.1·§4.7·§7.5 / WBS.md S1-1·S1-3·S2-1·S3-2

**맥락** — §4.8의 `item_profiles`는 "제품군 → 기본 **요건** 세트·**서류** 세트·**마일스톤** 세트"인데, 세 대상이 전부 후속 세션이다: 요건 템플릿은 S2-1(§5.1), 문서 종류는 S1-3(§4.7), 마일스톤은 S3-2(§7.5). S1-1 시점에는 연결할 것이 하나도 없다.

**결정** — S1-1은 프로파일 **헤더**(`code`, `name_ko`, `description`)와 **적용 FK**(`products.item_profile_id`, `skus.item_profile_id`)까지만 만든다. 내용 3종의 연결 테이블은 각 대상이 생기는 세션이 추가한다 — 서류 세트는 S1-3, 요건 세트는 S2-1, 마일스톤 세트는 S3-2. "신규 등록 시 자동 적용"(§4.8) 동작도 적용할 내용이 생긴 뒤다.

**근거** — 지금 세 연결 테이블을 만들면 참조할 대상 테이블이 없어 FK 없는 문자열 코드로 채우게 되고, 그 코드는 대상 테이블이 생겨도 FK로 바뀌지 않는다("이미 돌아가니까"). 반대로 헤더까지 미루면 S1-1의 제품·SKU 화면이 프로파일을 선택할 자리를 못 갖고, S2-1이 요건 세트를 만들면서 프로파일 자체를 새로 설계하게 된다. 헤더는 세 세션 모두가 참조할 안정된 축이라 지금 고정하는 것이 맞다.

**기각한 대안** — ① 내용까지 JSONB로 임시 저장: 대상 테이블이 생겨도 JSONB가 남고, FK 없는 참조는 대상이 삭제돼도 조용히 깨진다. ② `item_profiles` 전체를 S2-1로 이관: WBS 변경 + ADR이 필요하고, S1-1 화면에서 제품군 구분이 사라진다.

**되돌리기 비용** — 낮다. 테이블 1개와 FK 2개.

**부채 등록** — PROGRESS.md 부채 목록에 "item_profiles 내용 연결 미배정분(서류=S1-3 / 요건=S2-1 / 마일스톤=S3-2)"으로 기록하고, 각 세션이 자기 연결 테이블을 추가했는지 그 세션의 DoD에서 확인한다.
