# ADR-0078: LOCK_ORDER 개정(…PO → shipments → shipment_children → approvals → lines → seq)·SHARE→UPDATE 승격 금지·SO `FOR UPDATE` 선점·PO `FOR SHARE`는 수입선적 생성만

- **상태**: 자율 확정 — 사후 번복 가능 (S3-2 계획 2026-10-04 — 오너 지시 2026-09-29에 따라 판정 후보는 더 엄격한(fail-closed) 권장안으로 확정, ADR-0011 부기)
- **날짜**: 2026-10-04
- **관련**: DESIGN.md §8.3(문면 변경)·§17.2(S3-2 [M4] 보강) / ADR-0059 / docs/plans/s3-2-plan.md · docs/plans/s3-2/design-integrated.md(§9 적대 검토 정정 우선) — sC §C2·C3, sA §A10, X-09·X-10, R-08 / 구현 PR-3a(PR-4a·4c는 하위 기록 순서 소비)

**맥락** — §17.2 S3-1 부기 ②의 순서표에 선적·선적 하위 기록이 없고(변경은 ADR), §8.3 S3-1 부기 ②는 "선적·입고 소비 = 상위 헤더 `FOR SHARE`→라인 `FOR UPDATE`"다. 그러나 선적 생성은 같은 TX에서 SO 상태 수렴(ADR-0075)을 하므로 SO를 SHARE로 잡은 두 TX가 UPDATE로 승격하면 40P01 교착이 구조적으로 난다. 당사자·통관 기록 쓰기는 거래처 검증 잠금을 선적 뒤에서 잡을 위험이 있다(R-08).

**결정** — ① 순서: 멱등 claim → 인테이크 → **거래처** → QT → PI → SO → PO → **`shipments` → `shipment_children`(milestones·customs_records·shipment_parties)** → approvals → 라인(원천 라인 → 선적 라인, id 순) → `doc_number_seq`. ② 모드(경로별): **T1 수출 생성 = SO `FOR UPDATE` 선점**(그 뒤 `lock_lines_for_consumption`의 SHARE는 흡수 — **승격 금지**) / **T2 수입 생성만 PO `FOR SHARE`** / **선적 기점 경로(라인 편집·취소 T4·T5)는 `lock_chain` 그대로 SO·PO 모두 `FOR UPDATE`** / **T8·T9(당사자·통관) = 멱등 → 거래처 `FOR KEY SHARE`(id 순) → shipments → shipment_children** / T13 OEM = PO `FOR SHARE` → milestones `FOR UPDATE`. ③ 휴일 2표·`comm_logs`는 순서표 밖(교차 없음). ④ 담당 이관 `ASSIGNMENT_TARGETS`에 shipments를 purchase_orders 뒤로. ⑤ `locking.py` 독스트링·DESIGN §17.2·§8.3 부기를 같은 PR에서 고치고 J-07 계측 테스트에 T8·T9를 명시한다.

**근거** — 선점으로 SHARE→UPDATE 승격 교착을 구조적으로 없앤다. PO는 상태를 바꾸지 않으므로 SHARE로 충분하고 PO 취소(`FOR UPDATE`)와 직렬화된다. 부분수열 허용·순서 위반만 금지라는 ADR-0059 원칙을 그대로 승계한다.

**기각한 대안** — SHARE 유지 + 수렴을 별도 TX(§17.1 위반), PO도 `FOR UPDATE`로 통일(불필요하게 강함 — X-10), `ANCESTORS`에 경로별 모드를 싣기(헬퍼 확장 대비 실익 없음 — 교착 무관), 당사자 쓰기에서 거래처 검증을 선적 잠금 뒤에.

**되돌리기 비용** — **중간**(교착 재검증 필요 — 계측 테스트가 비용을 줄인다). 잠금 강도 낮추기는 헬퍼 1곳으로 낮음. DESIGN §8.3 부기 문면 변경이라 번복 시 부기 원복이 같이 움직인다.

**부기(2026-10-04 — S3-2 PR-3a 이행: 순서표·선점·계측)** — ①·②(T1·T4·T5·T8)·④·⑤를 구현했다. `locking.LOCK_ORDER` = 멱등 → 인테이크 → 거래처 → QT → PI → SO → PO → **shipments → shipment_children** → approvals → lines → seq(독스트링 갱신). T1 수출 생성 = 거래처(id 순) → **SO `FOR UPDATE` 선점** → 원천 라인 `FOR UPDATE`(`lock_lines_for_consumption`의 헤더 SHARE는 흡수) → 채번. 라인 편집·출고지시·취소 = `lock_chain(SHIPMENT)`(SO → 선적). 당사자 추가 = 멱등 → 거래처 `FOR KEY SHARE` → 선적, 당사자 제외 = 선적 → `shipment_children`. J-07 계측 시험이 경로 8개(생성·라인 추가·수정·삭제·당사자 추가·제외·출고지시·취소)의 첫 잠금 순서를 `LOCK_ORDER` 색인 오름차순으로 단언하고, GC-F4(7+7 동시)·20명 경합이 교착 0을 실측한다(변이: SO 선점을 빼면 GC-F4 실패). T2(수입 PO SHARE)·T9(통관)·T13(OEM)은 해당 PR(5a·4a·4c)이 소비한다. 담당 이관 대상은 purchase_orders 뒤에 shipments.

**부기(2026-10-04 — S3-2 PR-4a 이행: T9·마일스톤·통보 잠금)** — `shipment_children` 자리를 소비했다(`LOCK_ORDER` 무변경). 계획·실적 = 멱등 → 선적 `FOR UPDATE` → 마일스톤 행 `FOR UPDATE` / 초안 = 멱등 → 선적(새 행 INSERT뿐) / **T9 통관 추가** = 멱등 → 거래처(관세사 — 지정 시) `FOR KEY SHARE` → 선적 `FOR UPDATE` / 통관 정정 = (관세사 변경 시) 거래처 → 선적 → 통관 행 / 통관 삭제 = 선적 → 통관 행 / **통보** = 멱등 → 거래처(상대 — 지정 시) `FOR KEY SHARE` → 선적 `FOR SHARE`(상태 재검사 — 취소와 직렬화) → `comm_logs`·연결 행 INSERT(③ 순서표 밖). 오류 우선순위(ADR-0079 ⑧)를 지키려고 거래처 잠금 전 무잠금 peek로 선적 404·409를 먼저 판정하고 잠근 뒤 재검사한다(PR-3a 선례). 실적·통관 생존 취소 가드는 기존 `lock_chain(SHIPMENT)`(SO → 선적) 안에서 판정한다. J-07 계측 시험이 8경로(계획·실적·초안·통보·통관 추가·정정·삭제·취소)의 첫 접촉 순서를 `LOCK_ORDER` 색인 오름차순으로 단언한다. T13(OEM — PO `FOR SHARE` → milestones)은 PR-4c, T2는 PR-5a 그대로.

**부기(2026-10-04 — S3-2 PR-4c 이행: T13 OEM 생산 일정 잠금)** — N-07을 구현했다(`LOCK_ORDER` 무변경). OEM 계획·실적 = 멱등 claim → `purchase_orders` **`FOR SHARE`**(상태·구분만 읽는다 — Core `table()`로 원가 열 비조회, PO 무수정) → `milestones` 행 `FOR UPDATE`(shipment_children 슬롯 — X-09) + 행 version → UPDATE + `milestone_changes` INSERT + outbox `shipments.milestone.changed`(aggregate `purchase_orders`, payload `owner_type=PURCHASE_ORDER`). 선적 헤더는 건드리지 않는다. PO 취소(`lock_chain` `FOR UPDATE`)와 직렬화: 진행 중 취소가 PO를 쥔 동안 OEM 쓰기는 기다렸다가 커밋된 취소를 보고 409 `OWNER_NOT_ACTIVE`(다른 연결로 잠금을 쥔 실대기 시험). `FOR SHARE`는 공유 잠금이라 같은 종류 최초 계획 2건은 함께 들어오고 (PO, 종류) 부분 유니크 번역이 둘째를 409로 거른다(500 0). J-07 계측 시험이 첫 접촉 순서(멱등 → purchase_orders `FOR SHARE` → shipment_children `FOR UPDATE`)를 단언한다. 품목군 마일스톤 세트 쓰기는 순서표 밖(품목군·세트 행 — 전표 잠금 0).

**부기(2026-10-04 — S3-2 PR-4c 적대 검토 정정: 제목 문구)** — 제목의 'PO `FOR SHARE`는 수입선적 생성만'은 **'PO `FOR SHARE`는 수입선적 생성(T2)과 OEM 생산 일정(T13)'**으로 읽는다 — 결정 ②가 이미 T13 = PO `FOR SHARE` → milestones를 두었는데 제목·DESIGN §17.2 부기만 T2 하나로 적혀 있었다(두 경로 모두 PO 무수정). DESIGN §17.2 S3-2 부기 문면과 `locking.py` 독스트링((8) 정의에 PO 소유 OEM 마일스톤 행·잠금 모드 문단에 T2·T13)을 같은 커밋에서 고쳤다. 제목 파일명은 링크 안정을 위해 그대로 둔다. 또 위 PR-4c 이행 부기의 outbox 이름 `shipments.milestone.changed`는 `purchase_orders.milestone.changed`로 정정됐다(ADR-0083 부기 — 선적 알림 규칙의 OEM 발화 차단). **부기(2026-10-04 — S3-2 PR-5a 이행: T2 수입 생성 잠금)** — T2를 이행했다(`LOCK_ORDER` 무변경): 멱등 → partners(공급사 + 지정 당사자, id 순) `FOR KEY SHARE` → **PO `FOR SHARE`**(`lock_lines_for_consumption` — PO 상태·잔량을 바꾸지 않아 승격 0, 같은 TX의 수렴 함수는 수입이면 아무것도 잠그지 않는다) → PO 라인 `FOR UPDATE` id 순 → 채번. J-07 계측이 첫 접촉 순서(멱등→거래처→PO→라인→채번)와 **PO에 건 잠금 절이 전부 FOR SHARE**임을 단언한다(변이 'PO FOR UPDATE 선행'·'수렴 뒤 PO FOR UPDATE'·'라인을 거래처보다 먼저' kill). 같은 PO 다른 라인 6건 동시 = 전부 성공(교착 0), 생성 vs PO 취소 6회 = 하나만 성공. 선적 기점 경로(수입 라인 추가·수정·취소)는 `lock_chain` 그대로 PO `FOR UPDATE` → 선적(R-08).
