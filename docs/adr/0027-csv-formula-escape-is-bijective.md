# ADR-0027: CSV 수식 이스케이프는 전단사 대칭 변환이다

- **상태**: 채택 (웹 세션 판정 2026-08-05 — 보안 건 격상, S1-3 계획 조건부 승인)
- **날짜**: 2026-08-05
- **관련**: DESIGN.md §12.2 보강·§18.1 / WBS.md S1-3 / PROGRESS 부채 #17

**맥락** — 전 목록 CSV 내보내기(통로는 `core/csv_export` 한 곳)가 자유 텍스트 셀을 이스케이프 없이 내보내 Excel이 수식(`=`·`+`·`-`·`@` 시작)으로 해석할 수 있다(부채 #17). 그런데 단순 이스케이프는 §12.2 왕복 편집의 값 보존과 상충한다 — 이스케이프된 값이 업로드되면 diff가 전 행을 변경으로 오검출한다.

**결정** — 대칭 변환으로 상충을 없앤다. 내보내기: **문자열 타입 셀**의 선두가 `=` `+` `-` `@` 탭 CR `'`이면 `'` 하나를 접두한다(숫자·금액 타입 셀 비대상 — 음수 텍스트화 방지). 임포트 파서: 선두 `'` 다음 문자가 그 집합에 속하면 `'` 한 개를 제거한다. 변환이 전단사라 export→import 왕복에서 원값이 완전 보존된다(`'=`로 시작하는 원값도 `''=`로 이중 이스케이프 후 복원).

**근거** — §18.1(보안)과 §12.2(왕복 값 보존)를 한 규칙으로 동시 충족하고, 고치는 곳이 csv_export·임포트 파서 각 한 곳이다. **보증 범위: 전단사 보증은 본 시스템 export→import 쌍 기준이다.** `'` 접두는 엑셀 자체의 텍스트 접두 관례와 일치해 중간에 엑셀 편집이 끼어도 일반 케이스는 보존되고, 극단 케이스(원값이 `'`+수식문자 시작으로 엑셀을 경유)는 업계 표준 트레이드오프로 수용한다 — 이 이상 과잉 방어 금지(웹 세션 판정 문면).

**기각한 대안** — 탭 접두(값 자체를 오염시키고 CRLF 규율과 충돌), 내보내기 전용 이스케이프+왕복 별도 경로(통로가 둘이 되어 한쪽 누락이 재발 지점), 이스케이프 포기·신뢰 사용자 한정 유지(로그인 필수는 완화지 방어가 아니다).

**되돌리기 비용** — 규칙 변경 시 내보내기·파서 두 곳과 왕복 보존 테스트가 같이 움직인다. 이미 배포된 CSV 파일은 재다운로드로 해소(저장 데이터 무변).
