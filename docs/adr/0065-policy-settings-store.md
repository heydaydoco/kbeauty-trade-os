# ADR-0065: 정책 저장소 policy_settings — 값은 데이터·키/타입/기본값은 코드·폐쇄 키 CHECK·미설정은 fail-closed와 출처 표시·시드 없음

- **상태**: 자율 확정(2026-09-30) — 사후 번복 가능 (S3-1 계획 통합 검토서 §4.2 — E 묶음 E8, 통합 X-12)
- **날짜**: 2026-09-30
- **관련**: DESIGN.md §2 ADR-11·§7.3·§7.4·§15(폐쇄 레지스트리 선례)·§2 관리자 통제 / ADR-0041(소비 없는 열거 금지)·0060(유형 추가 절차 서식) / PROGRESS 함정 ⑩ / docs/plans/s3-1/design-E.md E8, design-integrated.md §1.1 X-12·§2.1(g)

**맥락** — ADR-11("설정화 가능분=데이터, 관리 화면")이 요구하는 값 있는 정책(PI 입금 게이트 모드·단가 편차 허용치)의 저장소가 없다. `feature_flags`는 bool 전용이고 `alert_rules.config`는 알림 문턱용 JSONB라 섞을 수 없다. D는 `gate_policies`(JSONB config), E는 `policy_settings`(키 CHECK 폐쇄 2개)를 각자 두어 같은 두 값을 두 표·두 기본값·두 API가 정의했다.

**결정** — ① **정책 저장소는 `policy_settings` 단일 테이블**이다(D의 `gate_policies` 테이블·CLI·`PUT /gate-policies`·`GATES.POLICY.INVALID_CONFIG`는 삭제). 믹스인은 Pk·Timestamp·SoftDelete·Version·Actor, `policy_key VARCHAR(60)`에 **CHECK IN ('pi_advance_gate_mode','price_deviation_tolerance_bp')**(폐쇄 열거), `value_text VARCHAR(20)`·`value_int INTEGER`, `unique_active(policy_key)`, 값 형 CHECK(모드 키는 `value_text IN ('OFF','WARN','BLOCK')`∧`value_int IS NULL`, 허용치 키는 `value_int BETWEEN 0 AND 10000`∧`value_text IS NULL`)이다. **값은 데이터, 키·타입·기본값은 코드**(ADR-11 해석)이며 키는 코드 동작과 1:1이라 행 추가만으로 새 동작이 생기지 않는다. 새 키는 소비 코드+CHECK 재정의 마이그레이션+ADR 부기(의도된 마찰, 승인 유형 추가 절차와 같은 규약)다. ② **코드 레지스트리 `POLICY_REGISTRY`**(`policies/registry.py`)의 키집합이 DB CHECK와 1:1이며 아키텍처 테스트가 `pg_get_constraintdef`를 파싱해 대사한다. **여신은 항상 켜진 승인 게이트**이므로 끔 스위치 키(`credit*enabled|off|skip` 류)를 등재할 수 없다. MOQ·중복 PO·품번 매핑·준비도 게이트는 DESIGN에 설정 문면이 없어 키를 만들지 않는다. ③ **미설정 동작(fail-closed·fail-visible)**: 행이 없으면 `pi_advance_gate_mode=BLOCK`(가장 엄격)·`price_deviation_tolerance_bp=0`(어떤 편차도 통과하지 않음 — 정확히 기준가인 라인은 통과, 1단위라도 벗어나면 BLOCK/OVERRIDE)로 동작하며, `get_policy(session, key) -> ResolvedPolicy(value, source: 'SET'|'UNSET_DEFAULT')`가 **유일 조회 통로**이고 게이트 응답·`gate_evaluations.results`(`policy_source`)·관리 화면이 `source`를 싣는다. **조용한 기본값 금지**이며 값 손상(CHECK 우회)은 미설정과 동일 취급+경고 로그다. 캐시하지 않고 게이트 평가 트랜잭션 안에서 읽는다. ④ **초기 행은 마이그레이션 시드·CLI 시드 모두 금지**(함정 ⑩·`_NEVER_SEEDED`)이고 관리자가 화면에서 저장할 때 upsert(없으면 `INSERT … ON CONFLICT DO NOTHING`, 충돌이면 409 `VERSION_CONFLICT`로 새로고침 안내 — 동시 최초 생성 500 금지)한다. 근거 없는 권장값(예: 허용치 5%)을 시스템이 박아 넣지 않으며 오너가 저장할 때까지 UNSET 기본 동작이다. ⑤ **API는 ADMIN 전용**이다: `GET /policies`(레지스트리 전 키를 행으로 — 현재값·`source`·라벨·설명·`version`·수정자·시각[KST])·`PUT /policies/{policy_key}`(본문 `{value, version|null, reason(2~300자, 필수)}`+`Idempotency-Key`, 알 수 없는 키 404 `POLICIES.POLICY.UNKNOWN_KEY`·값 위반 422 `POLICIES.POLICY.INVALID_VALUE`·version 충돌 409), 모든 변경은 같은 트랜잭션에서 `audit policy.update`(key·old·new·old_source·reason)+outbox `policies.policy.changed`를 남긴다. 삭제·"기본값으로 되돌리기"는 만들지 않는다. **실효 모드·출처는 게이트 응답으로 전 역할이 읽는다**(설정 열람·편집권과 분리). ⑥ 화면은 `/settings/policies`(ADMIN 전용): 표(라벨·설명·현재값·출처 배지[설정됨/**미설정 — 기본 동작(차단)** 적색+글자]·마지막 변경자·시각)와 행 편집(모드=셀렉트, 허용치=% 입력→bp 변환 표시, **변경 사유 필수**)이며 한국어 UI 규약을 따른다. ⑦ 값 변경(BLOCK→WARN/OFF 완화)은 ADMIN의 통제 결정이며 감사·사유로 추적되고 확정된 SO에는 사용된 모드·출처가 증적으로 남는다.

**근거** — ADR-11이 설정화 가능분을 데이터로 요구하고, 키를 폐쇄 열거+CHECK로 둔 것은 §15 스케줄 레지스트리 선례(코드 고정 폐쇄 열거)와 fail-closed(원시 INSERT 방어)에 맞는다. 미설정=BLOCK/0bp+source 표시는 D의 "0행=전 라인 UNKNOWN"보다 소음이 적으면서 fail-visible을 유지한다. 시드를 두지 않는 것은 Version·Actor 믹스인 테이블이 users FK 때문에 마이그레이션 시드 불가(함정 ⑩)이고, 수치 근거 없는 기본값이 업무 정책을 코드가 지어내기 때문이다. GET을 ADMIN 전용으로 둔 것은 게이트 응답이 이미 실효 모드·출처를 싣기 때문이다.

**기각한 대안** — `gate_policies` 별도 테이블(같은 두 값의 이중 저장소·기본값), `feature_flags`·`alert_rules.config` 혼용, `policy_key` CHECK 없는 열린 키, 마이그레이션·CLI 시드(`PRICE_DEVIATION 500bps`·`PI_DEPOSIT WARN` — 근거 없는 추측값), 미설정을 통과로 폴백, 정책 조회 GET을 TRADE에 개방, 기본값 복원 API·삭제, 거래처·품목군별 허용치(문면 근거 없음), 정책 값 캐시, 여신 끔 스위치.

**되돌리기 비용** — 낮음. 독립 신설 테이블·행 2개 수준이며 키 추가·값 범위 변경은 CHECK 마이그레이션 1건, 기본값 변경은 레지스트리 상수 1곳이다.

**영향 세션** — S3-1 PR-4(저장소·화면)·PR-11(`price_deviation_tolerance_bp`·`pi_advance_gate_mode` 소비) / S3-3(PI 모드 기본값 WARN→BLOCK 전환 오너 결정 — 정책 값 저장만) / S5-1(채널 게이트 정책 키는 추가 절차로) / runbook(운영 개시 시 정책 설정).
