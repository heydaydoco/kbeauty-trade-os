# ADR-0028: documents는 폴리모픽 소유 + 열린 종류 코드 + FILE/LINK 2형이다

- **상태**: 채택 (웹 세션 조건부 승인 2026-08-05의 PR-2 범위 구현)
- **날짜**: 2026-08-06
- **관련**: DESIGN.md §4.7·§4.8·§17.4·§12.1 / WBS.md S1-3 / ADR-11·ADR-0020·ADR-0021·ADR-0026

**맥락** — §4.7의 documents는 "폴리모픽 소유, 종류 코드, 유효기간, 파일, 해시"만 명세한다. 소유자 열거·종류 코드의 폐쇄 여부·파일과 링크의 공존 방식·해시 멱등의 범위가 구현 판단 대상이었다.

**결정** — ① 소유는 `owner_type`(CHECK)+`owner_id`이며 열거는 **이번 세션 소비분 2종(SKU·LABEL)뿐** — 전표·인증·시설 등 아직 없는 소유자는 소비 세션이 CHECK 확장 마이그레이션으로 추가한다(ADR-0021 규율). 소유 실재는 FK가 불가하므로 서비스가 검증한다. ② 종류 코드는 **닫힌 CHECK가 아니라 `document_types` 테이블**(ADR-11 "유형 코드는 데이터") — 시드는 §4.7 열거 9종+라벨 파일(추론분, 승격용)이고 roles와 같은 지위라 Version·Actor 컬럼이 없다(테스트 하네스의 TRUNCATE users CASCADE가 시드를 지우는 경로 차단 — 실측). ③ 저장은 FILE/LINK 2형 상호 배타 CHECK — 승격 이관분(구 msds_url·file_url)은 LINK, 신규 실물은 FILE. ④ 해시 멱등은 **(소유자, sha256) 부분 유니크** — 전역 유니크로 하면 용량 변형이 같은 MSDS 파일을 공유하는 실무가 막힌다(§12.1 "중복 감지"의 단위는 소유자다). ⑤ 원산지 증빙의 보존 규율은 `document_types.retention_years=5`(데이터)로 들고, 보존기한 내 soft delete 거부(파기 잠금)는 서비스가 강제한다 — "오늘"과의 비교는 CHECK로 표현할 수 없다. 강제 삭제 액션은 없다. ⑥ "SET SKU에 MSDS 금지"는 구 set_has_no_dg CHECK의 승계분으로 **서비스 가드+테스트**다(웹 세션 승인 — 다른 테이블이라 CHECK 불가).

**기각한 대안** — 소유자 전 열거 선반영(검증 불가한 값 — ADR-0021과 동일 사유), 종류 CHECK 고정(§4.6 유형 10종과 달리 §4.7 열거는 예시적 문면이고 ADR-11이 데이터로 지정), 해시 전역 유니크(실무 차단), 파기 잠금 트리거(ORM 밖 규칙 분산 — set_components 선례).

**되돌리기 비용** — 소유 열거·종류 추가는 마이그레이션 1건씩으로 낮다. 해시 유니크 범위 변경은 데이터 정리가 따라와 중간이다.
