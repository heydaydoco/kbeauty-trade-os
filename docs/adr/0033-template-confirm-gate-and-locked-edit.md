# ADR-0033: 템플릿 상태는 3값이고, 확정 게이트는 3층이며, 확정 상태는 편집 불가다

- **상태**: 채택 (S2-1 계획 웹 세션 판정 2026-08-07 — 안건 1·3·조건 7·11)
- **날짜**: 2026-08-10
- **관련**: DESIGN.md §5.1·§5.5·§15·§17.4 / WBS S2-1 DoD / s2-1-plan.md §0-1 / ADR-0025(상태 3값 선례)·ADR-0030 ⑤(확정=1클릭+멱등 선례) / GC-C8

**맥락** — §5.5가 "근거 링크 없는 항목 확정 차단"을 명시하지만(근거 2필드가 nullable인 이유 — 초안의 실재), CONFIRMED 행의 편집을 열어 두면 근거 강제 CHECK를 우회하는 경로(초안 강등 후 근거 소거, PATCH로 상태 직접 기입)가 생긴다 — 조건 11이 우회 불가 설계를 요구했다.

**결정** — 상태는 3값(DRAFT/CONFIRMED/RETIRED — ADR-0025 계보)이고 게이트는 3층이다: ① DB CHECK `confirmed_requires_evidence`(확정 행은 근거 2필드를 비울 수 없다 + `source_url_not_blank`로 공백 우회 차단) ② 서비스 — 확정 액션은 사람 1클릭+idempotency key 하나뿐이며 근거 결여 시 422, **CONFIRMED 행의 내용 편집(PATCH·체크리스트·선행요건 변경)은 409로 차단**하고 재확정 경로는 명시 액션(초안 전환→편집→재확정)뿐이다. PATCH의 status에 CONFIRMED는 올 수 없다(확정 진입=확정 액션 단일 경로) ③ 아키텍처 테스트 — requirements 모듈에 자동 확정 경로 부재를 고정(§12.2 선례 확장).

**근거** — 확정은 "요건 정의 데이터의 등록 완료" 표시이지 적합 판정이 아니고(§15 4금 비저촉 — 거부형 게이트+사람 1클릭), 내용이 바뀌면 근거의 지시 대상도 바뀌므로 재확정이 근거-내용 일치를 지킨다. "그때 요건"의 동결은 S2-2 인스턴스 스냅샷 몫이라 템플릿 자체는 불변 대상이 아니다(ADR-03 "규제 변경은 관리 화면에서 흡수").

**기각한 대안** — CONFIRMED 편집 허용+CHECK 의존(계획서 §2-2 초안 문면): 근거는 남되 내용-근거 불일치가 조용히 쌓인다 — 판정 조건 11로 대체. 상태를 PATCH 자유 필드로(라벨 방식): 확정 게이트가 형식이 된다.

**되돌리기 비용** — 편집 차단 해제는 서비스 가드 1곳+테스트 갱신이지만, GC-C8과 조건 11 문면이 함께 움직인다(웹 세션 재판정 세트).

**부기(#16 보완 판정 2026-08-11)** — confirm은 DRAFT 상태에서만 허용한다(RETIRED 확정 409 `REQUIREMENTS.TEMPLATE.NOT_DRAFT`). 상태 머신이 DRAFT 허브(CONFIRMED→RETIRED 직행도 409)인데 RETIRED→CONFIRMED만 열려 있던 것은 설계 선택이 아닌 결손이었고, 폐기 템플릿 재활성은 근거 최신성 재검토(초안 전환 경유)가 필수다 — `last_verified_on`이 낡아도 non-null이면 CHECK를 통과하는 맹점을 상태 규칙이 보완한다. GC 문서 비변경(근거 결여 아닌 상태 규칙 — GC-C8 무관, v1.2 유지).
