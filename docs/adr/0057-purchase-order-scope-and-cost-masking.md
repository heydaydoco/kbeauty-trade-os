# ADR-0057: 구매 발주(PO) — SKU 전용·생성=발행=사람 1클릭·po_kind 슬롯·원가는 `_cost` 명명과 필드 부재 마스킹 9채널·후반 소유는 WBS v1.5로 배정

- **상태**: 자율 확정(2026-09-30) — 사후 번복 가능 (S3-1 계획 통합 검토서 §4.2 — A 묶음 A12, F 묶음 F1~F7)
- **날짜**: 2026-09-30
- **관련**: DESIGN.md §2·§4.4·§7.1·§7.2·§8.1·§8.2·§8.5·§15 L3 4금 ①·§18.1 / ADR-0008·0017·0018·0024·0037·0038·0041 / docs/plans/s3-1/design-A.md A12, design-F.md F1~F7

**맥락** — PO는 §7.2에 "발행→공급사확인(OC)→…"로 초안 상태가 없고, 발주 확정은 §15 자동화 4금 ①이다. 자재 발주·입고 후반·수입선적 연결·OEM 생산 마일스톤의 소유 세션이 WBS에 없고, PO 금액은 원가라 조회(VIEWER)에게 새면 안 된다.

**결정** — ① **PO 라인 품목은 SKU 전용**(`sku_id NOT NULL`, 수량 EA 정수)이며 자재 PO는 S3-1에서 만들지 않는다. P4 가산 경로는 `sku_id DROP NOT NULL`+`material_id` 추가+`num_nonnulls(sku_id, material_id)=1` CHECK+수량 `INT→NUMERIC(14,4)` 확폭+`uom`+자재 단가 `MANUAL` 강제다(요청 스키마에 `material_id`·`item_type` 없음). ② **PO 생성 요청 자체가 발행=발주 확정(사람 1클릭+`Idempotency-Key`)**이고 초안·승인 게이트가 없다(§2 승인 대상 열거에 PO 발행 없음). 호출 경로는 라우터 1곳뿐이며 스케줄러·CLI·outbox 핸들러·imports·order_intake·order_board·approvals·gates·seeds 어디서도 `create_purchase_order`를 임포트하지 않는다(AST 스캔), 오더 보드 벌크 열거에 PO가 없고 §8.8 발주점 권고도 PO를 만들지 않는다. 화면은 2단(입력+비저장 `preview` → 확정 클릭)이고 확정 버튼의 키는 폼 인스턴스당 1개다. OC 기록의 `oc_received_on`은 `doc_date <= oc_received_on <= today_kst()`(서비스 경계)이며 발행 후 편집 가능한 FREE 열은 B의 4개뿐(라인 ETA 컬럼은 만들지 않는다). ③ **공급사 유형·`po_kind`**: `purchase_orders.po_kind VARCHAR(16) NOT NULL DEFAULT 'PURCHASE'`(`PURCHASE`·`OEM_PRODUCTION`, CONTENT — 생성 후 불변)이며, `PURCHASE`는 활성 유형 SUPPLIER 또는 OEM 하나 이상, `OEM_PRODUCTION`은 OEM 필수다. 검증은 생성 1회, 거래처 행 `FOR KEY SHARE`(ADR-0059)로 하고 `partners.service.require_partner_of_any_type(…, lock)`를 쓰며 신규 에러코드는 만들지 않는다(`VALIDATION_INVALID_FIELD`+필드 detail). 이후 유형 해제는 이미 발행된 PO를 무효화하지 않는다. ④ **PO 금액 열은 `unit_cost`·`line_cost`·`total_cost`**(통화 `currency`)로 명명한다 — `unit_cost`(마스킹 키)·`_cost`(마스킹 접미·금액 판정)에 이미 걸려 로그 마스킹·유니크 키 금지가 코드 변경 없이 편입된다(`amount`·`price`는 의도적으로 마스킹 제외이므로 `purchase_*_amount` 접두 안은 규칙을 새로 짜야 해 기각). 단가는 미입력 시 `price_at(price_type='PURCHASE', on=doc_date)`→`price_basis='MASTER'`(부재는 `CATALOG.PRICE.NOT_EFFECTIVE` 422 전파), 입력 시 `MANUAL`(`price_at` 미호출), **`unit_cost>0`**(무상 매입 미지원)이며 `price_type="PURCHASE"` 리터럴은 `purchase_orders` 모듈 밖 0건이다. ⑤ **원가 마스킹은 PO를 혼합 목적 행으로 보아 행 단위 숨김이 아니라 필드 부재(ADR-0024)**로 한다: 응답 스키마 2종(`PurchaseOrderDetail`/`…CostHiddenDetail` 등 목록·상세·라인 각각)에서 VIEWER에게는 `total_cost`·`currency`·`unit_cost`·`line_cost`·`price_basis` 키 자체가 없고(행 수·건수·상태는 보임, VIEWER 목록·상세 200), 갈림은 `response_model=None`+`may_see_cost`(`COST_VISIBLE_ROLES` 단일 출처) 한 곳이다. 부수 **9채널**을 전수 봉쇄한다: 정렬·필터·검색(원가 값 정렬·범위 필터 없음, `Literal` 화이트리스트 밖은 422) / CSV(헤더 상수 2종 — 원가 포함·미포함) / 에러 detail·검증 메시지(값 미기재) / 로그(원가 값을 로그·예외 f-string에 넣지 않음) / audit detail(`{doc_number, supplier_partner_id, line_count, po_kind}`만) / outbox·알림·브리핑(payload 화이트리스트, 원가·통화 금지) / `idempotency_keys.response_body`(생성 응답 Full 스키마가 생성자 스코프 24h 저장 — **at-rest 수용 사실로 명시**하고 청소 잡으로 최소화, ADR-0058) / documents 첨부(S3-1 없음 — 후속 첨부는 VIEWER 403을 소유 권한과 함께 검사) / 집계·보드(SO·QT·PI·보드·인테이크 응답에 cost·margin·purchase 계열 필드를 어느 역할에도 도입하지 않음). ⑥ **후반 소유 배정(WBS v1.5)**: 입고 문서·PO 잔량 차감(`LINE_CONSUMERS['PO_LINE']` 소비자)·PO 후반 전이(RESERVED 3값 엣지)·IN_PO 원장 ref는 **S4-1**(입고 확정이 IN_PO 원장 이동과 한 트랜잭션이어야 하므로), 수입선적의 PO 참조(`shipment_lines.po_line_id`)·`customs_records`는 **S3-2**, PO 라인 ETA 슬롯은 소비 세션(S3-2 선적 ETA 파생 또는 P4 백오더)이 판정한다. ⑦ **OEM·facilities**: 구분 슬롯 `po_kind`로 OEM 생산 발주 재판정 트리거를 종결하고 마일스톤 프로파일 적용은 S3-2 몫이며, **facilities 마스터는 신설하지 않는다**(PO는 `supplier_partner_id`만 가진다 — 재판정 트리거: S3-2 프로파일 계획에서 시설 단위 일정 필요 판정 / 한 거래처의 두 번째 시설 인스턴스 등록 시도 / 시설 인증 인스턴스 대량 등록 착수 전).

**근거** — materials 테이블에는 단가·통화·단위 컬럼이 없어(BOM 라인의 컬럼이다) 자재 라인은 단위·수량 타입·가격 원천 세 가지가 DESIGN에 없다 — 지금 정하면 추측 구현이며 자재 확장은 무손실 가산 ALTER다(ADR-0041). PO 초안은 §7.2 문면 밖이고 B가 6값·전이 3방향·생성=발행으로 확정했다. 다중 유형(SUPPLIER∧OEM) 거래처에서는 유형만으로 생산 발주 여부를 알 수 없고 구분을 나중에 붙이면 기발행 PO를 재분류해야 한다(ADR-05 재입력 금지). PO 행은 상태·공급사·품목·수량·납기는 물류·조회 업무 데이터이고 원가는 3~4칸뿐이라 행 존재 자체는 원가 정보가 아니다(ADR-0024 논지) — 행 단위 404는 "없는 것"으로 오독된다. §18.1은 "화면에서 못 보는 값이 로그에 평문이면 통제가 우회된다"이며 마스킹은 이름 기반이라 이름 규약이 곧 통제다.

**기각한 대안** — 자재 라인을 SKU와 폴리모픽으로 지금 도입(추측 구현), PO DRAFT·SHIPMENT_LINKED 상태(문면 밖), 라인 `expected_receipt_on`(소비자가 P4에 있어 발행 후 변경 가능 컬럼을 지금 만들 이유 없음), 금액 열을 `purchase_*_amount`·`unit_price_amount`로 명명(마스킹 회피 위험·규칙 신설), CERT의 PO 접근 403(`COST_VISIBLE_ROLES`와 두 곳으로 갈림), 행 단위 404 숨김, FastAPI `Union` 응답 자동 분기(ADR-0024 실측 실패), 직렬화 후 dict 키 삭제, facilities 즉시 신설, PO 승인 게이트(§2 열거 밖 — 필요 시 승인 유형 가산 절차로).

**되돌리기 비용** — 낮음~중간. SKU 전용→폴리모픽은 가산 ALTER지만 반대(폴리모픽→전용)는 자재 라인이 쌓인 뒤 비싸다. `_cost` 컬럼 rename은 신규 테이블이라 지금 무료이고 데이터 이후엔 마이그레이션+전 코드 변경이다. 필드 부재→행 단위 전환은 API 계약(200→404)이 프런트·테스트 전반에 퍼져 중간, 노출 확대는 스키마 통합만으로 되나 원가 유출은 회수 불가라 안전한 쪽을 채택했다. WBS 배정은 문서 한 줄(매우 낮음).

**영향 세션** — S3-1 PR-8(PO)·PR-3(`require_partner_of_any_type`) / S3-2(수입선적 PO 참조·`customs_records`·OEM 마일스톤 프로파일·`po_kind` 소비) / S3-4(PO 매입가=원가 원천·마진) / S4-1(입고 문서·후반 엣지·사급 ADR에서 자재 PO 가산) / S6-2(원가 조회)·후속 PO 첨부 세션(원가 가시성 검증).

**부기 (S3-1 PR-8a 구현, 자율 확정 2026-09-30 — 설계보다 좁은 쪽으로 구체화)** — ① 원가 없는 응답(`…CostHidden…`)은 설계 목록(`total_cost`·`currency`·`unit_cost`·`line_cost`·`price_basis`)에 더해 통화를 역추론할 수 있는 `minor_units`·`fx_rate`·`fx_rate_date`·`*_text` 금액 표기도 **필드 부재**로 했다(환율 값으로 통화가 드러나므로). ② 채널 5(audit)는 X-24(전표 생성·전이·편집은 audit 미기록)를 따라 **PO audit 행 자체가 0건**이다(화이트리스트 audit 문구는 "audit를 쓰는 경로가 생기면"의 제약으로 격하). ③ 채널 7의 청소 잡(`idempotency-purge`)은 PR-16이 이행한다 — 그 전까지 생성 응답(Full)의 24시간 at-rest는 수용 사실로 테스트가 스코프(생성자 행만)를 고정한다. ④ OC 열은 공급사 확인 전이에서 기록하고 메타(FREE)로는 SUPPLIER_CONFIRMED 상태에서만 고친다(DB CHECK와 같은 규칙을 422로 안내). 근거: design-integrated §1 해소 원칙 ②(더 좁고 fail-closed) / `tests/e2e/test_purchase_order_cost_masking.py`.
