# ADR-0005: 트랜잭션 경계 런타임 강제 + 테스트 격리 방식

- **상태**: 채택
- **날짜**: 2026-07-24
- **관련**: DESIGN.md §17.1·§17.2 / GC-F1

**맥락** — §17.1("트랜잭션 시작·종료는 서비스 레이어에서만")과 GC-F1("실제 동시 실행")을 문서 규율이 아니라 구조로 지켜야 P4에서 무너지지 않는다.

**결정** — GuardedSession이 UnitOfWork 밖의 commit/rollback을 거부한다(라우터는 세션을 손에 쥐지 못하고 읽기 전용 세션·unit_of_work만 쓴다). 중첩 UoW는 새 트랜잭션이 아니라 합류. 외부 호출은 `add_after_commit`(커밋 후)로만. 테스트 격리는 **실제 커밋 + owner 롤 별도 커넥션 TRUNCATE** — 롤백/SAVEPOINT 픽스처 채택 금지.

**근거** — 롤백 픽스처는 서비스 자체 커밋과 SAVEPOINT 해킹 없이 양립 불가하고(테스트 전용 코드 경로 생성), 하나의 열린 트랜잭션 안에서는 스레드 둘이 서로의 커밋을 볼 수 없어 GC-F1이 원리적으로 불가능하며, 아웃박스의 "커밋 후 발송"도 검증할 수 없다.

**기각한 대안** — 라우터 세션 직접 주입(트랜잭션이 화면 단위로 쪼개짐) / 트랜잭션 롤백 픽스처(빠르지만 §17.1·GC-F1·아웃박스와 원리적 충돌).

**되돌리기 비용** — 픽스처 방식을 나중에 바꾸면 P4에서 GC-F1·권한·아웃박스 테스트가 한꺼번에 무너진다. conftest 주석 + 이 ADR로 고정.
