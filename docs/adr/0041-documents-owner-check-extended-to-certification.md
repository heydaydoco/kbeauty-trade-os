# ADR-0041: documents 소유 열거 CHECK 확장 — CERTIFICATION 1종 추가(컬럼 확폭 동반)

- **상태**: 채택 (S2-2 계획 웹 세션 판정 2026-08-11 — 안건 ⑤ 기승인, PR-2 실장)
- **날짜**: 2026-08-12
- **관련**: DESIGN.md §4.7·§5.1·[M1] 보강(S1-3) ⑥·[M2] 보강(S2-2 PR-2) / ADR-0028(소유 열거는 소비분 한정 확장) / 마이그레이션 e7a1d4c8b2f6

**맥락** — certification_tasks 서류 링크(PR-2 ②)가 인증 인스턴스 소유 서류의 실소비를 연다. ADR-0028은 소유 열거를 "소비분 한정 CHECK 확장" 규율로 예약해 뒀고(S1-3 시점 2종), 이번이 그 규율의 첫 적용이다.

**결정** — DOCUMENT_OWNER_TYPES = (SKU, LABEL, CERTIFICATION) 3종. 기존 테이블 CHECK라 수기 재정의(drop→create, op.f() — 함정 ①·⑪)이고, 'CERTIFICATION'이 13자라 owner_type VARCHAR(10)→(13) 확폭이 선행된다(모델 String(13)과 drift 대사). 정의문 실재는 pg_get_constraintdef 테스트가 모델 열거와 1:1로 대조한다. 서비스 소유자 검증은 활성 인스턴스 실재+표시 "#id · 요건명", 권한·파일 보안·해시 멱등은 §4.7 계보 그대로.

**근거** — 폴리모픽 소유는 FK가 불가라 CHECK+서비스 검증이 유일한 실재 강제층이고, 소비 없는 선확장은 검증 코드 없는 열거값(죽은 문)을 만든다.

**기각한 대안** — SHIPMENT 등 동반 선확장(소비 세션 부재 — 과확장 억제 판정 문면), GMP류 공용 서류의 시설 소유 신설(정본 귀속처 판정은 관찰 등재 — 트리거: S2-4 전달 서류 zip 또는 실등록 수요), 특정 인스턴스 소유로의 공용 서류 등록(공용 문면과 상충).

**되돌리기 비용** — 낮다. downgrade는 구 정의·구 폭 복원이고, CERTIFICATION 소유 행이 있으면 실패하는 것이 올바른 실패다(데이터가 제약보다 넓다 — a7c3e9f2d4b8 선례).
