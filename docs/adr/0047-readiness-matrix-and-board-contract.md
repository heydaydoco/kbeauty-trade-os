# ADR-0047: 준비도 매트릭스·인증 보드 계약 — 계산값 미저장·색 표·실효 상태·필수 집합 4축·세트 롤업·읽기 전용 보드

- **상태**: 채택 (S2-3 계획 웹 세션 판정 2026-08-12 — 안건 ①·⑥, 판정 요청 1·2·16, 조건 A / PR-3 구현 판단은 계획 §0-4·§0-5 — 오너 자율 지시[2026-09-29]에 따른 **자율 확정**)
- **날짜**: 2026-09-29
- **관련**: DESIGN.md §4.2·§4.8·§5.2·§5.3·§14 ②④·§17·§18.4·§22 / ADR-0036(보드 배정)·0037~0040(상태머신·스윕)·0042(품목군 자동 적용 축)·0046(도과 계산값) / PROGRESS 관찰 "[S2-3 PR-3 등재]"

**맥락** — PR-2까지로 인증 인스턴스·상태머신·기일 알림이 섰다. 남은 것은 그 사실을 사람이 한눈에 보는 두 화면이다: 시장 준비도 매트릭스(§5.3 메인 — 행 SKU×열 시장, 셀=신호등)와 인증 보드(§14 ④ — 칸반+캘린더). 판단할 것은 여섯이다: 집계를 저장할 것인가, 상태를 어떤 색으로 읽을 것인가, 저장 상태와 달력의 어긋남을 어떻게 다룰 것인가, 무엇을 "필수"로 셀 것인가, 세트 SKU를 어떻게 굴릴 것인가, 보드에서 상태를 바꿀 수 있게 할 것인가.

**결정** — ① **집계는 저장하지 않는다**(§5.3 "저장하지 않고 계산"): 집계 테이블·컬럼·마이그레이션·이벤트 발행 0이며, 매트릭스 모듈에 쓰기 경로(`session.add`·insert·update·delete·outbox 발행)가 없음을 아키텍처 테스트가 소스 스캔으로 고정한다. 캘린더 조회도 읽기 전용이다. ② **색 표 하나가 정본**(`readiness/rules.py` — 상태 11값 전수 테스트): 🟢 승인(실효) / 🟡 서류준비·신청제출·심사중·보완요청·만료임박·갱신중(미도과) / 🔴 **미착수**·만료·반려·중단·**갱신중 도과**·활성 인스턴스 부재 / ⚪ 필수 요건 0건. **셀 = 최악값**(🔴>🟡>🟢). ③ **실효 상태 재계산**: 달력 파생 3태(승인·만료임박·만료)는 조회 시점에 만료일·리드타임으로 다시 계산하고(`certifications/calendar.py` 순수 함수 — 스윕·도과 표시·매트릭스·캘린더가 한 정의를 공유), 갱신중의 도과는 상태 전이 없이 🔴로 읽는다(ADR-0046 도과 계산값과 같은 정의). ④ **필수 집합 4축**(요청 2 (나)): 확정(CONFIRMED) 템플릿의 활성 인스턴스(삭제·종결 2태 제외)만 센다. SKU 요건=그 SKU 자신의 품목군, PRODUCT 요건=**소속 제품 자신의 품목군**(자동 적용과 같은 축 — ADR-0042), COMPANY·FACILITY=두 품목군의 합집합(같은 템플릿 1건). FACILITY 대상=SKU의 제조사 파트너이고 **제조사 미지정=🔴(fail-closed)**. INGREDIENT은 모집합 밖이며 범례가 공개한다(조건 A — 문구는 서버 `scope_note`가 정본). ⑤ **세트 롤업**(§4.2): 자기 요건+구성품 요건, **같은 (템플릿, 대상)은 한 번만**, 제조사 미지정은 구성품별 별개, 구성 유래는 `via_component_sku_*` 표기, 삭제된 구성품 제외, 세트 자신의 시설 요건은 구성품에 맡긴다. ⑥ **보드는 읽기 전용이고 드래그 전이는 없다**(요청 16): 칸반 컬럼=상태 11값(§5.2 진행 순 뒤에 만료·반려·중단), 카드는 `/certifications?id=` 딥링크로 상세를 연다(전이 통로는 인증 상세 폼 하나). 칸반은 카드 200장(서버 페이지 상한)까지, 캘린더는 한 달 200건까지 싣고 **넘으면 총계와 함께 잘림을 고지**한다. 캘린더 조회는 `GET /api/v1/deadlines/calendar?from&to` — **후보 정의가 기일 스캔과 같고**(활성·종결 2태 제외·기일 있음) 기간 최대 93일. ⑦ 응답 모양: 그리드형(봉투 최상위 `markets`·`as_of`·`scope_note`, 행=SKU 한 쪽 기본 50·최대 200, 각 행 `cells`는 `markets`와 같은 순서). 기준일은 API로 노출하지 않는다.

**근거** — 집계를 저장하면 "만료일을 고쳤는데 매트릭스가 어제 값"이라는 재계산 버그의 한 부류가 통째로 생기고, 그 실패는 🟢가 거짓으로 남는 모양이라 가장 위험하다(채널 리스팅 게이트의 입력이 된다). **미착수=🔴**: 착수 사실이 0인 요건을 🟡로 두면 "진행 중"이라는 거짓 신호가 되어 🟢 과신과 같은 방향의 오류다. **저장 상태를 그대로 믿지 않는 이유**: 스윕은 하루 한 번이라 만료일이 지난 날 06:00 전에는 저장 상태가 낡았고, 매트릭스가 그 지각에 종속되면 "정정 즉시 반영"(DoD)이 성립하지 않는다. **PRODUCT 축이 소속 제품 자신의 품목군인 이유**: 축이 자동 적용과 다르면 "자동 생성된 인스턴스가 미착수로 남아 있다"를 매트릭스가 읽지 못해 영원히 🔴이거나 영원히 ⚪인 칸이 구조적으로 생긴다. **FACILITY fail-closed**: 확인할 대상이 없는 것을 "해당 없음"으로 읽으면 🟢 과신이다. **세트 롤업의 중복 제거**: 기업·같은 제품·같은 제조사 요건은 구성품마다 반복되므로 안 세면 "필수 5건"이 실제로는 서로 다른 1건이 5번 세어진 것이 된다(색은 최악값이라 불변 — 건수·상세의 정직성 문제). **드래그 비구현**: 상태 전이는 사유·신청일 같은 부속 기록을 동반하는 사람의 기록이고, 카드 이동 한 번으로 완결되는 동작이 아니다 — 통로를 상세 폼 하나로 두어 §5.2 전이 표의 강제 지점이 하나로 남는다. **잘림 고지**: 조용히 잘린 200장은 "없다"로 읽힌다(함정 ⑦ 계열). **93일 상한**: 이 조회는 두 테이블을 기간으로 훑어 합친 뒤 쪽을 자르므로 기간이 무한하면 "전체를 읽고 잘라 주는" 조회가 된다(§18.4 무제한 조회 금지의 정신) — 화면은 월 단위로 부른다. 후보 정의를 스캔과 맞추는 이유: 다르면 "알림은 왔는데 캘린더에 없다"가 생긴다.

**기각한 대안** — 셀 집계를 캐시 테이블로 저장(재계산 버그 부류 신설·정정 즉시 반영 위반), 미착수를 🟡로(거짓 진행 신호), 저장 상태만 신뢰(스윕 지각 종속), INGREDIENT 축 포함(성분×제품 전개가 필요해 S2-3 범위 밖 — 모집합 명시로 갈음, 관찰 등재), 필수 집합을 인스턴스 존재로 정의(인스턴스가 없으면 요건도 없어져 미등록이 ⚪로 사라진다), PRODUCT 축을 SKU의 품목군으로(자동 적용 축과 불일치), 제조사 미지정 FACILITY를 ⚪로(🟢 과신), 세트 롤업의 중복 미제거(건수 부풀림), 드래그 전이(전이 강제 지점 분산·사유 미기록), 칸반 무제한 적재(조용한 잘림 또는 무한 조회), 캘린더 기간 무제한, 셀 클릭 시 상태 직접 변경 등 매트릭스발 쓰기 조작.

**되돌리기 비용** — 낮다. 두 화면 모두 읽기 전용이라 저장 형식이 없고, 색 표·모집합·잘림 상한은 모듈 한 곳의 상수·함수다(표를 바꾸면 테스트가 함께 움직인다). API 모양(그리드형·캘린더 항목)을 바꾸면 화면이 함께 바뀌지만 데이터 이관은 없다. 인증 뷰의 `assignee_name`은 읽기 전용 표시 필드라 제거해도 저장에 영향이 없다.
