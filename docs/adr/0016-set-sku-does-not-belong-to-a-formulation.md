# ADR-0016: 세트 SKU는 처방에 속하지 않는다 — `skus.kind`로 구조를 가른다

- **상태**: 채택
- **날짜**: 2026-07-29
- **관련**: DESIGN.md §4.1·§4.2 / WBS.md S1-1 / ADR-11(설정화의 한계선) / GC-E1

**맥락** — §4.1은 "제품(처방)과 SKU를 분리"하며 SKU를 처방에 매단다. 그런데 §4.2의 세트 SKU는 서로 다른 처방의 구성품을 담은 실물이라 처방 **하나**에 속할 수 없다 — §4.2 원문이 "인증·원산지 판정·C/O는 세트가 아니라 구성품 처방별 유지(세트 화면은 구성품 판정의 롤업 뷰)"라고 못박는다. `skus.product_id`를 단순 NOT NULL로 두면 세트를 넣을 자리가 없고, 단순 nullable로 두면 단품에서도 처방이 빠진 채 저장된다.

**결정** — `skus.kind ∈ (SINGLE, SET)`을 두고 DB CHECK로 **양방향** 강제한다: `SINGLE`이면 `product_id` NOT NULL, `SET`이면 `product_id` NULL. 세트의 인증·원산지는 구성품 롤업으로만 표현하고 세트 자체에는 처방을 달지 않는다. `set_components`의 구성품은 `SINGLE`만 허용한다(중첩 세트 금지).

**근거** — 처방 단위 판정(§4.1·§6.2)과 재고·판매 단위(§8.1 "원장 주체 = 품목")가 다른 축이라는 것이 §4.1의 요지다. 한쪽 CHECK만 걸면 나머지 방향이 열려 있고, 열린 쪽으로 들어온 행은 S3-4 판정이 처방 없는 SKU를 만나 침묵하거나, 세트가 구성품 롤업 대신 자기 처방으로 판정되는 형태로 새어 나간다. 중첩 세트를 지금 잠그는 이유도 같다 — §4.2가 중첩을 언급하지 않으므로 최소로 잠근다. 여는 것은 언제든 쉽고, 데이터가 쌓인 뒤 잠그는 것은 불가능하다.

**기각한 대안** — ① 세트용 더미 제품 행: 처방이 아닌 것이 처방 테이블에 앉으면 S3-4의 판정 대상 조회가 그 더미를 집는다. ② `product_id` nullable + 서비스 코드 검증: 마이그레이션·배치·직접 SQL 경로가 검증을 우회한다(§17.5 "가능한 불변식은 CHECK").

**되돌리기 비용** — 지금은 컬럼 1개와 CHECK 2개. Phase 3 이후에는 판정·C/O·채널 리스팅이 전부 이 구분에 의존하므로, 뒤집으면 그 세 곳의 조회 조건이 함께 움직인다.

**부기 (미결 — 문자열 잔류형 부채 방지)** — **SET 행의 DG 속성**(dg_flag·UN번호·Class·PG·인화점 등, §4.1)을 세트 자체에 입력받을지 구성품 롤업으로 계산할지는 **아직 정하지 않았다**. §7.7 DG 게이트(Phase 4)가 "MSDS 유효본 미첨부 차단"의 판정 주체를 정할 때 함께 확정한다. 그때까지 **SET 행은 DG 속성을 입력받지 않는다** — `kind='SET'`이면 `dg_flag = false`, `dg_flag = false`면 나머지 DG 컬럼 전부 NULL을 CHECK로 강제한다. 입력을 열어 두면 구성품과 어긋난 값이 쌓이고, 그 값은 P4에서 신뢰할 수 없어 전건 재입력 대상이 된다.
