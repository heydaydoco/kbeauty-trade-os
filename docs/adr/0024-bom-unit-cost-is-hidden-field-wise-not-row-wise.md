# ADR-0024: BOM 단가는 행이 아니라 **필드 단위**로 감춘다 (ADR-0018의 보완)

- **상태**: 채택 (웹 세션 판정 2026-07-30 — 조건 C)
- **날짜**: 2026-07-30
- **관련**: DESIGN.md §4.4·§2(권한·통제)·§6.3·§18.1·§20 G / WBS.md S1-2 / ADR-0017·ADR-0018

**맥락** — `product_boms.unit_cost`(자재 매입단가)는 원가다(§2 "조회는 원가·마진을 API 응답 레벨에서 마스킹", §6.3 RVC 계산의 입력). ADR-0018은 `sku_prices`의 매입가를 **행 단위**로 감추기로 했는데, 그 방식을 BOM에 그대로 쓰면 소요량·원산지상태·HS6까지 사라져 인증·원산지 업무가 불가능해진다.

**결정** — BOM 단가는 **응답 스키마를 나눠** 감춘다: 원가를 볼 수 없는 역할에게는 `unit_cost`·`currency` **필드 자체가 없는** 스키마(`BomLineCostHiddenSummary`)로 나가고, 행과 건수는 그대로 보인다. ① 갈림은 응답 경계(라우터) 한 곳에서만 일어나고 직렬화 후 dict에서 키를 지우는 방식은 금지한다 ② 원가 파생 합계·롤업(라인 금액·BOM 총원가)이 생기면 **같은 부재 규율**을 따른다 — 이번 범위에는 없으며, 원가 없는 스키마에 금액·민감 이름의 필드가 생기면 실패하는 아키텍처 테스트로 그 원칙을 기계화했다 ③ 역할 목록은 ADR-0018의 것을 재사용한다(`pricing.may_see_cost` 호출 — 다시 정의하면 두 곳이 갈린다) ④ 판정은 PROGRESS의 마스킹 원장에 등재한다 ⑤ 로그 원가 0건은 e2e로 확인한다(정상·실패·PostgreSQL DETAIL 세 경로).

**ADR-0018과의 관계(모순이 아니라 보완)** — 기준은 **행의 목적**이다. `sku_prices`의 PURCHASE 행은 존재 자체가 원가 정보이고(건수 = 원가 변경 횟수) 행 전체가 민감하므로 **행 단위**로 감춘다. `product_boms` 행은 **혼합 목적**이다 — 원가 한 칸 외에는 인증·판정 업무 데이터이고, 행 수는 BOM 라인 수여서 원가 정보가 아니다. 그래서 **필드 부재**다. null로 비우는 방식은 양쪽 모두에서 기각한다("0원"·"미입력" 오독이 곧 추정 단서다).

**기각한 대안** — ① 행 단위 마스킹 이식: 조회·인증 역할이 BOM을 못 본다("BOM이 비어 있다"로 읽혀 §6.3 전수 대조가 조용히 어긋난다). ② 같은 스키마 + null: 위 오독 문제. ③ FastAPI `Union` 응답 모델로 자동 분기: **실측으로 실패했다** — 두 갈래 중 하나로 재검증하며 원가 포함 응답의 필드를 통째로 지웠다. 그래서 `response_model=None` + 명시적 스키마 선택이다.

**되돌리기 비용** — 낮다. 스키마 2개와 라우터 분기 1곳. 단 방식을 행 단위로 바꾸면 조회·인증 역할의 화면·판정 경로가 함께 움직인다.

**부기(2026-09-30 — S3-1 계획)** — (자율 확정 — 사후 번복 가능. 위 원문 결정은 고치지 않는다.) **PO 적용 — 부재 방식의 대상 판정.** 구매 발주(PO)는 상태·공급사·품목·수량·요청납기·OC 일자가 물류·조회 업무 데이터이고 원가는 `unit_cost`·`line_cost`·`total_cost`·`currency`·`price_basis` 몇 칸뿐인 **혼합 목적 행**이므로 행 단위(ADR-0018)가 아니라 이 ADR의 **필드 부재 방식**을 적용한다: 응답 스키마 2종(`PurchaseOrderDetail`/`PurchaseOrderCostHiddenDetail` 등 목록·상세·라인 각각), `response_model=None`+`may_see_cost`(`COST_VISIBLE_ROLES` 단일 출처)로 라우터 경계 1곳에서 선택하며 VIEWER는 200으로 행·건수·상태를 보고 원가 키만 없다. 정렬·CSV·에러·로그·audit·이벤트·멱등 저장·첨부·집계까지 9채널을 봉쇄하고 PO 원가 컬럼은 `_cost` 접미로 지어 로그 마스킹에 자동 편입한다(ADR-0057). 근거: design-F.md F5 / design-A.md A12.

**부기(2026-10-04 — S3-2 계획)** — (자율 확정 — 사후 번복 가능. 위 원문 결정은 고치지 않는다.) **수입선적은 10번째 원가 채널을 열지 않는다**: 수입선적은 PO 라인을 참조 생성하지만 **단가·금액을 복사하지 않는다**(선적 라인 단가 NULL·금액 0 — CHECK `import_no_price`). 그래서 위 부기의 PO 원가 9채널 봉쇄는 선적 응답·CSV(`/shipments/export.csv`)·outbox·감사·마일스톤 어디로도 확장되지 않고, 원가 열람 역할로 조회해도 수입선적 응답에 원가 키가 0이다(GC-G3 — 필드 부재로 고정, 마스킹 분기 자체가 없다). PO 상세의 `assignable_quantity`·`expected_receipt`는 수량·날짜뿐이다. 근거: ADR-0074·0077 / design-integrated.md §2.1(b)·R-12.

**부기(2026-10-04 — S3-2 PR-5a 이행: 수입선적 원가 비복사·응답 키 부재)** — 위 S3-2 계획 부기를 이행했다. ① 복사 없음: 수입선적 생성은 PO를 **테이블 이름으로 원가 아닌 열만** 골라 읽는다(PO 모델·서비스 임포트 0, `unit_cost`·`line_cost`·`total_cost`·`price_basis`를 식별자·열 이름 상수로 쓰는 문장 0 — 아키텍처 스캔·변이 kill) → 라인 단가 NULL·금액 0. ② 응답: 수입선적 상세·목록·미리보기는 통화·소수 자릿수·환율·합계·라인 단가/금액/통화/무상 키를 **아예 싣지 않는다**(구분 판별자 합집합 `ImportShipmentDetail` 등 — 서비스 dict부터 만들지 않음, null 아닌 미포함). PO 통화·환율은 PO CostHidden이 원가 비열람 역할에게 가리는 필드라 수입선적 응답은 **전 역할 같은 모양**(원가 열람 역할로도 0 — GC-G3 golden: 상세·목록·CSV·미리보기·생성·멱등 저장 본문·outbox payload 키/센티널 0). CSV는 같은 열을 빈칸으로 둔다(헤더 고정 — R-3c-2 정합). 10번째 채널은 열리지 않았다.

**부기(2026-10-05 — S3-3 계획)** — (자율 확정 — 사후 번복 가능. 위 원문 결정은 고치지 않는다.) **원가 10번째 채널을 열지 않는다(S3-3 서류·첨부)**: 렌더 컨텍스트·CI 발행 스냅샷·S/I에 원가 키 0(뷰 허용 필드 고정 — R-28), **PO 발주서 렌더 미구현**(부채 A-02)·**PO 소유 첨부 미개방**·수입선적 첨부 422·수입선적 서류 422(GC-G4). 원가 열람 역할에게도 열지 않는다(마스킹 분기가 아니라 경로 부재 — GC-G3 계보).
