# ADR-0024: BOM 단가는 행이 아니라 **필드 단위**로 감춘다 (ADR-0018의 보완)

- **상태**: 채택 (웹 세션 판정 2026-07-30 — 조건 C)
- **날짜**: 2026-07-30
- **관련**: DESIGN.md §4.4·§2(권한·통제)·§6.3·§18.1·§20 G / WBS.md S1-2 / ADR-0017·ADR-0018

**맥락** — `product_boms.unit_cost`(자재 매입단가)는 원가다(§2 "조회는 원가·마진을 API 응답 레벨에서 마스킹", §6.3 RVC 계산의 입력). ADR-0018은 `sku_prices`의 매입가를 **행 단위**로 감추기로 했는데, 그 방식을 BOM에 그대로 쓰면 소요량·원산지상태·HS6까지 사라져 인증·원산지 업무가 불가능해진다.

**결정** — BOM 단가는 **응답 스키마를 나눠** 감춘다: 원가를 볼 수 없는 역할에게는 `unit_cost`·`currency` **필드 자체가 없는** 스키마(`BomLineCostHiddenSummary`)로 나가고, 행과 건수는 그대로 보인다. ① 갈림은 응답 경계(라우터) 한 곳에서만 일어나고 직렬화 후 dict에서 키를 지우는 방식은 금지한다 ② 원가 파생 합계·롤업(라인 금액·BOM 총원가)이 생기면 **같은 부재 규율**을 따른다 — 이번 범위에는 없으며, 원가 없는 스키마에 금액·민감 이름의 필드가 생기면 실패하는 아키텍처 테스트로 그 원칙을 기계화했다 ③ 역할 목록은 ADR-0018의 것을 재사용한다(`pricing.may_see_cost` 호출 — 다시 정의하면 두 곳이 갈린다) ④ 판정은 PROGRESS의 마스킹 원장에 등재한다 ⑤ 로그 원가 0건은 e2e로 확인한다(정상·실패·PostgreSQL DETAIL 세 경로).

**ADR-0018과의 관계(모순이 아니라 보완)** — 기준은 **행의 목적**이다. `sku_prices`의 PURCHASE 행은 존재 자체가 원가 정보이고(건수 = 원가 변경 횟수) 행 전체가 민감하므로 **행 단위**로 감춘다. `product_boms` 행은 **혼합 목적**이다 — 원가 한 칸 외에는 인증·판정 업무 데이터이고, 행 수는 BOM 라인 수여서 원가 정보가 아니다. 그래서 **필드 부재**다. null로 비우는 방식은 양쪽 모두에서 기각한다("0원"·"미입력" 오독이 곧 추정 단서다).

**기각한 대안** — ① 행 단위 마스킹 이식: 조회·인증 역할이 BOM을 못 본다("BOM이 비어 있다"로 읽혀 §6.3 전수 대조가 조용히 어긋난다). ② 같은 스키마 + null: 위 오독 문제. ③ FastAPI `Union` 응답 모델로 자동 분기: **실측으로 실패했다** — 두 갈래 중 하나로 재검증하며 원가 포함 응답의 필드를 통째로 지웠다. 그래서 `response_model=None` + 명시적 스키마 선택이다.

**되돌리기 비용** — 낮다. 스키마 2개와 라우터 분기 1곳. 단 방식을 행 단위로 바꾸면 조회·인증 역할의 화면·판정 경로가 함께 움직인다.
