# ADR-0012: 담당자 라우팅 — 구조는 Phase 0, 동작은 S2-3

- **상태**: 채택
- **날짜**: 2026-07-27
- **관련**: DESIGN.md §19 Phase 0·§2 ADR-07·§5.3·§20 H / WBS.md S0-2·S2-3 / WBS v1.2 / PROGRESS 부채 #4

**맥락** — DESIGN §19는 Phase 0에 "역할 5종·담당자 라우팅"을 넣었으나 WBS v1.1의 S0-2 산출물에는 라우팅 동작이 없고, 발송 채널(`notification_channels`·`webhook_subscriptions`·알림센터)은 전부 S2-3 산출물이다. 어느 세션도 만들지 않는 항목으로 떠 있었다(PROGRESS 부채 #4).

**결정** — 담당자 라우팅을 둘로 나눠, **구조**(담당자 컬럼 — `tasks.assignee_id`, `alert_rules`의 수신 대상)는 S0-2에, **동작**(이벤트→수신자 결정→채널 발송, 전사 폭포 금지)은 S2-3에 배정한다.

**근거** — ADR-07의 "담당자 라우팅 기본(전사 폭포 금지)"은 발송 채널을 전제로 한 요구다. 채널이 없는 Phase 0에서 동작을 구현하면 §20 H의 라우팅 케이스를 검증할 수단이 없어 §22 렌즈 8을 통과하지 못하고, S2-3에서 어차피 재작성된다. 반대로 구조까지 S2-3으로 미루면 S0-2가 만드는 `tasks`·`alert_rules`에 담당자 자리가 없어 Phase 2가 그 테이블을 다시 수술하게 된다.

**기각한 대안** — ① S0-2에 동작까지: 보낼 채널이 없어 테스트 불가·재작성 확정. ② S2-3에 구조까지: Phase 2에 스키마 변경 마이그레이션이 추가되고 그사이 쌓인 `tasks` 데이터의 담당자 백필이 따라온다.

**되돌리기 비용** — 지금은 WBS 두 줄과 컬럼 2개. 뒤집으면 S2-3 알림 엔진의 설계 전제(수신자 출처)가 통째로 바뀐다.
