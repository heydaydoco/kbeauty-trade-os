# 운영(prod) 실행 절차

> S0-1 단계에서는 **파일만 준비**돼 있고 실배포(VM·도메인·TLS)는 후속이다.
> 이 문서는 규칙을 고정한다.

## 절대 규칙

- dev와 **항상 명시적으로 분리**해서 실행한다. prod은 절대 무플래그로 뜨지 않는다:
  ```
  docker compose -f docker-compose.prod.yml --env-file .env.prod up -d
  ```
- `.env.prod`는 `.env.prod.example`을 복사해 실제 값으로 채운다. **커밋 금지**(.gitignore).
  - 모든 값이 필수다. 비우면 기동이 거부된다(`${VAR:?}`).
  - `DEV_ONLY_DO_NOT_USE_IN_PROD` 마커가 든 값을 넣으면 앱이 시작을 거부한다(2중 방어).
- prod 명령에 **`-v`(볼륨 삭제)를 절대 붙이지 않는다** — 운영 데이터가 사라진다.
- 마이그레이션은 기본 up에서 제외돼 있다(profiles). 배포 절차에서 수동 실행:
  ```
  docker compose -f docker-compose.prod.yml --env-file .env.prod --profile migrate run --rm migrate
  ```

## 렌더 검증(배포 전)

```
docker compose -f docker-compose.prod.yml --env-file .env.prod config -q
```
- 출력 없이 통과하면 문법 OK. (실제 값이 든 `config` 출력을 아무 데도 붙여넣지 말 것 — 시크릿 노출.)

## 포트·노출

- db·api는 포트를 게시하지 않는다(내부망 전용).
- web(nginx)만 `127.0.0.1:8080`. 외부 공개는 앞단에 리버스 프록시 + TLS 종단을 두는 것을 전제로 한다.
- `/api/v1/system/readyz`는 nginx가 사설 대역에서만 허용(내부 상태 점검용).

## 시크릿 업그레이드 경로

현재는 600 권한 env 파일. 향후 Docker secrets / 외부 시크릿 매니저로 갈 때는
compose의 `environment:`를 `*_FILE` 규약으로 바꾼다(이 문서 갱신 + ADR).

## 백업·복원·장애 수칙 (S2-4 PR-3)

- 백업은 compose `backup` 서비스가 한다(운영 기본 포함 — `.env.prod`의 `KBOS_BACKUP_PASSPHRASE` 필수, 16자 이상). 절차·판독·복원은 [backup-restore.md](backup-restore.md).
- **`backups` 볼륨을 호스트 밖으로 복제**하는 것은 운영자 몫이다(같은 디스크의 백업은 디스크 장애에 무력).
- 패스프레이즈는 `.env.prod`와 **별도 장소**에 보관한다 — 잃으면 백업을 풀 수 없다.
- 시스템이 멈추면 [incident-sop.md](incident-sop.md)(수기 기록 → 소급 입력 → 검산 1회). 인쇄용 양식은 [forms/manual-record-form.md](forms/manual-record-form.md).
- 배치는 **worker 기동 시 자동 등록**된다(멱등 — 이미 있는 잡·관리자가 끈 상태는 건드리지 않는다). 수동 등록이 필요하면 `python -m app.cli register-jobs`.
- 문서 실물 물리 정리는 **기본 OFF**(`KBOS_FILE_PURGE_ENABLED=false`)다. 켜기 전에 `python -m app.cli purge-files`(dry-run)로 후보를 확인한다 — 되돌릴 수 없다.


## S3-1 운영 개시 (전표 사슬·승인·게이트) — 운영에서 전표를 쓰기 전에 1회

> S3-1(PR-1~PR-16) 전 기능이 들어간 뒤의 **최종본**이다(2026-10-04 PR-16 — 실 브라우저 워크스루로 화면 이름·버튼 이름을 확인했다). 이 절은 DESIGN §2·§7.3·§7.10 [M4] 보강(S3-1 계획 자율 확정 2026-09-30)의 운영 귀결이다.
> **아래를 하기 전에 막히는 것은 오류가 아니라 fail-closed 정상 동작이다** — 결재선이 없으면 여신 초과 수주가, 정책이 없으면 선수금 수주가, 계좌가 없으면 PI가 만들어지거나 확정되지 않는다.
> 화면은 브라우저로 운영 주소(앞단 프록시 뒤 `web`)에 접속해 **관리자 계정**으로 로그인한 상태를 전제로 한다. 위쪽 메뉴 줄의 이름을 그대로 적었다.

### ① 관리자 계정을 2명 이상 둔다 (제2 결재 계정)

여신 초과 수주의 승인은 **요청한 사람과 다른 사람**만 할 수 있다(관리자도 예외 없음). 관리자가 1명이면 자기 기안을 승인할 수 없어 여신 초과 수주는 영원히 확정되지 않는다 — 정상 동작이다.

1. 서버 콘솔(PowerShell 또는 SSH)에서 아래 한 줄을 붙여넣는다(이메일·표시 이름은 실제 값으로):
   ```
   docker compose -f docker-compose.prod.yml --env-file .env.prod run --rm api python -m app.cli create-admin --email <둘째관리자이메일> --display-name "<이름>"
   ```
2. `비밀번호:` 가 나오면 12자 이상 비밀번호를 입력한다(화면에 글자가 안 보이는 게 정상).
3. `관리자 계정 준비 완료: … (id=N)` 이 나오면 끝. 그 사람에게 이메일·비밀번호를 따로 전달한다.
- 무역 담당자 계정도 같은 명령으로 만든 뒤 역할을 바꿔야 한다 — **사용자 역할을 바꾸는 화면은 아직 없다**(관리자 API `POST /api/v1/users/{id}/roles`·`DELETE …/roles/ADMIN`로만 가능, 부채 S3-1 종결 ⑤). 그 전까지는 개발자에게 요청한다.

### ② 결재선을 등록한다 (통화별 임계 0)

1. 메뉴 **결재선** 클릭.
2. 아래 **결재선 등록** 칸에서:
   - **승인 유형**: `여신 초과 수주 확정` 선택
   - **통화**: 거래에 쓰는 통화 하나 선택(예: `USD`)
   - **임계 금액 (초과 시)**: `0` 입력 — 여신 한도를 1원이라도 넘으면 결재가 필요하다는 뜻
   - **결재 역할**: `관리자` 선택(①에서 만든 제2 관리자가 결재한다)
   - 메모는 비워도 된다.
3. **등록** 클릭 → 목록에 한 줄이 생긴다.
4. **거래에 쓰는 통화마다** 1~3을 반복한다(USD·EUR·KRW 등). 통화가 빠진 결재선은 그 통화 수주의 승인 요청을 막는다(fail-closed).

### ③ 정책 2가지를 저장한다

1. 메뉴 **정책 설정** 클릭(관리자에게만 보인다). 미설정 항목은 **빨간색**으로 표시된다.
2. **선수금 입금 게이트 모드** 줄의 **편집** 클릭 → **모드**에서 `차단`(권장)·`경고`·`끔` 중 하나 선택 → **변경 사유**에 2자 이상(화면 표기 "2~300자")(예: `운영 개시 — 선수금 미입금 확정 차단`) → **저장**.
   - 저장 전에는 `차단`으로 동작한다(부채 P-16 — 완화 여부는 오너 판단).
3. **단가 편차 허용치(bp)** 줄의 **편집** 클릭 → **허용치 (%)**에 숫자(예: `5`) → 사유 → **저장**.
   - 저장 전에는 0%로 동작한다(마스터 판가와 1센트만 달라도 '가격 편차 차단' — 무역 담당자가 사유를 남기고 예외 승인해야 확정된다).

### ④ 통화별 은행 계좌를 등록한다

1. 메뉴 **은행 계좌** 클릭 → **계좌 등록** 클릭.
2. **표시 이름**(예: `USD 수취 계좌`)·**통화**·**수취인**·**수취인 주소**·**은행명**·**은행 주소**·**계좌번호**·**SWIFT 코드 (8 또는 11자리)**를 채운다.
3. **등록** 클릭. 통화마다 반복한다. 계좌가 없는 통화로는 PI를 만들 수 없다(PI 만들기 창에 '입금 은행 계좌를 선택해 주세요').
- 계좌번호는 PI에만 복사되고 로그·목록 CSV에는 실리지 않는다.

### ⑤ 거래처 영문명·주소와 여신한도를 넣는다 (여신한도는 관리자만)

- **새 거래처**: 메뉴 **거래처** → 등록 칸의 **거래처명(영문, 선택)**·**영문주소 (선택)**·**여신한도 (선택)**·**여신통화** 입력 → **등록**.
- **이미 있는 거래처**: 거래처 수정 화면이 아직 없다(부채 P-44). 대신 CSV 왕복으로 고친다:
  1. 메뉴 **거래처** → **CSV 내보내기**로 파일을 받는다.
  2. 엑셀에서 `영문명`·`영문주소`·`여신한도`·`여신통화` 열만 채우고 **CSV(UTF-8)** 로 저장한다(다른 열·ID 열은 건드리지 않는다).
  3. 메뉴 **엑셀 임포트** → **대상**에서 거래처 선택 → **CSV 파일** 고르기 → 업로드 → 아래 **검토 대기·이력**에서 변경 행을 확인하고 확정.
- **한도 넣는 법(중요)**: 시스템 도입 **전에** 생긴 미수금은 여신 노출에 반영되지 않는다(화면에 '미수 미반영' 배지). 그래서 한도는 **"원래 한도 − 지금 남아 있는 미수"** 로 넣는다(부채 P-51 — S3-3 이월 채권 반입 시 재판정).
- **통화를 섞어 거래하는 거래처는 여신통화를 `KRW`** 로 둔다. 한도 통화와 수주 통화를 비교할 수 없으면 승인 경로 없이 확정이 거부된다(부채 P-48).
- 한도를 비워 두면 '여신 관리 안 함'(확정을 막지 않음), `0`이면 '신용 거래 불가'(모든 수주가 승인 대상)다.

### ⑥ SKU MOQ와 바이어 품번 매핑

- **MOQ**: 메뉴 **SKU** → 등록 칸의 **MOQ (EA, 선택)**, 이미 있는 SKU는 SKU 왕복 CSV(`MOQ` 열)로 엑셀 임포트. 비어 있으면 MOQ 게이트는 통과다.
- **바이어 품번 매핑**: 바이어 PO(CSV·수동)를 처음 받을 때 **주문 접수(인테이크)** 상세의 **품번 등록**에서 SKU를 골라 연결하고 **품번 다시 확인**을 누른다. 매핑이 없으면 접수 확정이 막힌다(정상). 등록된 매핑은 **거래처 → 상세·품번**에서 보고 지울 수 있다(정정은 삭제 후 재등록 — 부채 P-36).

### ⑦ 아직 닫혀 있는 것 (S3-1 범위 밖 — 기다리면 된다)

- **L/C 결제유형은 닫혀 있다** — 선수금 T/T·후불 T/T만 고를 수 있다(feature flag 행을 만드는 경로가 없어 fail-closed — S3-3에서 열린다, 부채 P-10).
- **자사 레터헤드가 없다** — PI·견적은 화면 데이터로만 존재하고 인쇄용 서식(회사 로고·주소 머리글)은 S3-3 서류 렌더링에서 생긴다(부채 P-11). 바이어에게 보낼 PI 문서는 그때까지 기존 방식(엑셀 서식)으로 만든다.
- **미수금(채권)·선적은 아직 없다** — 여신 노출은 미결 수주만 센다(S3-2·S3-3).

### ⑧ 배치 13개가 등록됐는지 확인한다

1. 서버 콘솔에서:
   ```
   docker compose -f docker-compose.prod.yml --env-file .env.prod run --rm api python -m app.cli register-jobs
   ```
2. `새로 등록할 배치가 없습니다(전건 등록 상태).`가 나오면 정상이다. `등록 완료 N건: …`이 나오면 빠져 있던 배치가 방금 등록된 것이라 역시 정상이다(한 번 더 실행하면 위 문구가 나온다).
- 참고: worker 로그의 `실행기 기동 — 등록 잡 13종` 줄은 worker가 **켜질 때 한 번만** 찍히므로, 시간이 지나면 `logs --tail`로는 보이지 않는다(보려면 `logs worker | Select-String "등록 잡"` — PowerShell).
- 배치 목록을 보는 **화면은 아직 없다**(관리자 API `GET /api/v1/scheduled-jobs`로만 — 부채 S3-1 종결 ⑥). 실패한 배치는 관리자 **알림**(메뉴 줄 오른쪽 '알림')으로 오며, 알림이 말하는 오류 내용은 위 API 또는 worker 로그에서 확인한다(화면이 생기기 전까지 — 개발자에게 전달).
