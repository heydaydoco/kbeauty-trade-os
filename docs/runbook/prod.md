# 운영(prod) 실행 절차

> S0-1 단계에서는 **파일만 준비**돼 있고 실배포(VM·도메인·TLS)는 후속이다.
> 이 문서는 규칙을 고정한다.

## 절대 규칙

- dev와 **항상 명시적으로 분리**해서 실행한다. prod은 절대 무플래그로 뜨지 않는다:
  ```
  docker compose -f docker-compose.prod.yml --env-file .env.prod up -d
  ```
- `.env.prod`는 `.env.prod.example`을 복사해 실제 값으로 채운다. **커밋 금지**(.gitignore).
  - 모든 값이 필수다. 비우면 기동이 거부된다(`${VAR:?}`).
  - `DEV_ONLY_DO_NOT_USE_IN_PROD` 마커가 든 값을 넣으면 앱이 시작을 거부한다(2중 방어).
- prod 명령에 **`-v`(볼륨 삭제)를 절대 붙이지 않는다** — 운영 데이터가 사라진다.
- 마이그레이션은 기본 up에서 제외돼 있다(profiles). 배포 절차에서 수동 실행:
  ```
  docker compose -f docker-compose.prod.yml --env-file .env.prod --profile migrate run --rm migrate
  ```

## 렌더 검증(배포 전)

```
docker compose -f docker-compose.prod.yml --env-file .env.prod config -q
```
- 출력 없이 통과하면 문법 OK. (실제 값이 든 `config` 출력을 아무 데도 붙여넣지 말 것 — 시크릿 노출.)

## 포트·노출

- db·api는 포트를 게시하지 않는다(내부망 전용).
- web(nginx)만 `127.0.0.1:8080`. 외부 공개는 앞단에 리버스 프록시 + TLS 종단을 두는 것을 전제로 한다.
- `/api/v1/system/readyz`는 nginx가 사설 대역에서만 허용(내부 상태 점검용).

## 시크릿 업그레이드 경로

현재는 600 권한 env 파일. 향후 Docker secrets / 외부 시크릿 매니저로 갈 때는
compose의 `environment:`를 `*_FILE` 규약으로 바꾼다(이 문서 갱신 + ADR).

## 백업·복원·장애 수칙 (S2-4 PR-3)

- 백업은 compose `backup` 서비스가 한다(운영 기본 포함 — `.env.prod`의 `KBOS_BACKUP_PASSPHRASE` 필수, 16자 이상). 절차·판독·복원은 [backup-restore.md](backup-restore.md).
- **`backups` 볼륨을 호스트 밖으로 복제**하는 것은 운영자 몫이다(같은 디스크의 백업은 디스크 장애에 무력).
- 패스프레이즈는 `.env.prod`와 **별도 장소**에 보관한다 — 잃으면 백업을 풀 수 없다.
- 시스템이 멈추면 [incident-sop.md](incident-sop.md)(수기 기록 → 소급 입력 → 검산 1회). 인쇄용 양식은 [forms/manual-record-form.md](forms/manual-record-form.md).
- 배치는 **worker 기동 시 자동 등록**된다(멱등 — 이미 있는 잡·관리자가 끈 상태는 건드리지 않는다). 수동 등록이 필요하면 `python -m app.cli register-jobs`.
- 문서 실물 물리 정리는 **기본 OFF**(`KBOS_FILE_PURGE_ENABLED=false`)다. 켜기 전에 `python -m app.cli purge-files`(dry-run)로 후보를 확인한다 — 되돌릴 수 없다.


## S3-1 운영 개시 (전표 사슬·승인·게이트) — 운영에서 전표를 쓰기 전에 1회

> S3-1(PR-1~PR-16) 전 기능이 들어간 뒤의 **최종본**이다(2026-10-04 PR-16 — 실 브라우저 워크스루로 화면 이름·버튼 이름을 확인했다). 이 절은 DESIGN §2·§7.3·§7.10 [M4] 보강(S3-1 계획 자율 확정 2026-09-30)의 운영 귀결이다.
> **아래를 하기 전에 막히는 것은 오류가 아니라 fail-closed 정상 동작이다** — 결재선이 없으면 여신 초과 수주가, 정책이 없으면 선수금 수주가, 계좌가 없으면 PI가 만들어지거나 확정되지 않는다.
> 화면은 브라우저로 운영 주소(앞단 프록시 뒤 `web`)에 접속해 **관리자 계정**으로 로그인한 상태를 전제로 한다. 위쪽 메뉴 줄의 이름을 그대로 적었다.

### ① 관리자 계정을 2명 이상 둔다 (제2 결재 계정)

여신 초과 수주의 승인은 **요청한 사람과 다른 사람**만 할 수 있다(관리자도 예외 없음). 관리자가 1명이면 자기 기안을 승인할 수 없어 여신 초과 수주는 영원히 확정되지 않는다 — 정상 동작이다.

1. 서버 콘솔(PowerShell 또는 SSH)에서 아래 한 줄을 붙여넣는다(이메일·표시 이름은 실제 값으로):
   ```
   docker compose -f docker-compose.prod.yml --env-file .env.prod run --rm api python -m app.cli create-admin --email <둘째관리자이메일> --display-name "<이름>"
   ```
2. `비밀번호:` 가 나오면 12자 이상 비밀번호를 입력한다(화면에 글자가 안 보이는 게 정상).
3. `관리자 계정 준비 완료: … (id=N)` 이 나오면 끝. 그 사람에게 이메일·비밀번호를 따로 전달한다.
- 무역·물류 담당자 계정도 같은 명령으로 만든 뒤 **화면에서 역할을 바꾼다** — 메뉴 **사용자·역할**(S3-2 PR-7, 아래 [S3-2 운영 개시](#s3-2-운영-개시-선적기일휴일-운영에서-선적을-쓰기-전에-1회) ①). 계정을 만드는 화면은 없다(관리자 CLI만 — 부채 Q-12).

### ② 결재선을 등록한다 (통화별 임계 0)

1. 메뉴 **결재선** 클릭.
2. 아래 **결재선 등록** 칸에서:
   - **승인 유형**: `여신 초과 수주 확정` 선택
   - **통화**: 거래에 쓰는 통화 하나 선택(예: `USD`)
   - **임계 금액 (초과 시)**: `0` 입력 — 여신 한도를 1원이라도 넘으면 결재가 필요하다는 뜻
   - **결재 역할**: `관리자` 선택(①에서 만든 제2 관리자가 결재한다)
   - 메모는 비워도 된다.
3. **등록** 클릭 → 목록에 한 줄이 생긴다.
4. **거래에 쓰는 통화마다** 1~3을 반복한다(USD·EUR·KRW 등). 통화가 빠진 결재선은 그 통화 수주의 승인 요청을 막는다(fail-closed).

### ③ 정책 2가지를 저장한다

1. 메뉴 **정책 설정** 클릭(관리자에게만 보인다). 미설정 항목은 **빨간색**으로 표시된다.
2. **선수금 입금 게이트 모드** 줄의 **편집** 클릭 → **모드**에서 `차단`(권장)·`경고`·`끔` 중 하나 선택 → **변경 사유**에 2자 이상(화면 표기 "2~300자")(예: `운영 개시 — 선수금 미입금 확정 차단`) → **저장**.
   - 저장 전에는 `차단`으로 동작한다(부채 P-16 — 완화 여부는 오너 판단).
3. **단가 편차 허용치(bp)** 줄의 **편집** 클릭 → **허용치 (%)**에 숫자(예: `5`) → 사유 → **저장**.
   - 저장 전에는 0%로 동작한다(마스터 판가와 1센트만 달라도 '가격 편차 차단' — 무역 담당자가 사유를 남기고 예외 승인해야 확정된다).

### ④ 통화별 은행 계좌를 등록한다

1. 메뉴 **은행 계좌** 클릭 → **계좌 등록** 클릭.
2. **표시 이름**(예: `USD 수취 계좌`)·**통화**·**수취인**·**수취인 주소**·**은행명**·**은행 주소**·**계좌번호**·**SWIFT 코드 (8 또는 11자리)**를 채운다.
3. **등록** 클릭. 통화마다 반복한다. 계좌가 없는 통화로는 PI를 만들 수 없다(PI 만들기 창에 '입금 은행 계좌를 선택해 주세요').
- 계좌번호는 PI에만 복사되고 로그·목록 CSV에는 실리지 않는다.

### ⑤ 거래처 영문명·주소와 여신한도를 넣는다 (여신한도는 관리자만)

- **새 거래처**: 메뉴 **거래처** → 등록 칸의 **거래처명(영문, 선택)**·**영문주소 (선택)**·**여신한도 (선택)**·**여신통화** 입력 → **등록**.
- **이미 있는 거래처**: 거래처 수정 화면이 아직 없다(부채 P-44). 대신 CSV 왕복으로 고친다:
  1. 메뉴 **거래처** → **CSV 내보내기**로 파일을 받는다.
  2. 엑셀에서 `영문명`·`영문주소`·`여신한도`·`여신통화` 열만 채우고 **CSV(UTF-8)** 로 저장한다(다른 열·ID 열은 건드리지 않는다).
  3. 메뉴 **엑셀 임포트** → **대상**에서 거래처 선택 → **CSV 파일** 고르기 → 업로드 → 아래 **검토 대기·이력**에서 변경 행을 확인하고 확정.
- **한도 넣는 법(중요)**: 시스템 도입 **전에** 생긴 미수금은 여신 노출에 반영되지 않는다(화면에 '미수 미반영' 배지). 그래서 한도는 **"원래 한도 − 지금 남아 있는 미수"** 로 넣는다(부채 P-51 — S3-3 이월 채권 반입 시 재판정).
- **통화를 섞어 거래하는 거래처는 여신통화를 `KRW`** 로 둔다. 한도 통화와 수주 통화를 비교할 수 없으면 승인 경로 없이 확정이 거부된다(부채 P-48).
- 한도를 비워 두면 '여신 관리 안 함'(확정을 막지 않음), `0`이면 '신용 거래 불가'(모든 수주가 승인 대상)다.

### ⑥ SKU MOQ와 바이어 품번 매핑

- **MOQ**: 메뉴 **SKU** → 등록 칸의 **MOQ (EA, 선택)**, 이미 있는 SKU는 SKU 왕복 CSV(`MOQ` 열)로 엑셀 임포트. 비어 있으면 MOQ 게이트는 통과다.
- **바이어 품번 매핑**: 바이어 PO(CSV·수동)를 처음 받을 때 **주문 접수(인테이크)** 상세의 **품번 등록**에서 SKU를 골라 연결하고 **품번 다시 확인**을 누른다. 매핑이 없으면 접수 확정이 막힌다(정상). 등록된 매핑은 **거래처 → 상세·품번**에서 보고 지울 수 있다(정정은 삭제 후 재등록 — 부채 P-36).

### ⑦ 아직 닫혀 있는 것 (S3-1 범위 밖 — 기다리면 된다)

- **L/C 결제유형은 닫혀 있다** — 선수금 T/T·후불 T/T만 고를 수 있다(feature flag 행을 만드는 경로가 없어 fail-closed — S3-3에서 열린다, 부채 P-10).
- **자사 레터헤드가 없다** — PI·견적은 화면 데이터로만 존재하고 인쇄용 서식(회사 로고·주소 머리글)은 S3-3 서류 렌더링에서 생긴다(부채 P-11). 바이어에게 보낼 PI 문서는 그때까지 기존 방식(엑셀 서식)으로 만든다.
- **미수금(채권)은 아직 없다** — 여신 노출은 미결 수주만 센다(S3-3). 선적은 S3-2에서 생겼다(아래 S3-2 운영 개시 — 선적이 있어도 여신 노출은 그대로 수주 기준이다, 부채 P-01).

### ⑧ 배치 14개가 등록됐는지 확인한다

1. 서버 콘솔에서:
   ```
   docker compose -f docker-compose.prod.yml --env-file .env.prod run --rm api python -m app.cli register-jobs
   ```
2. `새로 등록할 배치가 없습니다(전건 등록 상태).`가 나오면 정상이다. `등록 완료 N건: …`이 나오면 빠져 있던 배치가 방금 등록된 것이라 역시 정상이다(한 번 더 실행하면 위 문구가 나온다).
- 참고: worker 로그의 `실행기 기동 — 등록 잡 14종` 줄은 worker가 **켜질 때 한 번만** 찍히므로, 시간이 지나면 `logs --tail`로는 보이지 않는다(보려면 `logs worker | Select-String "등록 잡"` — PowerShell).
- 배치 목록을 보는 **화면은 아직 없다**(관리자 API `GET /api/v1/scheduled-jobs`로만 — 부채 S3-1 종결 ⑥). 실패한 배치는 관리자 **알림**(메뉴 줄 오른쪽 '알림')으로 오며, 알림이 말하는 오류 내용은 위 API 또는 worker 로그에서 확인한다(화면이 생기기 전까지 — 개발자에게 전달).

- **무역 기일 알림을 받았을 때**(`trade-deadline-scan`): 알림을 누르면 선적(또는 견적·PI) 화면으로 간다. ① 일이 끝났으면 선적 상세 마일스톤에서 **실적**(서류 제출·Cargo Closing 완료·세금 납부·출항/B/L)을 입력한다 — 실적이 들어가면 그 기일 알림은 더 오지 않는다. ② 일정이 바뀌었으면 **계획 변경(롤오버)**을 사유와 함께 입력한다 — 새 기일 기준으로 다시 D-7/3/1이 온다(옛 기일 알림은 다시 안 옴). ③ 알림의 '확인'을 누르면 같은 알림은 다시 오지 않고, 기일 3일 이내(또는 도과)인데 지금 받는 사람이 **하루(24시간) 넘게** 확인하지 않은 기일 알림이 남아 있으면 관리자에게 에스컬레이션 알림이 간다(방금 받은 알림·담당이 바뀌기 전 사람의 알림으로는 부르지 않는다). ④ **대금만기·L/C 제시기한·OEM 생산 일정은 알림이 오지 않는다**(화면 표시만 — 입금·제시 확인 기능이 S3-3이라 지금 알리면 이미 입금된 건에도 '도과'가 뜬다). ⑤ '무역 기일 판정 불가' 알림은 그 기일의 시간대를 시스템이 해석하지 못했다는 뜻이다 — 선적 상세에서 시간대를 다시 골라 계획을 다시 입력한다(그동안 D-7/3/1은 오지 않지만, 기일 시각이 지나면 '도과' 알림은 온다). 담당자가 비활성 계정이면 알림은 관리자에게 간다(본문 꼬리말). 수동으로 다시 돌리려면 서버 콘솔에서 `docker compose -f docker-compose.prod.yml --env-file .env.prod run --rm api python -m app.cli trade-deadline-scan`(이미 보낸 알림은 다시 안 감 — 기준일 지정 옵션은 없다).
- **승인 무결성 알림을 받았을 때**: 알림 제목의 승인 번호(`승인 #N`)와 문제 코드(본문 괄호 — 예: `NO_EVENTS`)를 개발자에게 전달한다. 배치는 승인 기록을 고치지 않는다(읽기 전용). 수동으로 다시 대사하려면 서버 콘솔에서 `docker compose -f docker-compose.prod.yml --env-file .env.prod run --rm api python -m app.cli approval-integrity-check`를 실행한다(`불일치 0건`이면 정상 — 이미 알린 문제는 다시 알리지 않는다).
- 잡은 worker 기동 시 자동 등록되고(멱등), 수동 등록은 `python -m app.cli register-jobs`다(위 [백업·복원·장애 수칙](#백업복원장애-수칙-s2-4-pr-3) 절 참조).
- 청소 잡 2종은 백업(03:00)·일요일 복원 리허설(04:00) 뒤에 돈다. 24시간이 지난 재시도는 멱등 키가 아니라 전표 상태 검사(이미 확정됨 → 409)가 이중 확정을 막는다(ADR-0014 부기).


## S3-2 운영 개시 (선적·기일·휴일) — 운영에서 선적을 쓰기 전에 1회

> S3-2(PR-1~PR-8) 전 기능이 들어간 뒤의 **최종본**이다(2026-10-05 PR-8 — 실 브라우저 워크스루로 화면·버튼 이름을 확인했다). 위 [S3-1 운영 개시](#s3-1-운영-개시-전표-사슬승인게이트-운영에서-전표를-쓰기-전에-1회)를 먼저 끝낸 상태를 전제로 한다.
> **아래를 하기 전에 보이는 '확인 불가'·'판정 불가'는 오류가 아니라 fail-visible 정상 동작이다** — 휴일 캘린더가 없는 국가·연도의 ETA는 평일로 간주하지 않고 '휴일 캘린더 미등록'으로 보인다.
> 화면은 운영 주소에 **관리자 계정**으로 로그인한 상태를 전제로 한다(①·②). 위쪽 메뉴 줄의 이름을 그대로 적었다.

### ① 물류(·무역) 담당 계정을 만든다 — CLI 생성 → 화면에서 역할 부여 → 관리자 회수

계정을 만드는 화면은 없다(부채 Q-12). CLI는 **관리자 계정**만 만들 수 있으므로, 만든 뒤 화면에서 업무 역할을 주고 관리자 역할을 거둔다.

1. 서버 콘솔에서 아래 한 줄을 붙여넣는다(이메일·표시 이름은 실제 값으로):
   ```
   docker compose -f docker-compose.prod.yml --env-file .env.prod run --rm api python -m app.cli create-admin --email <물류담당이메일> --display-name "<이름>"
   ```
2. `비밀번호:`가 나오면 12자 이상 입력(글자가 안 보이는 게 정상) → `관리자 계정 준비 완료: … (id=N)`이 나오면 끝.
3. 브라우저에서 메뉴 **사용자·역할** 클릭(관리자에게만 보인다).
4. 방금 만든 이메일 줄의 **역할 선택**에서 `물류`(무역 담당이면 `무역`) 선택 → 바로 옆 **부여** 클릭 → 확인 창의 **부여** 클릭.
5. 같은 줄 역할 칸의 `관리자` 옆 **회수** 클릭 → 확인 창의 **회수** 클릭. 역할 칸에 `물류`(또는 `무역`)만 남으면 끝.
6. 그 사람에게 이메일·비밀번호를 따로 전달한다. 물류 계정으로 로그인하면 메뉴에 **사용자·역할**이 없고, 수주 상세에 **선적 만들기**가 없다(정상 — 선적 생성·라인·취소는 무역·관리자, 일정·실적·통관·출고지시는 물류도 할 수 있다 — ADR-0079).
- **주의**: 지금 화면은 **자기 자신의 관리자 역할 회수도 막지 않는다**(다른 활성 관리자가 있으면 통과 — 부채 R-7-1). 마지막 활성 관리자만은 서버가 막는다('마지막 관리자' 오류). 자기 줄의 회수 버튼은 누르지 않는다.

### ② 휴일 캘린더를 국가·연도별로 선언한다 (도착국 × 거래 연도)

ETA(도착 예정일)가 도착국 공휴일이면 선적 상세에 **도착국 휴일** 경고가 뜬다 — 날짜를 자동으로 옮기지는 않는다(경고만, ADR-0082). 선언하지 않은 국가·연도는 **'휴일 캘린더 미등록 — 확인 불가'**로 보인다(평일로 간주하지 않는다).

1. 메뉴 **휴일 캘린더** 클릭 → **국가 코드**에 영문 대문자 2자(예: `US`, `CN`, `JP`) → **연도**(예: `2026`) → **조회**.
2. '휴일 캘린더 미등록'이 보이면 **휴일 캘린더 등록** 클릭(이미 있으면 **편집·CSV 불러오기**).
3. 창에서 **근거 링크**(그 나라 정부·공신력 있는 공휴일 공지 주소)와 **확인일**(그 링크를 확인한 날 — 오늘 이전)을 채운다. 둘 다 필수다.
4. 휴일 입력은 둘 중 하나: **휴일 추가**로 한 줄씩(날짜·이름), 또는 엑셀에서 머리글 `holiday_on,name`·날짜 `2026-10-01` 형식으로 만들어 **'CSV UTF-8'** 로 저장한 파일을 **휴일 CSV 파일**로 고른다(미리보기에서 문제 행을 보여 준다 — 일반 'CSV(쉼표로 분리)' 저장본은 거부된다, 부채 R-2a-2).
5. **저장** → '`US 2026` 휴일 캘린더를 저장했습니다(n건)'. 저장은 그 국가·연도 목록 **전체 교체**다(목록에 없는 기존 휴일은 지워진다).
6. **휴일이 하나도 없는 해**라면 목록을 비운 채 저장한다('휴일 없음 확인'으로 기록 — 미등록과 다르다).
- 대상 = **거래하는 도착국 × ETA가 걸칠 연도**(연말에는 다음 해도). 출발국(한국) 휴일·주말은 판정하지 않는다(부채 Q-19·Q-07).

### ③ 선적을 쓰는 하루 흐름 (무역·물류)

1. **선적 만들기(무역)**: 메뉴 **수주** → 확정된 수주 상세 → **선적 만들기** → 라인별 **이번 선적 수량**·**출발국 (필수)**·**도착국 (필수)**(·포워더 등 당사자) → **다음: 미리보기**(저장 안 됨) → **생성 확정**. 한 수주를 여러 선적으로 나눌 수 있고(부분선적), 첫 선적이 생기면 수주가 **선적중**으로 바뀐다. 남은 수량보다 많이 담으면 서버가 칸별로 막는다.
2. **수입선적(무역)**: 메뉴 **발주** → 발주 상세 → **수입선적 만들기** → 같은 2단. 수입선적은 **금액을 복사하지 않는다**(원가 비노출)이고 발주 잔량은 줄지 않는다(배정 가능량만 준다 — 입고는 Phase 4).
3. **담당 이관(무역·관리자)**: 선적 상세 **메모·담당·국가**의 **담당자**를 물류 담당으로 바꾸고 **저장** — 이후 기일 알림이 그 사람에게 간다.
4. **일정(물류)**: 선적 상세 **마일스톤**에서 **계획 초안 만들기**(빈 행) → 카드마다 **계획 입력**. 서류마감·Cargo Closing은 **시각+시간대**(출발국 기본 시간대가 채워진다), 나머지는 날짜다. 적재기한·대금만기·L/C 제시기한은 **자동 계산 — 직접 수정 불가**.
5. **일정이 바뀌면(물류)**: 그 카드의 **계획 변경** → 새 날짜·**변경 사유 (필수)** → 상대에게 알렸으면 **통보도 지금 기록**(상대 유형·거래처·요지) → **변경 + 통보 기록 저장**. 통보는 '알렸다는 기록'이고 시스템이 메일을 보내지 않는다.
6. **통관(물류)**: **통관 기록 추가** → **신고번호 (필수)**·**신고일 (필수)**·**수리일**(미수리면 비움) → **추가**. 수리일이 적재기한(수리일+30)을 만든다. 신고수리는 통관 기록에서만 입력된다(카드에 직접 입력 없음). 수리 안 된 기록이 남아 있으면 '일부 미수리 n건'.
7. **출고지시 → 실적(물류)**: **출고지시** → **출고지시 확정** 뒤에 ETD·B/L·ETA **실적 입력**이 열린다(미래 날짜는 거부 — 현지 시차 때문에 날짜는 하루 여유). 실적이 들어가면 대금만기 등이 실적 기준으로 다시 계산된다.
8. **취소(무역)**: 선적 상세 **취소** → **취소 사유 (필수)** → **취소 확정**. 실적이나 통관 기록이 살아 있으면 막힌다 — 실적은 사유와 함께 지우고(정정), 통관 기록은 사유와 함께 삭제한 뒤 취소한다. 마지막 선적이 취소되면 수주는 **확정**으로 돌아간다.

### ④ 기일 알림·DG 경고·통관 이슈 — 지금은 사람이 챙기는 것

- **기일 알림**: 매일 06:40 `trade-deadline-scan`이 서류마감·Cargo Closing·수입 세금 납부기한·적재기한·견적/PI 유효기간을 D-7/3/1·도과로 알린다(대응 방법은 위 잡 표 아래 '무역 기일 알림을 받았을 때'). 알림센터의 **대상**(예: `선적 #1`)을 누르면 그 선적 화면으로 간다. **대금만기·L/C 제시기한·OEM 생산 일정은 알림이 없다**(화면 표시만 — 부채 R-6-2·Q-09).
- **DG(위험물) 선적 경고**: 선적 상세 **선적 정보**의 **위험물(DG)** 칸에 '위험물 라인 n개'가 보이면, **시스템은 선적을 막지 않는다**(차단은 S4-4). 담당자가 선적 전에 직접 확인한다 — ① MSDS 유효본(문서보관소) ② UN 번호·포장 등급이 포워더 부킹·S/I에 반영됐는지 ③ 선사 DG 접수 확인. 확인 결과는 선적 **내부 메모**에 `DG 확인 <날짜> <확인자>`로 남긴다(정식 체크리스트는 S3-4 — 부채 Q-17).
- **통관 이슈 임시 규칙**(DESIGN §19 P3 '통관 이슈=태스크+메모' — 코드 없음, 부채 Q-18): 세관 보류·검사·보완 요청이 생기면 ① 그 통관 기록의 **정정**에서 **메모 (선택)**에 `이슈: <내용> / 다음: <할 일> / 기한: <날짜>`를 적고 ② 선적 **내부 메모**에도 한 줄 요약을 남기며 ③ 기한이 있는 일은 선적의 해당 마일스톤 계획(예: 서류마감) 변경으로 기일 알림에 태운다. ④ 2영업일 넘게 풀리지 않으면 관리자에게 알린다(정식 이슈 관리는 S5-3).
- **수기 기록**: 시스템이 멈춘 동안의 선적·실적·통관은 [수기 양식](forms/manual-record-form.md) **4-2**에 적고, 복구 후 실제 발생일 그대로 입력한다([incident-sop.md](incident-sop.md)).

### ⑤ 아직 닫혀 있는 것 (S3-2 범위 밖)

- 선적의 피킹·검수·출고·선적 완료·종결 상태(S4-2), 출고 재고 원장(S4-2), 수입 입고·발주 잔량 차감(S4-1), CI·PL·S/I 서류(S3-3), 선적 캘린더 화면(S4-4), 채널입고·샘플무상 선적 생성(부채 Q-03), 여러 수주 합적(부채 Q-01).
- L/C 결제유형은 여전히 닫혀 있다 — L/C 선적의 대금만기·제시기한은 '판정 불가(L/C 조건 미등록)'로 보인다(S3-3).
