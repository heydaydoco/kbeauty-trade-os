# 장애 운영 수칙 (SOP) — 시스템이 멈췄을 때

> 근거: DESIGN §21 "다운 중 실물 발생분은 수기 표준 양식 기록 → 복구 후 소급 입력(증빙일=실제 발생일·입력일=복구일 — 날짜 3종이 수용) + 검산 1회 의무".
> 이 문서는 **지금 존재하는 기능만** 다룬다(Phase 2 종결 시점). 전표·재고 계열(Phase 3 이후)은 도래 시 갱신한다 — 미리 발명하지 않는다.
> 백업·복원 절차는 [backup-restore.md](backup-restore.md), 수기 양식은 [forms/manual-record-form.md](forms/manual-record-form.md).

## 0. 한 장 요약 (시스템이 안 열릴 때)

1. **당황하지 않는다.** 데이터는 서버에 있다 — 화면이 안 열리는 것과 데이터가 사라진 것은 다르다.
2. 서류·연락이 **실물로 오가면 그 자리에서 수기 양식**에 적는다(아래 §2). 나중에 시스템에 옮길 것이므로 **실제로 일어난 날짜**를 꼭 적는다.
3. 원인 확인은 담당(IT)이 한다: `/api/v1/system/healthz`(살아 있나)·`/api/v1/system/readyz`(DB·마이그레이션) → 안 되면 [prod.md](prod.md)의 점검 순서.
4. 복구되면 **소급 입력 → 검산 1회**(§3~§4)를 끝내야 장애가 종료된다.

## 1. 역할

| 역할 | 하는 일 |
|---|---|
| 현장 담당(인증·무역) | 다운 중 발생분을 수기 양식에 기록, 복구 후 소급 입력 |
| 관리자 | 장애 선언·종료 선언, 검산 결과 확인, 백업 복원 여부 판단 |
| IT 담당 | 원인 조사·복구, 필요 시 백업 복원(리허설을 통과한 세트만) |

## 2. 다운 중에 하는 일 — 수기 기록

- 양식: [forms/manual-record-form.md](forms/manual-record-form.md)를 인쇄해 쓴다. **한 건에 한 장**(또는 한 줄).
- 반드시 적는 것: **실제 발생일**(서류를 받은 날·보낸 날·통화한 날), 종류, 상대방, 요지, 첨부(있으면 파일명·보관 위치), 적은 사람.
- 파일(스캔본 등)은 **날짜별 폴더**에 모아 둔다(예: `장애-2026-10-05/`). 시스템이 복구되면 그대로 업로드한다.
- 시스템에서 **새로 결정해야 하는 일**(인증 신청 제출 등 되돌릴 수 없는 외부 행위)은 복구를 기다릴 수 있으면 기다린다. 못 기다리면 수기 양식에 "결정자·사유"를 적고 진행한다.

## 3. 복구 후 — 소급 입력

원칙: **증빙일 = 실제 발생일, 입력일 = 복구일(시스템이 자동 기록)**. 시스템은 이 두 날짜를 구분해 받는다(과거 날짜 입력 허용).
입력은 양식의 "시스템 입력 대응" 표([forms/manual-record-form.md](forms/manual-record-form.md#시스템-입력-대응표))를 따른다.

| 무엇을 | 어디에(화면) | 실제 발생일을 넣는 필드 | 시스템이 자동 기록하는 입력일 |
|---|---|---|---|
| 서류 파일·링크 | 문서보관소 | **발급일** (유효기간·보존기한은 서류에 적힌 대로) | 등록 시각 |
| 인증 진행(신청·승인) | 인증 → 상태 전이 | **신청일·승인일·시작일·만료일** (전이 폼) | 상태 이력의 기록 시각 |
| 대행사·기관과 주고받은 연락 | 인증 상세 → 통신 기록 | **오간 날** | 기록 등록 시각 |
| 다음 액션(회신 기한 등) | 통신 기록의 다음 액션 | **기한** | — |

- 미래 날짜는 입력되지 않는다. 오늘 이전이면 몇 달 전이어도 된다.
- 소급 입력한 건이 **정체 알림**을 되돌리지 않는지 확인한다: 정체 시계는 "오간 날"(실제 날짜) 기준이라, 예전 날짜로 입력한 기록은 이미 지난 정체를 되돌리지 않는다(의도된 동작).

## 4. 검산 1회 (의무)

복구 뒤 **한 번, 관리자가 확인**한다. 하나라도 어긋나면 장애 종료를 선언하지 않는다.

1. **건수 대조**: 수기 양식 장수 = 시스템에 소급 입력한 건수(양식 하단 "입력 완료" 칸에 체크).
2. **날짜 대조**: 무작위 3건을 골라 양식의 실제 발생일과 시스템의 발급일/오간 날/전이 일자가 같은지 본다.
3. **첨부 대조**: 양식에 적은 파일명이 문서보관소에 모두 있는지 본다.
4. **알림 확인**: 알림센터에서 장애 기간에 밀린 기일 알림(만료 임박·정체 독촉)이 정상 발생했는지 본다. 배치는 다운 중 놓친 일정을 **재기동 시 1회** 실행한다(미스파이어 수렴).
5. **백업 확인**: 복구 직후 `GET /api/v1/system/backups`(관리자)에서 마지막 백업·복원 리허설이 정상인지 본다([backup-restore.md](backup-restore.md)).

## 5. 데이터가 손상·유실됐다면

- 임의로 고치지 않는다. [backup-restore.md](backup-restore.md)의 **복원 절차**로 간다. 복원은 마지막 백업 시점으로 되돌리는 것이라, 그 뒤 발생분은 §2~§4로 다시 입력한다.
- 문서 파일 유실은 저장소 점검 알림("문서 실물 유실")이 알린다. 자동으로 고치지 않는다 — 백업에서 파일만 꺼내 같은 이름으로 되돌린다.

## 6. 장애 종료 기록

관리자가 아래를 한 줄로 남긴다(PROGRESS 세션 기록 또는 사내 기록): **발생 시각·복구 시각·원인·수기 기록 건수·소급 입력 건수·검산 결과**.
